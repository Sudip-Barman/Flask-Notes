Jinja2 **includes** allow you to take a piece of HTML from one template file and **insert it into another template**.

This is useful for reusable components such as:

- Navbar
- Footer
- Sidebar
- Alert messages
- Cards
- Forms
- Pagination
- Repeated UI sections

The main syntax is:

```
{% include "filename.html" %}
```

---

# 1. Why Do We Need `include`?

Suppose your project has:

```
templates/
├── home.html
├── about.html
├── login.html
└── contact.html
```

And every page has the same navbar:
```
<nav>
    <a href="/">Home</a>
    <a href="/about">About</a>
    <a href="/login">Login</a>
</nav>
```

You could copy this navbar into every file.

But that's a bad idea.

If you later add:

```
<a href="/contact">Contact</a>
```

you would need to update every page.

Instead, create:

```
templates/
├── home.html
├── about.html
├── login.html
├── contact.htm
└── navbar.html
```

Put the navbar in:

```
navbar.html
```

Then include it wherever needed.

---

# 2. Basic Example

### `navbar.html`

```
<nav>
    <a href="/">Home</a>
    <a href="/about">About</a>
    <a href="/login">Login</a>
</nav>
```

### `home.html`

```
<!DOCTYPE html>
<html>
<body>
    {% include "navbar.html" %}
    <h1>Home Page</h1>
</body>
</html>
```

Jinja2 inserts the contents of `navbar.html` at:

```
{% include "navbar.html" %}
```

---

# 3. What Actually Happens?

Think of:

```
{% include "navbar.html" %}
```

as:

```
"Take the contents of navbar.html
and put them right here."
```

Before rendering:

```
home.html


<html>
    {% include "navbar.html" %}
    <h1>Home</h1>
</html>
```

`navbar.html`:

```
<nav>
    Home
    About
    Login
</nav>
```

After Jinja2 processes it:

```
<html>
    <nav>
        Home
        About
        Login
    </nav>
    <h1>Home</h1>
</html>
```

The browser receives the final HTML, not the Jinja2 `include` statement.

---

# 4. Include in `base.html`

Includes become especially useful with template inheritance.

You might have:

```
templates/
│
├── base.html
│
├── home.html
├── about.html
│
└── components/
    ├── navbar.html
    └── footer.html
```

### `base.html`

```
<!DOCTYPE html>
<html>
<head>
    <title>
        {% block title %}
            My Website
        {% endblock %}
    </title>
</head>
<body>
    {% include "components/navbar.html" %}
    <main>
        {% block content %}
        {% endblock %}
    </main>
    {% include "components/footer.html" %}
</body>
</html>
```

Now every page automatically gets the navbar and footer.

---

# 5. Include + Inheritance Together

This is a very common Flask structure.

```
templates/
│
├── base.html
│
├── home.html
├── about.html
│
└── components/
    ├── navbar.html
    ├── sidebar.html
    └── footer.html
```

### `base.html`

```
<!DOCTYPE html>
<html>
<body>
    {% include "components/navbar.html" %}
    {% include "components/sidebar.html" %}
    <main>
        {% block content %}
        {% endblock %}
    </main>
    {% include "components/footer.html" %}
</body>
</html>
```

### `home.html`

```
{% extends "base.html" %}
{% block content %}
    <h1>Home Page</h1>
{% endblock %}
```

The resulting structure is roughly:

```
base.html
│
├── navbar.html
├── sidebar.html
│
├── home.html
│
└── footer.html
```

This gives you a clean separation between **layout**, **components**, and **page content**.

# 6. Passing Data to an Included Template

An included template can access variables available in the current template.

Suppose Flask sends:

```
@app.route("/")
def home():

    username = "John"

    return render_template(
        "home.html",
        username=username
    )
```

`home.html`:

```
{% include "navbar.html" %}
```

`navbar.html`:

```
<nav>
    <p>Welcome, {{ username }}</p>
</nav>
```

The included template can access:

```
{{ username }}
```

because the include normally uses the current template context.

---

# 7. Passing Specific Data with `with`

You can explicitly pass values to an included template.

Example:

```
{% include "user_card.html" with context %}
```

However, because `with context` is the normal behavior, you usually don't need to write it.

More useful is controlling the context:

```
{% include "user_card.html" without context %}
```

This tells Jinja2 not to pass the current template context into the included template.

---

# 8. `without context`

Suppose:

```
{% include "navbar.html" without context %}
```

The included template won't have access to variables from the current context.

For example, if `home.html` has:

```
{% set username = "John" %}
```

then `navbar.html` won't receive that variable through the normal template context.

This is useful when you want an included component to be more isolated.

---

# 9. `with context`

You can explicitly write:

```
{% include "navbar.html" with context %}
```

This means:

> Include this template and give it access to the current template context.

For example:

```
{% include "navbar.html" with context %}
```

The navbar can access variables such as:

```
{{ username }}
{{ logged_in }}
{{ role }}
```

if those variables exist in the current context.

Again, this is normally the default behavior.

---

# 10. Include an Optional Template

Sometimes a template may or may not exist.

You can use:

```
{% include "announcement.html" ignore missing %}
```

If `announcement.html` exists:

```
Include it.
```

If it doesn't:

```
Continue rendering.
```

Without `ignore missing`, Jinja2 will normally raise an error when the requested template cannot be found.

---

# 11. `ignore missing` with Multiple Templates

You can provide alternatives:

```
{% include [
    "custom/navbar.html",
    "default/navbar.html"
] ignore missing %}
```

Jinja2 tries the templates in order.

Conceptually:

```
Try custom/navbar.html
        ↓
    exists?
     /    \
   yes     no
   ↓        ↓
include   Try default/navbar.html
```

This is more advanced and isn't something you'll use every day, but it's useful to know it exists.

---

# 12. Include Inside a Loop

You can include a template repeatedly.

Suppose:

```
products = [
    {"name": "Laptop", "price": 50000},
    {"name": "Phone", "price": 30000},
    {"name": "Tablet", "price": 20000}
]
```

You can create:

```
templates/
├── products.html
└── product_card.html
```

### `product_card.html`

```
<div class="product-card">
    <h2>{{ product.name }}</h2>
    <p>₹{{ product.price }}</p>
</div>
```

### `products.html`

```
{% for product in products %}
    {% include "product_card.html" %}
{% endfor %}
```

Because `product` exists inside the loop, the included template can use it.

The result is:

```
Laptop
₹50000

Phone
₹30000

Tablet
₹20000
```

This pattern is extremely useful for repeated UI components.

---

# 13. Include + Loop Mental Model

Think of:

```
{% for product in products %}
    {% include "product_card.html" %}
{% endfor %}
```

as:

```
Product 1
   ↓
product_card.html


Product 2
   ↓
product_card.html


Product 3
   ↓
product_card.html
```

One template defines the card.

The loop generates as many cards as necessary.

---

# 14. Include vs Template Inheritance

This distinction is **very important**.

### Template inheritance

Uses:

```
{% extends "base.html" %}
```

Its purpose:

> Build a page using a common layout.

Example:

```
base.html
    │
    ├── home.html
    ├── about.html
    └── login.html
```

---

### Include

Uses:

```
{% include "navbar.html" %}
```

Its purpose:

> Insert a reusable template component.

Example:

```
navbar.html
     │
     ├── home.html
     ├── about.html
     └── login.html
```

---

# 15. The Difference Visually

### Inheritance

```
             base.html
                 │
       ┌─────────┼─────────┐
       ▼         ▼         ▼
     home      about      login
```

The child templates **inherit the structure**.

---

### Include

```
             navbar.html
                 │
       ┌─────────┼─────────┐
       ▼         ▼         ▼
     home      about      login
```

The navbar is simply **inserted into** those templates.

---

# 16. They Can Be Used Together

Real applications commonly use both.

```
                    base.html
                       │
              ┌────────┴────────┐
              │                 │
          navbar.html       footer.html
              │                 │
              └────────┬────────┘
                       │
                 child template
                       │
              ┌────────┼────────┐
              ▼        ▼        ▼
            home     about     login
```

For example:

### `base.html`

```
{% include "components/navbar.html" %}

{% block content %}

{% endblock %}

{% include "components/footer.html" %}
```

### `home.html`

```
{% extends "base.html" %}

{% block content %}

    <h1>Home</h1>

{% endblock %}
```

This gives you both:

- **Inheritance** for page layout
- **Includes** for reusable components

# 17. Good Folder Structure

As your application grows, you can organize reusable components:

```
templates/
│
├── base.html
│
├── home.html
├── about.html
├── login.html
│
└── components/
    │
    ├── navbar.html
    ├── footer.html
    ├── sidebar.html
    ├── alert.html
    ├── card.html
    └── pagination.html
```

The child templates remain relatively small.

---

# 18. Nested Includes

An included template can itself include another template.

For example:

```
base.html
   ↓
navbar.html
   ↓
user_menu.html
```

### `base.html`

```
{% include "navbar.html" %}
```

### `navbar.html`

```
<nav>
    {% include "user_menu.html" %}
</nav>
```

This works.

But don't create a huge maze of nested includes. If you have to jump through six files just to understand one small section, the template architecture has probably eaten too much broccoli. 🥦

---

# 19. Include Does Not Mean Copying the File Physically

The original files are not merged together on your disk.

You still have:

```
navbar.html
home.html
```

separately.

Jinja2 combines them **during template rendering**.

So:

```
Files on disk
     ↓
Jinja2 processing
     ↓
Final HTML
     ↓
Browser
```

# 20. Include Is Mainly for Reusability

Good candidates for includes:

```
navbar
footer
sidebar
alert
card
pagination
search form
login form
table row
```

For example:

```
{% include "components/alert.html" %}
```

or:

```
{% include "components/sidebar.html" %}
```

---

# 21. When Should You Use Inheritance?

Use **inheritance** when the relationship is:

> "This page follows this overall layout."

Example:

```
{% extends "base.html" %}
```

---

# 22. When Should You Use Include?

Use **include** when the relationship is:

> "I want to insert this reusable piece of HTML here."

Example:

```
{% include "components/navbar.html" %}
```

---

# 23. Simple Comparison

|Feature|Template Inheritance|Include|
|---|---|---|
|Syntax|`{% extends %}`|`{% include %}`|
|Main purpose|Page layout|Reusable component|
|Parent/child relationship|Yes|No|
|Uses blocks|Yes|Not required|
|Good for navbar|Possible, but usually include|✅ Excellent|
|Good for footer|Possible|✅ Excellent|
|Good for page layout|✅ Excellent|❌ Not the main purpose|
|Can be used inside loop|Not normally for this purpose|✅ Yes|
|Can work with variables|✅|✅|

# 24. Complete Example

### Project

```
myproject/
│
├── app.py
│
└── templates/
    │
    ├── base.html
    ├── home.html
    │
    └── components/
        ├── navbar.html
        └── footer.html
```

### `components/navbar.html`

```
<nav>
    <a href="/">Home</a>
    <a href="/about">About</a>
    <a href="/login">Login</a>
</nav>
```

### `components/footer.html`

```
<footer>
    <p>Copyright 2026</p>
</footer>
```

### `base.html`

```
<!DOCTYPE html>
<html>
<head>
    <title>
        {% block title %}
            My Website
        {% endblock %}
    </title>
</head>
<body>
    {% include "components/navbar.html" %}
    <main>
        {% block content %}
        {% endblock %}
    </main>
    {% include "components/footer.html" %}
</body>
</html>
```

### `home.html`

```
{% extends "base.html" %}

{% block title %}
    Home
{% endblock %}

{% block content %}
    <h1>Home Page</h1>
    <p>Welcome to the website.</p>
{% endblock %}
```

Now the architecture is:

```
                    base.html
                  /           \
                 /             \
        navbar.html          footer.html
                 \             /
                  \           /
                   home.html
                       │
                       ▼
                  Final HTML
```

# 25. The Most Important Syntax

### Basic include

```
{% include "navbar.html" %}
```

### Include with current context

```
{% include "navbar.html" with context %}
```

### Include without current context

```
{% include "navbar.html" without context %}
```

### Ignore missing template

```
{% include "alert.html" ignore missing %}
```

### Include inside a loop

```
{% for item in items %}
    {% include "card.html" %}
{% endfor %}
```

---

# Mental Model

Keep these two ideas separate:

```
EXTENDS
   ↓
"I want to use this page layout."


INCLUDE
   ↓
"I want to insert this reusable component."
```

Or even shorter:

```
extends  →  Layout
include  →  Component
```

That's the key distinction.

---

## One-Line Definition

> **Jinja2 `{% include %}` inserts a reusable template file into the current template, allowing common UI components to be defined once and reused across multiple pages.**
