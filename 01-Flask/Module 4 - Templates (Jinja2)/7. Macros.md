Jinja2 **macros** allow you to create **reusable template functions**.

They are especially useful when you repeatedly generate the same HTML structure with different data.

The basic idea is:

```
Macro
  ↓
Reusable HTML template function
  ↓
Call it with different values
  ↓
Generate different HTML
```

---

# 1. Why Do We Need Macros?

Suppose you have many buttons:

```
<button class="primary">Save</button>

<button class="primary">Login</button>

<button class="primary">Register</button>
```

You could write each button manually.

But imagine the HTML is more complicated:

```
<button class="btn primary" type="submit">
    Save
</button>
```

Then another:

```
<button class="btn primary" type="submit">
    Login
</button>
```

And dozens more.

Instead, create a macro:

```
{% macro button(text) %}

    <button class="btn primary">
        {{ text }}
    </button>

{% endmacro %}
```

Then:

```
{{ button("Save") }}
{{ button("Login") }}
{{ button("Register") }}
```

The macro generates the HTML for you.

---

# 2. Macro Syntax

The basic syntax is:

```
{% macro name(parameters) %}

    HTML

{% endmacro %}
```

For example:

```
{% macro hello(name) %}

    <h1>Hello {{ name }}</h1>

{% endmacro %}
```

Then call it:

```
{{ hello("John") }}
```

Output:

```
<h1>Hello John</h1>
```

---

# 3. Macro vs Normal Jinja2 Variable

You already learned:

```
{{ username }}
```

This displays a value.

A macro:

```
{{ hello("John") }}
```

**calls a reusable template function**.

So:

```
{{ variable }}
        ↓
    Display data


{{ macro(...) }}
        ↓
    Generate HTML
```

---

# 4. Creating Your First Macro

Create a file:

```
templates/
├── home.html
└── macros.html
```

### `macros.html`

```
{% macro greeting(name) %}

    <h1>Hello {{ name }}</h1>

{% endmacro %}
```

Now we have a macro named:

```
greeting
```

which accepts:

```
name
```

---

# 5. Importing a Macro

Macros in another template file need to be imported.

In `home.html`:

```
{% from "macros.html" import greeting %}
```

Then:

```
{{ greeting("John") }}
```

Output:

```
<h1>Hello John</h1>
```

---

# 6. Understanding `from ... import`

This syntax:

```
{% from "macros.html" import greeting %}
```

means:

```
Open macros.html
       ↓
Find the macro called greeting
       ↓
Make it available here
```

It's conceptually similar to Python:

```
from module import function
```

For example:

```
from math import sqrt
```

is conceptually similar to:

```
{% from "macros.html" import greeting %}
```

---

# 7. Multiple Macros

A single file can contain many macros.

### `macros.html`

```
{% macro greeting(name) %}

    <h1>Hello {{ name }}</h1>

{% endmacro %}


{% macro goodbye(name) %}

    <p>Goodbye {{ name }}</p>

{% endmacro %}
```

Import both:

```
{% from "macros.html" import greeting, goodbye %}
```

Use them:

```
{{ greeting("John") }}

{{ goodbye("John") }}
```

---

# 8. Importing All Macros

You can import the entire macro file:

```
{% import "macros.html" as macros %}
```

Then access macros using:

```
{{ macros.greeting("John") }}
```

and:

```
{{ macros.goodbye("John") }}
```

This is useful when a macro file contains many related macros.

---

# 9. `from` vs `import`

### `from`

```
{% from "macros.html" import button %}
```

Call directly:

```
{{ button("Save") }}
```

### `import`

```
{% import "macros.html" as macros %}
```

Call through the namespace:

```
{{ macros.button("Save") }}
```

Think:

```
from
 ↓
Direct access

import as
 ↓
Namespace access
```

---

# 10. Macro With Multiple Parameters

Macros can accept multiple parameters.

```
{% macro user_card(name, age) %}

    <div class="card">

        <h2>{{ name }}</h2>

        <p>Age: {{ age }}</p>

    </div>

{% endmacro %}
```

Call:

```
{{ user_card("John", 25) }}
```

Output:

```
<div class="card">

    <h2>John</h2>

    <p>Age: 25</p>

</div>
```

---

# 11. Macro With More Complex Data

You can pass dictionaries or objects.

Suppose Flask sends:

```
user = {
    "name": "John",
    "age": 25,
    "email": "john@example.com"
}
```

Macro:

```
{% macro user_card(user) %}

    <div class="card">

        <h2>{{ user.name }}</h2>

        <p>Age: {{ user.age }}</p>

        <p>Email: {{ user.email }}</p>

    </div>

{% endmacro %}
```

Call:

```
{{ user_card(user) }}
```

The entire object is passed as one argument.

---

# 12. Default Parameters

Macros can have default values.

```
{% macro button(text, type="button") %}

    <button type="{{ type }}">
        {{ text }}
    </button>

{% endmacro %}
```

Now:

```
{{ button("Click") }}
```

uses:

```
type = "button"
```

Output:

```
<button type="button">
    Click
</button>
```

But you can override it:

```
{{ button("Save", "submit") }}
```

Output:

```
<button type="submit">
    Save
</button>
```

---

# 13. Macro for Buttons

A practical example:

### `macros.html`

```
{% macro button(text, type="button", class="btn") %}

    <button
        type="{{ type }}"
        class="{{ class }}"
    >
        {{ text }}
    </button>

{% endmacro %}
```

Import:

```
{% from "macros.html" import button %}
```

Use:

```
{{ button("Click Me") }}
```

or:

```
{{ button("Save", "submit", "btn-primary") }}
```

or:

```
{{ button("Delete", "button", "btn-danger") }}
```

One macro can generate many variations.

---

# 14. Keyword Arguments

Instead of relying on parameter order, you can use named arguments.

```
{{ button(
    text="Save",
    type="submit",
    class="btn-primary"
) }}
```

This is often easier to read when there are many parameters.

---

# 15. Macro for Form Input

Macros are extremely useful for forms.

Without a macro:

```
<label>Username</label>

<input
    type="text"
    name="username"
>

<label>Email</label>

<input
    type="email"
    name="email"
>

<label>Password</label>

<input
    type="password"
    name="password"
>
```

A lot of repeated structure.

With a macro:

```
{% macro input(name, type="text", label="") %}

    <label for="{{ name }}">
        {{ label }}
    </label>

    <input
        type="{{ type }}"
        name="{{ name }}"
        id="{{ name }}"
    >

{% endmacro %}
```

Then:

```
{{ input(
    "username",
    "text",
    "Username"
) }}

{{ input(
    "email",
    "email",
    "Email"
) }}

{{ input(
    "password",
    "password",
    "Password"
) }}
```

Much cleaner.

---

# 16. Macro With `class`

You can create reusable UI components.

```
{% macro alert(message, class="info") %}

    <div class="alert {{ class }}">

        {{ message }}

    </div>

{% endmacro %}
```

Use:

```
{{ alert("Welcome!") }}
```

or:

```
{{ alert("Invalid password", "error") }}
```

This produces different styles using the same HTML structure.

---

# 17. Macro With Conditional Logic

Macros can contain normal Jinja2 logic.

```
{% macro user_status(active) %}

    {% if active %}

        <span class="active">
            Active
        </span>

    {% else %}

        <span class="inactive">
            Inactive
        </span>

    {% endif %}

{% endmacro %}
```

Call:

```
{{ user_status(True) }}
```

or:

```
{{ user_status(False) }}
```

So a macro can contain:

```
HTML
 +
Variables
 +
Conditions
 +
Loops
 +
Filters
```

---

# 18. Macro With a Loop

For example:

```
{% macro show_list(items) %}

    <ul>

        {% for item in items %}

            <li>{{ item }}</li>

        {% endfor %}

    </ul>

{% endmacro %}
```

Call:

```
{{ show_list(["Python", "Flask", "MySQL"]) }}
```

Output:

```
• Python
• Flask
• MySQL
```

---

# 19. Macro With Filters

Macros can use filters too.

```
{% macro username(name) %}

    <p>
        {{ name | title }}
    </p>

{% endmacro %}
```

Call:

```
{{ username("john doe") }}
```

Output:

```
John Doe
```

# 20. Macro for a Card

A common real-world pattern:

### `macros.html`

```
{% macro card(title, description) %}

    <div class="card">

        <h2>
            {{ title }}
        </h2>

        <p>
            {{ description }}
        </p>

    </div>

{% endmacro %}
```

Then:

```
{% from "macros.html" import card %}

{{ card(
    "Python",
    "A programming language."
) }}

{{ card(
    "Flask",
    "A Python web framework."
) }}
```

One macro generates multiple cards.

---

# 21. Macro vs Include

This is extremely important because they can look similar.

### Include

```
{% include "card.html" %}
```

An include basically says:

> Insert this template here.

### Macro

```
{{ card(title, description) }}
```

A macro says:

> Generate this reusable template structure using these parameters.

---

# 22. Visual Difference

### Include

```
card.html
   │
   ▼
Insert this template
```

Generally:

```
{% include "card.html" %}
```

---

### Macro

```
card macro
    │
    ├── title = Python
    ├── description = ...
    │
    ▼
Generated card

    │
    ├── title = Flask
    ├── description = ...
    │
    ▼
Generated card
```

So:

```
include → reusable template

macro   → reusable template function
```

---

# 23. Macro vs Function

If you know Python functions, macros are easy to understand.

### Python

```
def greet(name):
    return f"Hello {name}"
```

Call:

```
greet("John")
```

### Jinja2

```
{% macro greet(name) %}

    Hello {{ name }}

{% endmacro %}
```

Call:

```
{{ greet("John") }}
```

The concept is similar:

```
Function
    ↓
Input
    ↓
Output

Macro
    ↓
Parameters
    ↓
Generated template output
```

But a Jinja2 macro is designed for template rendering, not general Python logic.

# 24. Where Should Macros Live?

For small projects:

```
templates/
├── base.html
├── macros.html
├── home.html
└── about.html
```

For larger projects:

```
templates/
│
├── base.html
│
├── macros/
│   ├── forms.html
│   ├── buttons.html
│   ├── cards.html
│   └── navigation.html
│
├── home.html
└── about.html
```

You can then import only what you need.

For example:

```
{% from "macros/forms.html" import input %}
```

# 25. A Complete Example

### Project

```
myproject/
│
├── app.py
│
└── templates/
    │
    ├── base.html
    ├── home.html
    │
    └── macros/
        └── ui.html
```

### `macros/ui.html`

```
{% macro button(text, type="button") %}

    <button type="{{ type }}">
        {{ text }}
    </button>

{% endmacro %}


{% macro card(title, description) %}

    <div class="card">

        <h2>{{ title }}</h2>

        <p>{{ description }}</p>

    </div>

{% endmacro %}
```

### `home.html`

```
{% extends "base.html" %}

{% from "macros/ui.html" import button, card %}


{% block content %}

    <h1>Home</h1>

    {{ button("Click Me") }}

    {{ button("Save", "submit") }}


    {{ card(
        "Python",
        "A programming language."
    ) }}

    {{ card(
        "Flask",
        "A web framework for Python."
    ) }}

{% endblock %}
```

Here we're combining **three Jinja2 concepts**:

```
extends
   ↓
Page layout

from/import
   ↓
Import macros

macro calls
   ↓
Generate reusable HTML
```

# 26. A Very Important Feature: `caller`

Macros can also accept a block of content from the caller using:

```
caller()
```

This is an advanced macro feature.

Example:

```
{% macro box(title) %}

    <div class="box">

        <h2>{{ title }}</h2>

        <div>
            {{ caller() }}
        </div>

    </div>

{% endmacro %}
```

You can call it with:

```
{% call box("Information") %}

    <p>
        This is inside the box.
    </p>

{% endcall %}
```

The content passed between:

```
{% call %}
{% endcall %}
```

becomes available through:

```
{{ caller() }}
```

Result:

```
┌─────────────────────────┐
│ Information             │
│                         │
│ This is inside the box. │
└─────────────────────────┘
```

This is powerful for building reusable layouts and components.

You don't need to memorize `caller()` yet, but understand what it does.

---

# 27. Macro Scope

Macros defined in another template aren't automatically available everywhere.

You normally need to import them:

```
{% from "macros.html" import button %}
```

or:

```
{% import "macros.html" as macros %}
```

Then use:

```
{{ macros.button("Save") }}
```

---

# 28. Common Mistakes

### Mistake 1: Forgetting to import

You created:

```
{% macro button(text) %}
    <button>{{ text }}</button>
{% endmacro %}
```

but then directly wrote:

```
{{ button("Save") }}
```

from another template.

You need:

```
{% from "macros.html" import button %}
```

first.

---

### Mistake 2: Confusing include and macro

This:

```
{% include "button.html" %}
```

doesn't call a macro.

This:

```
{{ button("Save") }}
```

does.

---

### Mistake 3: Forgetting `endmacro`

Incorrect:

```
{% macro button(text) %}

    <button>{{ text }}</button>
```

Correct:

```
{% macro button(text) %}

    <button>{{ text }}</button>

{% endmacro %}
```

# 29. Important Syntax Cheat Sheet

### Define

```
{% macro name(parameter) %}

    HTML

{% endmacro %}
```

### Call

```
{{ name(value) }}
```

### Import one

```
{% from "macros.html" import name %}
```

### Import multiple

```
{% from "macros.html" import name, button, card %}
```

### Import as namespace

```
{% import "macros.html" as macros %}
```

Then:

```
{{ macros.button("Save") }}
```

### Default parameter

```
{% macro button(text, type="button") %}
```

### Caller

```
{{ caller() }}
```

with:

```
{% call macro_name() %}

    Content

{% endcall %}
```

# 30. Include vs Macro vs Inheritance

Now you have three concepts that often get confused.

|Feature|Purpose|Example|
|---|---|---|
|`extends`|Reuse page layout|`base.html`|
|`include`|Insert reusable template|`navbar.html`|
|`macro`|Generate reusable template with parameters|`button(text)`|

### Mental shortcut

```
extends
   ↓
"I want this page's layout."

include
   ↓
"I want this component here."

macro
   ↓
"I want to generate this component with different data."
```

---

# One-Line Definition

> **A Jinja2 macro is a reusable template function that accepts parameters and generates HTML or other template output.**
