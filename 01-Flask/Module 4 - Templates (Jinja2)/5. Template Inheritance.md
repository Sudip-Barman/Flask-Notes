**Template inheritance** allows multiple HTML pages to share a **common layout** without duplicating the same HTML code in every file.

This is one of the most important Jinja2 concepts for building real Flask applications.

---

# 1. The Problem Template Inheritance Solves

Imagine a website with these pages:

```
Home
About
Login
Profile
Settings
```

Every page might have the same:

```
Navbar
Sidebar
Footer
CSS
JavaScript
```

Without template inheritance, you might create:

```
home.html
about.html
login.html
profile.html
settings.html
```

and copy this into every file:
```
<nav>
    ...
</nav>

<main>
    ...
</main>

<footer>
    ...
</footer>
```

That's bad because if you change the navbar, you have to modify **every page**.

Template inheritance solves this.

---

# 2. The Basic Idea

Create one **base template**:

```
base.html
```

It contains the common structure.

Then other templates **extend** it:

```
home.html

about.html

login.html
```

The structure becomes:

```
             base.html
                 │
       ┌─────────┼─────────┐
       ▼         ▼         ▼
    home.html  about.html  login.html
```

---

# 3. Project Structure

A simple project:

```
myproject/
│
├── app.py
│
└── templates/
    │
    ├── base.html
    ├── home.html
    ├── about.html
    └── login.html
```

---

# 4. Create `base.html`

The base template contains the common HTML.

```
<!DOCTYPE html>
<html>
<head>
    <title>{% block title %}My Website{% endblock %}</title>
</head>
<body>
    <nav>
        <a href="/">Home</a>
        <a href="/about">About</a>
        <a href="/login">Login</a>
    </nav>
    <main>
        {% block content %}
        {% endblock %}
    </main>
    <footer>
        <p>Copyright 2026</p>
    </footer>
</body>
</html>
```

The important part is:

```
{% block content %}

{% endblock %}
```

This creates a **replaceable area**.

---

# 5. Create `home.html`

Now the home page can extend `base.html`.

```
{% extends "base.html" %}

{% block content %}

    <h1>Home Page</h1>

    <p>Welcome to the website.</p>

{% endblock %}
```

That's it.

The home page doesn't need to repeat:

```
<!DOCTYPE html>
<html>
<head>
...
</head>
<body>
...
<footer>
...
</footer>
```

because those things already exist in `base.html`.

---

# 6. What Actually Happens?

Jinja2 sees:

```
{% extends "base.html" %}
```

and thinks:

> "Use `base.html` as the main structure."

Then it finds:

```
{% block content %}
```

and replaces that block with the content from `home.html`.

So:

### Base template

```
base.html

  
Navbar
   ↓
[ content block ]
   ↓
Footer
```

### Child template

```
home.html

  
content block:
    Home Page
    Welcome...
```
### Final HTML

```
Navbar
   ↓
Home Page

Welcome...
   ↓
Footer
```

---

# 7. `extends`

The first important Jinja2 inheritance statement is:

```
{% extends "base.html" %}
```

It tells Jinja2:

> This template inherits from `base.html`.

Usually, `extends` should appear near the top of the template.

---

# 8. `block`

A block defines an area that child templates can replace.

In `base.html`:

```
{% block content %}

{% endblock %}

In the child:

{% block content %}

    <h1>Home Page</h1>

{% endblock %}
```

The block name must match:

```
base.html          home.html

────────────────────────────────

block content  ←→  block content
```

---

# 9. Multiple Blocks

You aren't limited to one block.

For example:

```
<!DOCTYPE html>
<html>
<head>
    <title>
        {% block title %}
            My Website
        {% endblock %}
    </title>
</head>
<body>
    <header>
        {% block header %}
        {% endblock %}
    </header>
    <main>
        {% block content %}
        {% endblock %}
    </main>
    <footer>
        {% block footer %}
        {% endblock %}
    </footer>
</body>
</html>
```

  

A child template can override any of these.

---

# 10. Changing the Page Title

### `base.html`

```
<title>
    {% block title %}
        My Website
    {% endblock %}
</title>
```
### `home.html`

```
{% extends "base.html" %}
{% block title %}
    Home
{% endblock %}
{% block content %}
    <h1>Home Page</h1>
{% endblock %}
```

The browser title becomes:

```
Home
```

while the rest of the layout still comes from `base.html`.

---

# 11. Another Page

### `about.html`

```
{% extends "base.html" %}

{% block title %}
    About
{% endblock %}

{% block content %}

    <h1>About Us</h1>

    <p>This is the about page.</p>

{% endblock %}
```

Now you have:

```
base.html
    │
    ├── home.html
    └── about.html
```

Both pages share the same layout.

---

# 12. Flask Routes

Your Flask application can render these templates normally.

```
from flask import Flask, render_template

  

app = Flask(__name__)

  

@app.route("/")
def home():
    return render_template("home.html")

  
@app.route("/about")
def about():
    return render_template("about.html")


@app.route("/login")
def login():
    return render_template("login.html")


if __name__ == "__main__":
    app.run(debug=True)
```

The inheritance happens inside Jinja2, not inside the Flask route.

# 14. Default Block Content

A block can have default content.

In `base.html`:

```
{% block title %}

    My Website

{% endblock %}
```

If a child template doesn't override `title`, the default:

```
My Website
```

is used.

---

# 15. Overriding a Block

Base:

```
{% block title %}

    My Website

{% endblock %}
```

Child:

```
{% block title %}

    About

{% endblock %}
```

The child replaces the parent's block.

```
Parent:
My Website

        ↓ override

Child:
About
```

---

# 16. Calling the Parent Block with `super()`

Sometimes you don't want to completely replace the parent's content.

You want to **keep the parent content and add something to it**.

Jinja2 provides:

```
{{ super() }}
```

Example:

### Base

```
{% block content %}

    <p>Common content</p>

{% endblock %}
```

### Child

```
{% extends "base.html" %}

{% block content %}

    {{ super() }}

    <p>Additional content</p>

{% endblock %}
```

Result:

```
Common content

Additional content
```

So:

```
super()
   ↓
Parent block content
```

# 17. A Realistic Layout

A practical `base.html` might look like:

<!DOCTYPE html>

  

<html>

  

<head>

  

    <meta charset="UTF-8">

  

    <meta name="viewport"

          content="width=device-width, initial-scale=1.0">

  

    <title>

        {% block title %}

            My Website

        {% endblock %}

    </title>

  

    <link rel="stylesheet"

          href="{{ url_for('static', filename='css/style.css') }}">

  

</head>

  

<body>

  

    <nav>

  

        <a href="/">Home</a>

        <a href="/about">About</a>

        <a href="/login">Login</a>

  

    </nav>

  

  

    <main>

  

        {% block content %}

Then:

{% extends "base.html" %}

  

{% block title %}

    Home

{% endblock %}

  

{% block content %}

  

    <h1>Welcome</h1>

  

    <p>This is the home page.</p>

  

{% endblock %}

This is much closer to how real Flask applications are structured.

---

# 18. Why This Is Better

Without inheritance:

home.html

 ├── Navbar

 ├── Content

 └── Footer

  

about.html

 ├── Navbar

 ├── Content

 └── Footer

  

login.html

 ├── Navbar

 ├── Content

 └── Footer

Lots of duplication.

With inheritance:

             base.html

          ┌──────┼──────┐

          ↓      ↓      ↓

        home   about   login

Common structure exists only once.

---

# 19. What If You Change the Navbar?

Suppose you have:

<nav>

    <a href="/">Home</a>

    <a href="/about">About</a>

</nav>

in `base.html`.

Later you change it to:

<nav>

    <a href="/">Home</a>

    <a href="/about">About</a>

    <a href="/contact">Contact</a>

</nav>

Every child template automatically gets the new navbar.

You modify **one file**, not ten.

That's the real power of inheritance.

{% block x %}

prefer:

{% block content %}

{% block scripts %}

Meaningful names make large projects much easier to understand.

# 22. A Very Useful `scripts` Block

Sometimes one particular page needs extra JavaScript.

Base:

<body>

  

    {% block content %}

    {% endblock %}

  

  

    <script src="/static/js/main.js"></script>

  

    {% block scripts %}

    {% endblock %}

  

</body>

Child:

{% extends "base.html" %}

  

{% block content %}

  

    <h1>Dashboard</h1>

  

{% endblock %}

  

  

{% block scripts %}

  

    <script src="/static/js/dashboard.js"></script>

  

{% endblock %}

Now:

Every page

   ↓

main.js

  

Dashboard only

   ↓

dashboard.js

This is a very common pattern.

---

# 23. `extends` Must Refer to the Template

If:

templates/

├── base.html

└── home.html

then:

{% extends "base.html" %}

works.

For nested templates:

templates/

│

├── base.html

│

└── admin/

    └── dashboard.html

you can still extend:

{% extends "base.html" %}

Jinja2 searches the template environment.

---

# 24. Common Mistake: Forgetting `extends`

If you write:

{% block content %}

  

    <h1>Hello</h1>

  

{% endblock %}

but don't write:

{% extends "base.html" %}

then the template isn't inheriting from your base layout.

Usually the child template starts with:

{% extends "base.html" %}

---

# 25. Common Mistake: Wrong Block Name

Base:

{% block content %}

{% endblock %}

Child:

{% block contents %}

These are different names:

content

contents

So the child won't override the intended block.

They must match exactly.

---

# 26. Template Inheritance vs Copy-Paste

### Without inheritance

100 lines × 10 pages

=

1000 lines

A lot of duplicated markup.

### With inheritance

base.html

+

10 small child templates

Much cleaner.

The goal isn't merely fewer lines. It's **one source of truth for shared layout**.

# Mental Model

Think of `base.html` as the **skeleton** of your website:

              base.html

                 │

        ┌────────┴────────┐

        │                 │

     fixed parts      changeable blocks

        │                 │

   Navbar/Footer       Content/Title

                          │

                    child templates

The child template doesn't rebuild the skeleton. It simply says:

> "Use that layout, and here's what I want inside these blocks."

---

## One-Line Definition

> **Template inheritance allows child Jinja2 templates to reuse a common parent template and override specific blocks instead of duplicating HTML.**
