In a real application, data is rarely stored in only one table.

For example, a school database might have:

```
students
courses
teachers
departments
```

These tables often need to be connected.

For example:

```
Student ───────→ Course
```

A student can enroll in courses, and a course can have many students.

This connection between tables is called a **relationship**.

---

# 6.1 What is a Database Relationship?

A database relationship describes how records in one table are connected to records in another table.

For example:

```
students                  courses

id | name                  id | title
---+-------              ----+----------
1  | Rahul                1  | Python
2  | Priya                2  | SQL
```

Suppose Rahul belongs to one department:

```
Student
   │
   │ belongs to
   ↓
Department
```

The database needs a way to represent this connection.

Usually, this is done using a **Foreign Key**.

---

# 6.2 Why Relationships Are Needed

Suppose we store everything in one giant table:

```
students

id | student_name | department_name | department_head
---+--------------+-----------------+----------------
1  | Rahul        | Computer        | Dr. Sen
2  | Priya        | Computer        | Dr. Sen
3  | Amit         | Computer        | Dr. Sen
```

There is a lot of repeated information.

Instead, we can separate the data:

```
students
departments
```

and connect them.

```
students                    departments

id | name | department_id   id | name
---+------+--------------   ---+------------
1  | Rahul| 1                1 | Computer
2  | Priya| 1                2 | Mathematics
3  | Amit | 1
```

Now:

```
student.department_id
        ↓
departments.id
```

This is a much cleaner database design.

---

# 6.3 Foreign Key

A **Foreign Key** is a column that refers to a key in another table.

Example:

```
department_id = db.Column(
    db.Integer,
    db.ForeignKey("departments.id")
)
```

Here:

```
department_id
      ↓
departments.id
```

So the student table can reference a department.

---

# 6.4 Primary Key vs Foreign Key

This distinction is extremely important.

### Primary Key

Uniquely identifies a record **inside its own table**.

```
id = db.Column(
    db.Integer,
    primary_key=True
)
```

### Foreign Key

References a key in **another table**.

```
department_id = db.Column(
    db.Integer,
    db.ForeignKey("departments.id")
)
```

Think:

```
Primary Key
     ↓
"My identity"


Foreign Key
     ↓
"The record I am connected to"
```

---

# 6.5 Example: Department and Student

Let's create two models.

### Department

```
class Department(db.Model):
    __tablename__ = "departments"

    id = db.Column(
        db.Integer,
        primary_key=True
    )

    name = db.Column(
        db.String(100),
        nullable=False
    )
```

### Student

```
class Student(db.Model):
    __tablename__ = "students"

    id = db.Column(
        db.Integer,
        primary_key=True
    )

    name = db.Column(
        db.String(100),
        nullable=False
    )

    department_id = db.Column(
        db.Integer,
        db.ForeignKey("departments.id")
    )
```

Now the database structure is:

```
departments
----------------
id
name


students
----------------
id
name
department_id
```

And:

```
students.department_id
          ↓
departments.id
```

---

# 6.6 What Does `db.ForeignKey()` Do?

This:

```
db.ForeignKey("departments.id")
```

tells SQLAlchemy:

> The value in this column refers to the `id` column of the `departments` table.

The syntax is:

```
db.ForeignKey("table_name.column_name")
```

Example:

```
db.ForeignKey("departments.id")
```

Breakdown:

```
departments → table
id          → column
```

---

# 6.7 Foreign Key Alone Is Not the Whole ORM Relationship

This is an important distinction.

You might have:

```
department_id = db.Column(
    db.Integer,
    db.ForeignKey("departments.id")
)
```

This creates a **database-level foreign key**.

But you usually also want Python-level navigation between objects.

For example:

```
student.department
```

and:

```
department.students
```

For that, SQLAlchemy provides:

```
relationship()
```

So:

```
ForeignKey
    ↓
Database connection

relationship()
    ↓
Python/ORM connection
```

Together they make relationships much easier to work with.

---

# 6.8 `relationship()`

Let's add a relationship.

### Department

```
class Department(db.Model):
    __tablename__ = "departments"

    id = db.Column(
        db.Integer,
        primary_key=True
    )

    name = db.Column(
        db.String(100),
        nullable=False
    )

    students = db.relationship(
        "Student",
        back_populates="department"
    )
```

### Student

```
class Student(db.Model):
    __tablename__ = "students"

    id = db.Column(
        db.Integer,
        primary_key=True
    )

    name = db.Column(
        db.String(100),
        nullable=False
    )

    department_id = db.Column(
        db.Integer,
        db.ForeignKey("departments.id")
    )

    department = db.relationship(
        "Department",
        back_populates="students"
    )
```

Now SQLAlchemy understands:

```
Department
    │
    │ students
    ↓
Student
```

and:

```
Student
    │
    │ department
    ↓
Department
```

---

# 6.9 Understanding `back_populates`

We have:

```
students = db.relationship(
    "Student",
    back_populates="department"
)
```

and:

```
department = db.relationship(
    "Department",
    back_populates="students"
)
```

These two properties point toward each other.

```
Department.students
        ↕
Student.department
```

So:

```
student.department
```

can access the student's department.

And:

```
department.students
```

can access the students belonging to that department.

---

# 6.10 One-to-Many Relationship

The previous example is a:

> **One-to-Many relationship**

One department can have many students.

```
Department
     │
     ├── Student 1
     ├── Student 2
     ├── Student 3
     └── Student 4
```

But each student belongs to one department.

```
One Department
      ↓
Many Students
```

---

# 6.11 One-to-Many Model

Complete example:

```
class Department(db.Model):
    __tablename__ = "departments"

    id = db.Column(
        db.Integer,
        primary_key=True
    )

    name = db.Column(
        db.String(100),
        nullable=False
    )

    students = db.relationship(
        "Student",
        back_populates="department"
    )


class Student(db.Model):
    __tablename__ = "students"

    id = db.Column(
        db.Integer,
        primary_key=True
    )

    name = db.Column(
        db.String(100),
        nullable=False
    )

    department_id = db.Column(
        db.Integer,
        db.ForeignKey("departments.id"),
        nullable=False
    )

    department = db.relationship(
        "Department",
        back_populates="students"
    )
```

The important parts are:

```
db.ForeignKey("departments.id")
```

and:

```
db.relationship(
    "Department",
    back_populates="students"
)
```

---

# 6.12 Creating Related Objects

Suppose we create a department:

```
department = Department(
    name="Computer Science"
)

db.session.add(department)
db.session.commit()
```

Now create a student:

```
student = Student(
    name="Rahul",
    department=department
)

db.session.add(student)
db.session.commit()
```

Notice:

```
department=department
```

We don't have to manually write:

```
department_id=department.id
```

when using the relationship.

SQLAlchemy can handle the foreign key value.

---

# 6.13 Accessing the Student's Department

Suppose:

```
student = db.session.get(Student, 1)
```

You can do:

```
print(student.department.name)
```

Output:

```
Computer Science
```

The flow is:

```
student
   ↓
student.department
   ↓
Department object
   ↓
department.name
```

---

# 6.14 Accessing Students from a Department

Suppose:

```
department = db.session.get(
    Department,
    1
)
```

Then:

```
department.students
```

returns a collection of Student objects.

For example:

```
for student in department.students:
    print(student.name)
```

Output:

```
Rahul
Priya
Amit
```

This is one of the biggest benefits of ORM relationships.

---

# 6.15 Relationship Direction

Notice the difference:

### Student → Department

```
student.department
```

returns **one Department**.

### Department → Students

```
department.students
```

returns **multiple Students**.

So:

```
Student
   │
   │ department
   ↓
Department


Department
   │
   │ students
   ↓
[Student, Student, Student]
```

---

# 6.16 One-to-One Relationship

Another common relationship is:

> **One-to-One**

Example:

```
Person
  │
  ↓
Passport
```

One person has one passport.

One passport belongs to one person.

SQLAlchemy can represent this using `uselist=False`.

Example:

```
class Person(db.Model):
    __tablename__ = "persons"

    id = db.Column(
        db.Integer,
        primary_key=True
    )

    name = db.Column(
        db.String(100)
    )

    passport = db.relationship(
        "Passport",
        back_populates="person",
        uselist=False
    )
```

```
class Passport(db.Model):
    __tablename__ = "passports"

    id = db.Column(
        db.Integer,
        primary_key=True
    )

    person_id = db.Column(
        db.Integer,
        db.ForeignKey("persons.id"),
        unique=True
    )

    person = db.relationship(
        "Person",
        back_populates="passport"
    )
```

The important idea is:

```
Person
   ↓
one Passport
```

rather than:

```
Person
   ↓
many Passports
```

---

# 6.17 Many-to-Many Relationship

Now consider:

```
Student ↔ Course
```

A student can enroll in multiple courses.

A course can contain multiple students.

For example:

```
Rahul → Python
Rahul → SQL

Priya → Python
Priya → Flask
```

This is:

> **Many-to-Many**

```
Students                Courses

Rahul ───────────────→ Python
  │                       ↑
  └───────────────────────┘

Priya ────────────────→ Flask
  │
  └──────────────────→ Python
```

A many-to-many relationship normally requires an **association table**.

---

# 6.18 Association Table

Instead of directly connecting:

```
students ↔ courses
```

we create:

```
student_courses
```

For example:

```
student_courses

student_id | course_id
-----------+----------
1          | 1
1          | 2
2          | 1
2          | 3
```

This means:

```
Student 1 → Course 1
Student 1 → Course 2
Student 2 → Course 1
Student 2 → Course 3
```

---

# 6.19 Many-to-Many Example

Define an association table:

```
student_courses = db.Table(
    "student_courses",

    db.Column(
        "student_id",
        db.Integer,
        db.ForeignKey("students.id"),
        primary_key=True
    ),

    db.Column(
        "course_id",
        db.Integer,
        db.ForeignKey("courses.id"),
        primary_key=True
    )
)
```

Then:

```
class Student(db.Model):
    __tablename__ = "students"

    id = db.Column(
        db.Integer,
        primary_key=True
    )

    name = db.Column(
        db.String(100),
        nullable=False
    )

    courses = db.relationship(
        "Course",
        secondary=student_courses,
        back_populates="students"
    )
```

And:

```
class Course(db.Model):
    __tablename__ = "courses"

    id = db.Column(
        db.Integer,
        primary_key=True
    )

    title = db.Column(
        db.String(100),
        nullable=False
    )

    students = db.relationship(
        "Student",
        secondary=student_courses,
        back_populates="courses"
    )
```

Now:

```
student.courses
```

can return multiple courses.

And:

```
course.students
```

can return multiple students.

---

# 6.20 Adding Many-to-Many Data

Create a student:

```
student = Student(
    name="Rahul"
)
```

Create courses:

```
python_course = Course(
    title="Python"
)

sql_course = Course(
    title="SQL"
)
```

Connect them:

```
student.courses.append(python_course)
student.courses.append(sql_course)
```

Then:

```
db.session.add(student)
db.session.commit()
```

SQLAlchemy can create the appropriate records in the association table.

# 6.21 Relationship Types Summary

There are three major relationship patterns:

```
1. One-to-One

Person ───── Passport


2. One-to-Many

Department ─────┬── Student
                ├── Student
                └── Student


3. Many-to-Many

Student ─────┬──── Course
             ├──── Course
             │
Student ─────┴──── Course
```

---

# 6.22 `back_populates` vs `backref`

You may see older or alternative SQLAlchemy code using:

```
db.relationship(
    "Student",
    backref="department"
)
```

`backref` can automatically create the reverse relationship.

For example:

```
students = db.relationship(
    "Student",
    backref="department"
)
```

Then:

```
student.department
```

can work without explicitly declaring the reverse relationship.

However, `back_populates` explicitly defines both sides:

```
# Department
students = db.relationship(
    "Student",
    back_populates="department"
)
```

```
# Student
department = db.relationship(
    "Department",
    back_populates="students"
)
```

For learning and larger projects, explicit `back_populates` is often easier to understand because both sides are visible.

---

# 6.23 `cascade`

Relationships can also define what happens to related objects when a parent is deleted.

For example:

```
students = db.relationship(
    "Student",
    back_populates="department",
    cascade="all, delete-orphan"
)
```

This can mean that when a department is deleted, its associated student objects are also handled according to the cascade configuration.

### Important

Cascade behavior needs careful design.

You should not blindly add:

```
cascade="all, delete-orphan"
```

to every relationship.

The correct behavior depends on the business rules and database design.

This distinction is worth memorizing.

### Foreign Key

```
department_id = db.Column(
    db.Integer,
    db.ForeignKey("departments.id")
)
```

Purpose:

```
Database-level connection
```

### Relationship

```
department = db.relationship(

Purpose:

```
Python/ORM-level navigation
```

Together:

```

# 6.25 A Complete One-to-Many Example

Here is the example you should understand thoroughly:

```
from flask_sqlalchemy import SQLAlchemy

db = SQLAlchemy()


class Department(db.Model):
    __tablename__ = "departments"

    id = db.Column(
        db.Integer,
        primary_key=True
    )

    name = db.Column(
        db.String(100),
        nullable=False
    )

    students = db.relationship(
        "Student",
        back_populates="department"
    )


class Student(db.Model):
    __tablename__ = "students"

    id = db.Column(
        db.Integer,
        primary_key=True
    )

    name = db.Column(
        db.String(100),
        nullable=False
    )

    department_id = db.Column(
        db.Integer,
        db.ForeignKey("departments.id"),
        nullable=False
    )

    department = db.relationship(
        "Department",
        back_populates="students"
    )
```

The structure is:

```
Department
   │
   │ students
   ↓
Student
   │
   │ department
   ↓
Department
```

And in the database:

```
departments
----------------
id
name


students
----------------
id
name
department_id
     │
     └────────────→ departments.id
```

# 6.27 Relationship Loading

When you access:

```
student.department
```

SQLAlchemy may need to retrieve the related department from the database.

Similarly:

```
department.students
```

may require SQLAlchemy to retrieve the related students.

This leads to concepts such as:

```
Lazy Loading
Eager Loading
Joined Loading
Select-in Loading
```

These become important for performance, especially when working with many related records.

You don't need to master them yet. The key thing for now is understanding **what a relationship represents**.

# 6.28 Common Relationship Mistakes

### Mistake 1: Confusing ForeignKey with relationship

This:

```
department_id = db.Column(
    db.Integer,
    db.ForeignKey("departments.id")
)
```

does not give you:

```
student.department
```

by itself.

For ORM navigation, you normally also define:

```
department = db.relationship(...)
```

---

### Mistake 2: Wrong foreign-key table name

If your table is:

```
__tablename__ = "departments"
```

then use:

```
db.ForeignKey("departments.id")
```

not:

```
db.ForeignKey("department.id")
```

unless the actual table is named `department`.

---

### Mistake 3: Forgetting `back_populates` consistency

If you write:

```
students = db.relationship(
    "Student",
    back_populates="department"
)
```

the `Student` model should have:

```
department = db.relationship(
    "Department",
    back_populates="students"
)
```

The names need to match.

---

### Mistake 4: Using the wrong relationship type

Don't model:

```
Department → Student
```

as many-to-many if every student belongs to only one department.

Choose the relationship based on the actual data rules.
