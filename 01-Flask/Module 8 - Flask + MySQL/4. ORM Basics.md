ORM is one of the most important concepts in Flask-SQLAlchemy because it changes how you interact with a database.

Instead of thinking primarily in terms of SQL queries and rows, you can work with **Python classes and objects**.

---

# 4.1 What is ORM?

**ORM** stands for:

> **Object-Relational Mapping**

It is a technique that maps:

```
Python Objects
      ↕
Database Tables
```

With SQLAlchemy ORM:

```
Python                         Database

Class             →           Table
Object            →           Row
Attribute         →           Column
```

For example:

```
class Student(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(100))
    age = db.Column(db.Integer)
```

maps approximately to:

```
Student class
      ↓
students table

id    → id column
name  → name column
age   → age column
```

---

# 4.2 Why Do We Need ORM?

Without ORM, you might write SQL manually.

For example, to get all students:

```
SELECT * FROM students;
```

With SQLAlchemy ORM:

```
students = Student.query.all()
```

To find one student:

```
SELECT * FROM students WHERE id = 1;
```

With ORM:

```
student = Student.query.get(1)
```

So ORM allows you to work with the database using Python syntax.

---

# 4.3 ORM Without SQLAlchemy

Imagine you have this table:

```
students

+----+--------+-----+
| id | name   | age |
+----+--------+-----+
| 1  | Rahul  | 20  |
| 2  | Priya  | 21  |
| 3  | Amit   | 19  |
+----+--------+-----+
```

Normally, SQL works with:

```
Database
   ↓
Table
   ↓
Rows
   ↓
Columns
```

ORM gives you:

```
Database
   ↓
Model
   ↓
Python Objects
   ↓
Attributes
```

For example:

```
student.name
```

instead of manually extracting the `name` column from a SQL result.

---

# 4.4 The Core ORM Mapping

This is the most important part:

```
┌──────────────────┬──────────────────┐
│ Python           │ Database         │
├──────────────────┼──────────────────┤
│ Class            │ Table            │
│ Object           │ Row              │
│ Attribute        │ Column           │
│ Object list      │ Multiple rows    │
└──────────────────┴──────────────────┘
```

Example:

```
class Student(db.Model):
    ...
```

↓

```
students table
```

Then:

```
student = Student(...)
```

↓

```
one row
```

And:

```
student.name
```

↓

```
name column
```

---

# 4.5 Creating an Object

Suppose we have:

```
class Student(db.Model):
    __tablename__ = "students"

    id = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(100), nullable=False)
    age = db.Column(db.Integer)
```

We can create a Python object:

```
student = Student(
    name="Rahul",
    age=20
)
```

At this moment, `student` is just a Python/SQLAlchemy object.

It has **not necessarily been saved to the database yet**.

Think:

```
Student object
       ↓
Python memory
       ↓
Not committed yet
```

---

# 4.6 Adding an Object to the Session

To tell SQLAlchemy that we want to save the object:

```
db.session.add(student)
```

Now the object is added to the SQLAlchemy session.

```
student object
      ↓
db.session.add()
      ↓
SQLAlchemy Session
```

But the data still isn't permanently committed.

---

# 4.7 Commit

To save the changes:

```
db.session.commit()
```

So the complete process is:

```
student = Student(
    name="Rahul",
    age=20
)

db.session.add(student)
db.session.commit()
```

Conceptually:

```
Create object
     ↓
Add to session
     ↓
Commit
     ↓
Database
```

SQLAlchemy will generate the appropriate SQL behind the scenes.

Conceptually, it is similar to:

```
INSERT INTO students (name, age)
VALUES ('Rahul', 20);
```

You don't normally need to write that SQL yourself.

---

# 4.8 What is `db.session`?

`db.session` is SQLAlchemy's interface for managing database operations involving ORM objects.

You will frequently use:

```
db.session.add()
db.session.add_all()
db.session.delete()
db.session.commit()
db.session.rollback()
```

For example:

```
db.session.add(student)
```

adds an object.

```
db.session.delete(student)
```

marks an object for deletion.

```
db.session.commit()
```

commits the changes.

```
db.session.rollback()
```

undoes pending changes in the current transaction.

We'll study transactions more deeply later in **8.11 Transactions**.

---

# 4.9 Reading Data with ORM

Suppose the database contains:

```
students

1 | Rahul | 20
2 | Priya | 21
3 | Amit  | 19
```

You can retrieve all records with:

```
students = Student.query.all()
```

The result is a Python list of `Student` objects.

Conceptually:

```
[
    Student(...),
    Student(...),
    Student(...)
]
```

You can then loop through them:

```
students = Student.query.all()

for student in students:
    print(student.name)
```

Output:

```
Rahul
Priya
Amit
```

---

# 4.10 Getting One Record

For example:

```
student = Student.query.get(1)
```

This asks SQLAlchemy to find the student whose primary key is `1`.

Conceptually:

```
SELECT *
FROM students
WHERE id = 1;
```

If the record exists, you get a `Student` object.

Then:

```
print(student.name)
```

might output:

```
Rahul
```

---

# 4.11 Important Note About `.get()`

In newer SQLAlchemy usage, the preferred approach for primary-key lookup is through the session:

```
student = db.session.get(Student, 1)
```

So you may encounter both styles in tutorials.

For modern SQLAlchemy code, prefer:

```
db.session.get(Student, 1)
```

when retrieving by primary key.

---

# 4.12 Filtering Data

Suppose you want students whose age is 20.

You can write:

```
students = Student.query.filter_by(age=20).all()
```

Conceptually:

```
SELECT *
FROM students
WHERE age = 20;
```

You can access the results:

```
for student in students:
    print(student.name)
```

---

# 4.13 `filter_by()`

`filter_by()` is convenient for simple equality conditions.

Example:

```
Student.query.filter_by(name="Rahul").all()
```

Equivalent idea:

```
SELECT *
FROM students
WHERE name = 'Rahul';
```

Multiple conditions:

```
Student.query.filter_by(
    age=20,
    name="Rahul"
).all()
```

Conceptually:

```
SELECT *
FROM students
WHERE age = 20
AND name = 'Rahul';
```

---

# 4.14 `filter()`

For more complex conditions, use:

```
Student.query.filter(Student.age > 18).all()
```

This represents:

```
SELECT *
FROM students
WHERE age > 18;
```

Another example:

```
Student.query.filter(Student.age >= 20).all()
```

You can use operators such as:

```
>     greater than
<     less than
>=    greater than or equal
<=    less than or equal
==    equal
!=    not equal
```

Example:

```
Student.query.filter(Student.age != 20).all()
```

---

# 4.15 `filter_by()` vs `filter()`

### `filter_by()`

Simple equality conditions:

```
Student.query.filter_by(age=20).all()
```

### `filter()`

More flexible expressions:

```
Student.query.filter(Student.age > 20).all()
```

Think:

```
filter_by()
   ↓
Simple matching

filter()
   ↓
Complex conditions
```

---

# 4.16 Ordering Results

You can order records using:

```
students = Student.query.order_by(Student.name).all()
```

Conceptually:

```
SELECT *
FROM students
ORDER BY name;
```

Descending order:

```
students = Student.query.order_by(
    Student.name.desc()
).all()
```

Ascending:

```
Student.name.asc()
```

---

# 4.17 Limiting Results

You can limit the number of results:

```
students = Student.query.limit(5).all()
```

Conceptually:

```
SELECT *
FROM students
LIMIT 5;
```

This is useful when you don't want to retrieve a huge number of rows at once.

---

# 4.18 First Result

If you only need the first matching result:

```
student = Student.query.filter_by(
    name="Rahul"
).first()
```

If no matching record exists, `first()` returns:

```
None
```

This makes it useful when a record may or may not exist.

---

# 4.19 Updating an Object

Suppose:

```
student = db.session.get(Student, 1)
```

You can change its attribute:

```
student.age = 21
```

Then:

```
db.session.commit()
```

That's it.

You don't normally need to manually write:

```
UPDATE students
SET age = 21
WHERE id = 1;
```

SQLAlchemy detects the changed object and generates the required SQL.

The flow is:

```
Get object
    ↓
Change attribute
    ↓
Commit
    ↓
Database updated
```

---

# 4.20 Deleting an Object

Suppose:

```
student = db.session.get(Student, 1)
```

To delete it:

```
db.session.delete(student)
db.session.commit()
```

Conceptually:

```
DELETE FROM students
WHERE id = 1;
```

Flow:

```
Get object
    ↓
db.session.delete()
    ↓
commit()
    ↓
Row deleted
```

---

# 4.21 `add()` vs `add_all()`

For one object:

```
db.session.add(student)
```

For multiple objects:

```
student1 = Student(name="Rahul", age=20)
student2 = Student(name="Priya", age=21)

db.session.add_all([
    student1,
    student2
])

db.session.commit()
```

So:

```
add()       → one object
add_all()   → multiple objects
```

---

# 4.22 What Happens During `commit()`?

Suppose:

```
student = Student(
    name="Rahul",
    age=20
)

db.session.add(student)
db.session.commit()
```

SQLAlchemy roughly does:

```
Student object
      ↓
Session tracks object
      ↓
commit()
      ↓
SQLAlchemy generates SQL
      ↓
MySQL executes SQL
      ↓
Data stored
```

You work with Python objects while SQLAlchemy handles much of the SQL translation.

---

# 4.23 Query Result is Not Always a Plain Dictionary

This is important for beginners.

When you do:

```
student = db.session.get(Student, 1)
```

you generally get a `Student` object.

You access its data like:

```
student.name
student.age
student.email
```

Not normally:

```
student["name"]
```

The ORM object behaves like a Python object.

---

# 4.24 ORM Example

Let's put the basic operations together.

```
# Create
student = Student(
    name="Rahul",
    age=20
)

# Add
db.session.add(student)

# Save
db.session.commit()
```

Read:

```
students = Student.query.all()

for student in students:
    print(student.name)
```

Find:

```
student = db.session.get(Student, 1)
```

Update:

```
student.age = 21
db.session.commit()
```

Delete:

```
db.session.delete(student)
db.session.commit()
```

This gives you the basic ORM lifecycle:

```
CREATE
   ↓
READ
   ↓
UPDATE
   ↓
DELETE
```

---

# 4.25 ORM vs Raw SQL

### Raw SQL

```
cursor.execute(
    "SELECT * FROM students WHERE age > 18"
)
```

You explicitly write SQL.

### ORM

```
students = Student.query.filter(
    Student.age > 18
).all()
```

You work with the model.

Both approaches ultimately interact with the same database.

---

# 4.26 ORM Does Not Mean "No SQL"

This is an important misconception.

SQLAlchemy provides several levels of database interaction:

```
High-level
    ↓
ORM
    ↓
SQLAlchemy SQL Expression Language
    ↓
Raw SQL
    ↓
Database
```

ORM is simply the high-level approach.

There are situations where raw SQL is useful, which is why your Module 8 also contains:

```
9. Raw SQL
```

We'll cover that later.

# 4.27 Advantages of ORM

### 1. Python-friendly

You work with Python classes and objects.

### 2. Less repetitive SQL

Common database operations don't require manually writing SQL every time.

### 3. Easier model organization

Database structures are represented in Python code.

### 4. Relationships become easier

SQLAlchemy provides tools for connecting models.

We'll explore this in:

**8.6 Relationships**

### 5. Better integration with Flask

Flask-SQLAlchemy provides convenient integration through:

```
db.Model
db.session
```

### 6. Database abstraction

SQLAlchemy can work with multiple database systems, although database-specific behavior still exists.

---

# 4.28 Disadvantages of ORM

ORM isn't magic dust. 🪄

### 1. Can hide SQL complexity

You may not immediately know what SQL is being generated.

### 2. Complex queries can become complicated

Some advanced database operations may be easier to understand directly in SQL.

### 3. Performance can be misunderstood

Poor ORM usage can generate inefficient queries.

### 4. You still need SQL knowledge

A good backend developer should understand both:

```
SQL
+
ORM
```

Learning SQL first was therefore a very good foundation.


# 4.30 ORM Cheat Sheet

|Operation|SQLAlchemy|
|---|---|
|Create object|`Student(...)`|
|Add one|`db.session.add(obj)`|
|Add many|`db.session.add_all([...])`|
|Save|`db.session.commit()`|
|Get all|`Student.query.all()`|
|Get by primary key|`db.session.get(Student, id)`|
|Simple filter|`Student.query.filter_by(age=20).all()`|
|Complex filter|`Student.query.filter(Student.age > 18).all()`|
|First result|`Student.query.first()`|
|Sort|`Student.query.order_by(Student.name).all()`|
|Limit|`Student.query.limit(5).all()`|
|Update|Change object attribute + `commit()`|
|Delete|`db.session.delete(obj)` + `commit()`|
|Undo pending changes|`db.session.rollback()`|

# 4.31 The ORM Lifecycle

Remember this sequence:

```
              CREATE
                 ↓
        Student(...)
                 ↓
          session.add()
                 ↓
              COMMIT
                 ↓
             DATABASE
                 ↓
              QUERY
                 ↓
         Python Object
                 ↓
          Modify Object
                 ↓
              COMMIT
                 ↓
          Updated Database
```

For deletion:

```
Database
   ↓
Get Object
   ↓
session.delete()
   ↓
commit()
   ↓
Row Deleted
```

# 4.32 Key Things to Remember

If you're revising this topic before an exam or interview, remember these points:

1. **ORM = Object-Relational Mapping.**
2. A model represents a database table.
3. A model class maps to a table.
4. A model object maps to a row.
5. A model attribute maps to a column.
6. `db.session` manages ORM database operations.
7. `db.session.add()` adds an object to the session.
8. `db.session.commit()` saves pending changes.
9. `db.session.delete()` marks an object for deletion.
10. `db.session.rollback()` rolls back pending changes.
11. `filter_by()` is convenient for simple equality filtering.
12. `filter()` is useful for more complex conditions.
13. ORM reduces the need to write SQL manually, but **SQL knowledge is still important**.
