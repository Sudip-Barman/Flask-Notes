# 9. Raw SQL

## 1. What is Raw SQL?

**Raw SQL** means writing SQL queries directly instead of using only SQLAlchemy ORM methods.

For example, with ORM you might write:

```
students = Student.query.all()
```

With Raw SQL, you write the SQL yourself:

```
SELECT * FROM students;
```

and execute it through SQLAlchemy.

### Simple definition

> **Raw SQL = Writing and executing SQL statements directly from Python.**

---

# 2. ORM vs Raw SQL

You have already learned ORM.

### ORM

```
students = Student.query.filter_by(age=20).all()
```

SQLAlchemy generates SQL behind the scenes.

Conceptually:

```
Python code
    ↓
SQLAlchemy ORM
    ↓
SQL
    ↓
MySQL
```

### Raw SQL

You directly write:

```
SELECT * FROM students WHERE age = 20;
```

Conceptually:

```
Python
    ↓
Raw SQL
    ↓
SQLAlchemy
    ↓
MySQL
```

---

# 3. Why Use Raw SQL?

ORM is usually easier and safer for common database operations, but sometimes Raw SQL is useful.

### Common situations

- Complex SQL queries
- Advanced joins
- Database-specific features
- Complex aggregations
- Performance-sensitive queries
- Existing SQL queries
- Stored procedures
- SQL features not conveniently exposed through ORM

For example, a complicated report might be easier to express directly in SQL.

---

# 4. SQLAlchemy and Raw SQL

SQLAlchemy allows you to execute SQL using:

```
from sqlalchemy import text
```

Then:

```
result = db.session.execute(
    text("SELECT * FROM students")
)
```

The `text()` function is important when executing textual SQL through modern SQLAlchemy.

---

# 5. Basic Raw SQL Query

Suppose the database contains:

```
students
-----------------------
id | name | age
-----------------------
1  | Rahul | 20
2  | Priya | 21
3  | Amit  | 19
```

You can execute:

```
from sqlalchemy import text

result = db.session.execute(
    text("SELECT * FROM students")
)
```

`result` contains the returned rows.

You can iterate through them:

```
for row in result:
    print(row)
```

Conceptually:

```
SELECT * FROM students
        ↓
MySQL
        ↓
Rows returned
        ↓
Python
```

---

# 6. Getting Rows

You can use:

```
result = db.session.execute(
    text("SELECT * FROM students")
)

rows = result.fetchall()
```

Then:

```
for row in rows:
    print(row)
```

You can also get one row:

```
row = result.fetchone()
```

### Common methods

|Method|Purpose|
|---|---|
|`fetchone()`|Get one row|
|`fetchall()`|Get all remaining rows|
|`first()`|Get first result|
|Iteration|Process rows one by one|

---

# 7. Selecting Specific Columns

Instead of:

```
SELECT * FROM students;
```

you can write:

```
result = db.session.execute(
    text("SELECT id, name FROM students")
)
```

This is equivalent to:

```
SELECT id, name
FROM students;
```

---

# 8. Using WHERE

Suppose you want students older than 18:

```
result = db.session.execute(
    text("SELECT * FROM students WHERE age > 18")
)
```

The SQL is:

```
SELECT *
FROM students
WHERE age > 18;
```

You can use any normal SQL condition.

---

# 9. Parameterized Queries

This is one of the **most important Raw SQL concepts**.

Avoid building SQL using string concatenation.

### ❌ Bad approach

```
name = "Rahul"

query = f"SELECT * FROM students WHERE name = '{name}'"

result = db.session.execute(text(query))
```

This can create **SQL injection vulnerabilities** when values come from users.

Instead, use parameters.

### ✅ Correct approach

```
result = db.session.execute(
    text("SELECT * FROM students WHERE name = :name"),
    {"name": "Rahul"}
)
```

Here:

```
:name
```

is a parameter placeholder.

The value is supplied separately:

```
{"name": "Rahul"}
```

---

# 10. Why Parameterized Queries Matter

Suppose a user enters malicious input into a search field.

If you directly insert that input into your SQL string, the input could potentially alter the SQL query.

Parameterized SQL separates:

```
SQL structure
```

from:

```
User data
```

So:

```
text("SELECT * FROM students WHERE name = :name")
```

and:

```
{"name": user_name}
```

are treated separately.

### Remember

> **Never construct SQL queries by directly concatenating untrusted user input.**

Use parameters.

---

# 11. Multiple Parameters

You can use multiple parameters:

```
result = db.session.execute(
    text("""
        SELECT *
        FROM students
        WHERE age >= :min_age
        AND age <= :max_age
    """),
    {
        "min_age": 18,
        "max_age": 25
    }
)
```

SQL:

```
SELECT *
FROM students
WHERE age >= 18
AND age <= 25;
```

---

# 12. INSERT with Raw SQL

You can also insert data using Raw SQL.

```
result = db.session.execute(
    text("""
        INSERT INTO students (name, age)
        VALUES (:name, :age)
    """),
    {
        "name": "Rahul",
        "age": 20
    }
)
```

Then:

```
db.session.commit()
```

### Important

For INSERT, UPDATE, and DELETE, you generally need to **commit the transaction** if you want the changes permanently saved.

---

# 13. UPDATE with Raw SQL

Example:

```
db.session.execute(
    text("""
        UPDATE students
        SET age = :age
        WHERE id = :id
    """),
    {
        "age": 21,
        "id": 1
    }
)

db.session.commit()
```

This corresponds to:

```
UPDATE students
SET age = 21
WHERE id = 1;
```

---

# 14. DELETE with Raw SQL

Example:

```
db.session.execute(
    text("""
        DELETE FROM students
        WHERE id = :id
    """),
    {
        "id": 1
    }
)

db.session.commit()
```

Equivalent SQL:

```
DELETE FROM students
WHERE id = 1;
```

Again, parameters should be used for values coming from variables or users.

---

# 15. SELECT vs INSERT/UPDATE/DELETE

A useful distinction:

### SELECT

Retrieves data:

```
result = db.session.execute(
    text("SELECT * FROM students")
)
```

### INSERT

Changes data:

```
db.session.execute(
    text("INSERT INTO ...")
)

db.session.commit()
```

### UPDATE

Changes data:

```
db.session.execute(
    text("UPDATE ...")
)

db.session.commit()
```

### DELETE

Changes data:

```
db.session.execute(
    text("DELETE ...")
)

db.session.commit()
```

Mental model:

```
SELECT
   ↓
Read

INSERT
UPDATE
DELETE
   ↓
Modify
   ↓
Commit
```

# 16. Reading Column Values

Depending on the SQLAlchemy result handling, a returned row can be accessed by position:

```
for row in result:
    print(row[0])
    print(row[1])
```

You can also use mappings when you want dictionary-like access:

```
result = db.session.execute(
    text("SELECT id, name, age FROM students")
)

rows = result.mappings().all()
```

Then:

```
for row in rows:
    print(row["id"])
    print(row["name"])
    print(row["age"])
```

This is often convenient when returning data from an API.

# 17. Raw SQL in a Flask Route

You can use Raw SQL inside Flask routes.

Example:

```
from flask import Flask, jsonify
from flask_sqlalchemy import SQLAlchemy
from sqlalchemy import text

app = Flask(__name__)

app.config["SQLALCHEMY_DATABASE_URI"] = (
    "mysql+pymysql://root:password@localhost/school"
)

db = SQLAlchemy(app)


@app.route("/students")
def get_students():

    result = db.session.execute(
        text("SELECT id, name, age FROM students")
    )

    students = [
        {
            "id": row.id,
            "name": row.name,
            "age": row.age
        }
        for row in result
    ]

    return jsonify(students)
```

The flow is:

```
GET /students
      ↓
Flask Route
      ↓
Raw SQL
      ↓
MySQL
      ↓
Rows
      ↓
JSON Response
```

---

# 18. Raw SQL with Parameters in Flask

Suppose the route receives an ID:

```
@app.route("/students/<int:student_id>")
def get_student(student_id):

    result = db.session.execute(
        text("""
            SELECT id, name, age
            FROM students
            WHERE id = :student_id
        """),
        {
            "student_id": student_id
        }
    )

    row = result.fetchone()

    if row is None:
        return jsonify({
            "message": "Student not found"
        }), 404

    return jsonify({
        "id": row.id,
        "name": row.name,
        "age": row.age
    })
```

Notice that the value is passed separately:

```
{"student_id": student_id}
```

rather than being inserted into the SQL string.

# 19. Raw SQL JOIN

You can use normal SQL joins.

Suppose:

```
departments
----------------
id
name
```

and:

```
students
----------------
id
name
department_id
```

You could write:

```
result = db.session.execute(
    text("""
        SELECT
            students.name,
            departments.name AS department_name
        FROM students
        JOIN departments
            ON students.department_id = departments.id
    """)
)
```

This is ordinary SQL.

The advantage is that you have complete control over the query.

# 20. Raw SQL with Aggregation

Raw SQL is also useful for reports.

For example:

```
result = db.session.execute(
    text("""
        SELECT department_id, COUNT(*) AS student_count
        FROM students
        GROUP BY department_id

```

SQL:

```
SELECT department_id, COUNT(*) AS student_count
FROM students

```

This can be useful for:

- Reports
- Statistics
- Dashboards
- Analytics
- Aggregated data

# 21. Raw SQL and Transactions

Raw SQL operations participate in SQLAlchemy's session/transaction system.

For example:

```
db.session.execute(
    text("""
        UPDATE students
        SET age = :age
        WHERE id = :id
    """),
    {
        "age": 21,
        "id": 1
    }
)

db.session.commit()
```

If something goes wrong before committing:

```
db.session.rollback()
```

can undo the uncommitted changes.

Transactions will be covered in detail in **Topic 11: Transactions**.

---

# 22. Error Handling

Raw SQL can also produce database errors.

You can handle them using SQLAlchemy exceptions.

For example:

```
from sqlalchemy.exc import SQLAlchemyError

try:
    db.session.execute(
        text("""
            UPDATE students
            SET age = :age
            WHERE id = :id
        """),
        {
            "age": 21,
            "id": 1
        }
    )

    db.session.commit()

except SQLAlchemyError:
    db.session.rollback()
    raise
```

The important pattern is:

```
try
  ↓
Execute SQL
  ↓
Commit
  ↓
Success

Exception
  ↓
Rollback
```

# 23. Raw SQL vs ORM

Let's compare them directly.

|Task|ORM|Raw SQL|
|---|---|---|
|Get all students|`Student.query.all()`|`SELECT * FROM students`|
|Find by ID|`db.session.get(Student, 1)`|`SELECT ... WHERE id = :id`|
|Insert|`db.session.add()`|`INSERT`|
|Update|Modify object|`UPDATE`|
|Delete|`db.session.delete()`|`DELETE`|
|Complex query|Sometimes verbose|Often easier|
|SQL knowledge required|Lower|Higher|
|Database-specific SQL|Less convenient|Easier|
|Type/model abstraction|Strong|Less|
|Fine-grained SQL control|Lower|High|

---

# 24. ORM Does Not Replace SQL Knowledge

This is important for your learning.

SQLAlchemy ORM allows you to write:

```
students = Student.query.filter(
    Student.age > 18
).all()
```

But underneath, SQL is still being executed.

Conceptually:

```
Python ORM
     ↓
SQLAlchemy
     ↓
SELECT ...
FROM students
WHERE age > 18
     ↓
MySQL
```

Therefore, learning SQL remains valuable even when you use an ORM.

---

# 25. When Should You Use ORM?

Use ORM for common application operations such as:

```
Create user
Get user
Update user
Delete user
Find products
Find orders
```

For example:

```
student = db.session.get(Student, 1)
```

is clean and easy to maintain.

---

# 26. When Should You Use Raw SQL?

Raw SQL can be a good choice when:

### Complex query

```
JOIN
GROUP BY
HAVING
SUBQUERY
CTE
WINDOW FUNCTIONS
```

make an ORM query difficult to understand.

### Database-specific features

You may need SQL that is specific to your database system.

### Existing SQL

You already have a tested SQL query that you want to use.

### Advanced reporting

For example:

```
SUM()
AVG()
COUNT()
GROUP BY
```

with multiple joins.

---

# 27. Don't Use Raw SQL Everywhere

Raw SQL gives you more control, but that doesn't mean you should use it for every operation.

For example, this:

```
student = db.session.get(Student, 1)
```

is usually much cleaner than manually writing:

```
result = db.session.execute(
    text("SELECT * FROM students WHERE id = :id"),
    {"id": 1}
)
```

For simple CRUD, ORM is generally easier.

A practical approach is:

```
Simple database operations
        ↓
      ORM

Complex/specialized queries
        ↓
     Raw SQL
```

This gives you the advantages of both approaches.

---

# 28. Important Security Rule

### Never do this with user input:

```
query = "SELECT * FROM students WHERE name = '" + name + "'"
```

or:

```
query = f"SELECT * FROM students WHERE name = '{name}'"
```

Instead:

```
query = text(
    "SELECT * FROM students WHERE name = :name"
)

result = db.session.execute(
    query,
    {"name": name}
)
```

### Remember:

```
❌ String concatenation
❌ f-string SQL

✅ Parameterized SQL
```

This helps protect against **SQL injection**.

# 29. `text()` Function

The `text()` function is provided by SQLAlchemy:

```
from sqlalchemy import text
```

Example:

```
query = text(
    "SELECT * FROM students WHERE age > :age"
)

result = db.session.execute(
    query,
    {"age": 18}
)
```

Think of:

```
text(...)
```

as telling SQLAlchemy:

> "This string is SQL that I want to execute."

# 30. Complete Example

Here is a small example combining the important concepts:

```
from flask import Flask, jsonify
from flask_sqlalchemy import SQLAlchemy
from sqlalchemy import text

app = Flask(__name__)

app.config["SQLALCHEMY_DATABASE_URI"] = (
    "mysql+pymysql://root:password@localhost/school"
)

db = SQLAlchemy(app)


@app.route("/students")
def get_students():

    result = db.session.execute(
        text("""
            SELECT id, name, age
            FROM students
            WHERE age >= :minimum_age
            ORDER BY name
        """),
        {
            "minimum_age": 18
        }
    )

    students = [
        {
            "id": row.id,
            "name": row.name,
            "age": row.age
        }
        for row in result
    ]

    return jsonify(students)


if __name__ == "__main__":
    app.run(debug=True)
```

The SQL being executed is essentially:

```
SELECT id, name, age
FROM students
WHERE age >= 18
ORDER BY name;
```

The important part is that `18` is supplied as a parameter rather than manually inserted into the SQL string.

# 31. ORM + Raw SQL Together

A real Flask application can use both.

```
# ORM
student = db.session.get(Student, 1)
```

and:

```
# Raw SQL
result = db.session.execute(
    text("""

```

You don't have to choose only one.

A common architecture is:

```
Application
    │
    ├── Simple CRUD
    │      ↓
    │     ORM
    │
    └── Complex queries
           ↓
        Raw SQL
              ↓
            MySQL
```

# 32. Key Takeaways

- **Raw SQL** means writing SQL queries directly.
- SQLAlchemy allows Raw SQL through `text()` and `db.session.execute()`.
- Raw SQL is useful for complex queries and database-specific features.
- Use **parameterized queries** instead of string concatenation.
- `SELECT` retrieves data.
- `INSERT`, `UPDATE`, and `DELETE` modify data.
- Data-changing operations generally need `commit()`.
- Use `rollback()` when an operation fails and the transaction needs to be reverted.
- ORM is usually better for common CRUD.
- Raw SQL is useful when you need more direct SQL control.
- Knowing SQL is still important even when using SQLAlchemy ORM.
