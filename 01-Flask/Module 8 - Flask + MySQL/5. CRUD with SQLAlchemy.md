 
**CRUD** stands for:

```
C → Create
R → Read
U → Update
D → Delete
```

These are the four fundamental operations performed on database data.

With Flask-SQLAlchemy, we can perform CRUD operations using **Python objects and SQLAlchemy methods** instead of writing SQL manually for every operation.

---

# 5.1 What is CRUD?

Suppose we have a `students` table:

```
students

+----+--------+-----+-------------------+
| id | name   | age | email             |
+----+--------+-----+-------------------+
| 1  | Rahul  | 20  | rahul@example.com |
| 2  | Priya  | 21  | priya@example.com |
+----+--------+-----+-------------------+
```

CRUD means:

|Operation|Meaning|Example|
|---|---|---|
|Create|Add new data|Add a student|
|Read|Retrieve data|Get students|
|Update|Modify existing data|Change student's age|
|Delete|Remove data|Delete a student|

The complete flow is:

```
             Database
                ↑
                │
        ┌───────┴───────┐
        │      CRUD     │
        ├───────────────┤
        │ Create        │
        │ Read          │
        │ Update        │
        │ Delete        │
        └───────────────┘
```

---

# 5.2 Our Model

We'll use a simple `Student` model throughout this topic.

```
from flask_sqlalchemy import SQLAlchemy

db = SQLAlchemy()


class Student(db.Model):
    __tablename__ = "students"

    id = db.Column(
        db.Integer,
        primary_key=True
    )

    name = db.Column(
        db.String(100),
        nullable=False
    )

    email = db.Column(
        db.String(120),
        unique=True,
        nullable=False
    )

    age = db.Column(
        db.Integer
    )
```

The model represents:

```
students
-------------------------------------
id       → Integer, Primary Key
name     → String
email    → String, Unique
age      → Integer
```

# 5.3 CREATE

Create means **adding new records** to the database.

In SQL, we might write:

```
INSERT INTO students (name, email, age)
VALUES ('Rahul', 'rahul@example.com', 20);
```

With SQLAlchemy ORM:

```
student = Student(
    name="Rahul",
    email="rahul@example.com",
    age=20
)

db.session.add(student)
db.session.commit()
```

That's the basic SQLAlchemy insert operation.

---

# 5.4 Step-by-Step Create

### Step 1: Create the object

```
student = Student(
    name="Rahul",
    email="rahul@example.com",
    age=20
)
```

At this point:

```
Student object
      ↓
Python memory
```

It hasn't been permanently saved yet.

---

### Step 2: Add it to the session

```
db.session.add(student)
```

Now SQLAlchemy knows:

> This object should be inserted into the database.

---

### Step 3: Commit

```
db.session.commit()
```

Now SQLAlchemy sends the required database operation.

Conceptually:

```
Student(...)
    ↓
session.add()
    ↓
session
    ↓
commit()
    ↓
MySQL
    ↓
students table
```

---

# 5.5 Create Multiple Records

You can add multiple objects.

```
student1 = Student(
    name="Rahul",
    email="rahul@example.com",
    age=20
)

student2 = Student(
    name="Priya",
    email="priya@example.com",
    age=21
)

db.session.add_all([
    student1,
    student2
])

db.session.commit()
```

Use:

```
db.session.add()
```

for one object.

Use:

```
db.session.add_all()
```

for multiple objects.

# 5.6 READ

Read means retrieving existing data.

There are several common ways to read data.

---

## Get All Records

```
students = Student.query.all()
```

This retrieves all students.

You can loop through them:

```
students = Student.query.all()

for student in students:
    print(student.name)
```

Output:

```
Rahul
Priya
Amit
```

Conceptually:

```
SELECT * FROM students;
```

---

# 5.7 Get One Record by Primary Key

Suppose you want student ID `1`.

Modern SQLAlchemy style:

```
student = db.session.get(Student, 1)
```

If the student exists:

```
print(student.name)
```

might output:

```
Rahul
```

If no student with ID `1` exists:

```
student
```

will be:

```
None
```

So you should often check:

```
student = db.session.get(Student, 1)

if student is None:
    print("Student not found")
else:
    print(student.name)
```

---

# 5.8 Filtering Records

Suppose you want students whose age is `20`.

```
students = Student.query.filter_by(
    age=20
).all()
```

You can loop through them:

```
for student in students:
    print(student.name)
```

Conceptually:

```
SELECT *
FROM students
WHERE age = 20;
```

---

# 5.9 `filter_by()`

`filter_by()` is useful for simple equality conditions.

Example:

```
Student.query.filter_by(
    name="Rahul"
).all()
```

Another example:

```
Student.query.filter_by(
    age=20
).all()
```

Multiple conditions:

```
Student.query.filter_by(
    age=20,
    name="Rahul"
).all()
```

Conceptually:

```
WHERE age = 20
AND name = 'Rahul'
```

---

# 5.10 `filter()`

`filter()` is useful for more complex conditions.

For example:

```
students = Student.query.filter(
    Student.age > 18
).all()
```

Conceptually:

```
SELECT *
FROM students
WHERE age > 18;
```

Other examples:

```
Student.query.filter(Student.age >= 20).all()
```

```
Student.query.filter(Student.age < 25).all()
```

```
Student.query.filter(Student.age != 20).all()
```

---

# 5.11 Combining Conditions

You can combine conditions using SQLAlchemy expressions.

For example:

```
from sqlalchemy import and_

students = Student.query.filter(
    and_(
        Student.age >= 18,
        Student.age <= 25
    )
).all()
```

Conceptually:

```
WHERE age >= 18
AND age <= 25
```

You can also use:

```
students = Student.query.filter(
    Student.age >= 18,
    Student.age <= 25
).all()
```

For OR conditions:

```
from sqlalchemy import or_

students = Student.query.filter(
    or_(
        Student.age == 18,
        Student.age == 20
    )
).all()
```

Conceptually:

```
WHERE age = 18
OR age = 20
```

---

# 5.12 `first()`

Sometimes you don't need a list. You only need the first matching record.

```
student = Student.query.filter_by(
    name="Rahul"
).first()
```

If found:

```
student.name
```

If nothing matches:

```
student is None
```

This is useful when you expect zero or one result.

# 5.13 `count()`

You can count records:

```
count = Student.query.count()
```

For example:

```
print(count)
```

might output:

```
25
```

Conceptually:

```

```

You can also count filtered results:

```
count = Student.query.filter_by(
```

# 5.14 Ordering Results

You can sort the results.

Ascending:

```
students = Student.query.order_by(
    Student.name.asc()

```

Descending:

```
students = Student.query.order_by(
    Student.name.desc()
).all()
```

For age:

```
students = Student.query.order_by(
    Student.age.desc()
).all()
```

Conceptually:

```
ORDER BY age DESC;
```

# 5.15 Limiting Results

You can limit how many records are returned:

```
students = Student.query.limit(5).all()
```

Conceptually:

```
SELECT *
FROM students
LIMIT 5;
```

You can combine ordering and limiting:

```
students = Student.query.order_by(
    Student.id.desc()
).limit(5).all()
```

This can be useful for things like:

```
Latest 5 students
Top 5 records
First 10 records
```

# 5.16 UPDATE

Update means modifying existing data.

Suppose:

```
id | name  | age
---+-------+----
1  | Rahul | 20
```

We want to change the age to `21`.

First, get the object:

```
student = db.session.get(Student, 1)
```

Then change its attribute:

```
student.age = 21
```

Then commit:

```
db.session.commit()
```

Complete code:

```
student = db.session.get(Student, 1)

if student:
    student.age = 21
    db.session.commit()
```

SQLAlchemy detects the change.

Conceptually, it performs:

```
UPDATE students
SET age = 21
WHERE id = 1;
```

---

# 5.17 Updating Multiple Fields

You can change multiple attributes:

```
student = db.session.get(Student, 1)

if student:
    student.name = "Rahul Kumar"
    student.age = 21
    student.email = "rahulk@example.com"

    db.session.commit()
```

You don't need separate commits:

```
# Don't do this unnecessarily

student.name = "Rahul"
db.session.commit()

student.age = 21
db.session.commit()
```

Prefer:

```
student.name = "Rahul"
student.age = 21

db.session.commit()
```

One logical operation, one commit.

---

# 5.18 DELETE

Delete means removing a record.

First, find the object:

```
student = db.session.get(Student, 1)
```

Then:

```
db.session.delete(student)
```

Finally:

```
db.session.commit()
```

Complete example:

```
student = db.session.get(Student, 1)

if student:
    db.session.delete(student)
    db.session.commit()
```

Conceptually:

```
DELETE FROM students
WHERE id = 1;
```

# 5.21 CRUD with Flask Routes

Now let's connect CRUD to Flask.

Suppose we want an API for students.

Basic application:

```
from flask import Flask, jsonify, request
from flask_sqlalchemy import SQLAlchemy

app = Flask(__name__)

app.config["SQLALCHEMY_DATABASE_URI"] = (
    "mysql+pymysql://root:password@localhost/school"
)

db = SQLAlchemy(app)


class Student(db.Model):
    __tablename__ = "students"

    id = db.Column(
        db.Integer,
        primary_key=True
    )

    name = db.Column(
        db.String(100),
        nullable=False
    )

    email = db.Column(
        db.String(120),
        unique=True,
        nullable=False
    )

    age = db.Column(
        db.Integer
    )


with app.app_context():
    db.create_all()
```

Now let's create routes.

---

# 5.22 CREATE API

```
@app.route("/students", methods=["POST"])
def create_student():

    data = request.get_json()

    student = Student(
        name=data["name"],
        email=data["email"],
        age=data["age"]
    )

    db.session.add(student)
    db.session.commit()

    return jsonify({
        "message": "Student created",
        "id": student.id
    }), 201
```

A client could send:

```
{
    "name": "Rahul",
    "email": "rahul@example.com",
    "age": 20
}
```

The flow becomes:

```
POST /students
      ↓
request.get_json()
      ↓
Student(...)
      ↓
db.session.add()
      ↓
db.session.commit()
      ↓
MySQL
```

---

# 5.28 Important: Validate Before Creating

Don't blindly trust request data.

Instead of:

```
data = request.get_json()

student = Student(
    name=data["name"],
    email=data["email"],
    age=data["age"]
)
```

you should eventually validate:

```
data = request.get_json()

if not data.get("name"):
    return jsonify({
        "error": "Name is required"
    }), 400
```

Similarly, validate:

- Email
- Age
- Required fields
- Data types
- Allowed values
- Duplicate data

Proper validation becomes increasingly important when building real APIs.

# 5.29 Handling Database Errors

Suppose `email` is unique:

```
email = db.Column(
    db.String(120),
    unique=True,
    nullable=False
)
```

If you try to insert the same email twice, the database can raise an integrity error.

You can handle it:

```
from sqlalchemy.exc import IntegrityError
```

Then:

```
try:
    db.session.add(student)
    db.session.commit()

except IntegrityError:
    db.session.rollback()

    return jsonify({
        "error": "Email already exists"
    }), 400
```

Notice the important part:

```
db.session.rollback()
```

After a database error, the session may need to be rolled back before you continue using it.

We'll study transactions and rollback more deeply later.

---

# 5.30 Why `rollback()` Matters

Suppose:

```
try:
    db.session.add(student)
    db.session.commit()

except Exception:
    db.session.rollback()
```

The rollback resets the current transaction's pending database changes.

Think:

```
Changes
   ↓
Session
   ↓
Error
   ↓
rollback()
   ↓
Undo pending transaction changes
```

Without proper rollback handling, the session can remain in a failed state.

# 5.31 Common CRUD Mistakes

### Mistake 1: Forgetting `commit()`

```
db.session.add(student)
```

This alone doesn't mean the data has been permanently saved.

Usually you need:

```
db.session.commit()
```

---

### Mistake 2: Updating without getting the object

You need an object to modify:

```
student = db.session.get(Student, 1)

student.age = 21

db.session.commit()
```

---

### Mistake 3: Deleting without checking

Avoid blindly doing:

```
student = db.session.get(Student, 100)

db.session.delete(student)
```

Instead:

```
student = db.session.get(Student, 100)

if student is None:
    # Handle not found
    ...
else:
    db.session.delete(student)
    db.session.commit()
```

---

### Mistake 4: Not rolling back after an error

Bad:

```
try:
    db.session.commit()
except Exception:
    print("Error")
```

Better:

```
try:
    db.session.commit()
except Exception:
    db.session.rollback()
```

---

### Mistake 5: Loading unnecessary data

Don't always do:

```
Student.query.all()
```

if you only need one record.

Use:

```
db.session.get(Student, id)
```

when you know the primary key.

# 5.32 CRUD and HTTP Methods

CRUD operations commonly map to HTTP methods:

|CRUD|HTTP Method|Example|
|---|---|---|
|Create|`POST`|`POST /students`|
|Read|`GET`|`GET /students`|
|Update|`PUT` / `PATCH`|`PUT /students/1`|
|Delete|`DELETE`|`DELETE /students/1`|

Mental model:

```
POST    → Create
GET     → Read
PUT     → Update
PATCH   → Partial Update
DELETE  → Delete
```

`PUT` and `PATCH` are slightly different. In general:

- `PUT` is commonly used for replacing/updating a resource representation.
- `PATCH` is commonly used for partial modification.

---

# 5.33 CRUD and SQL Comparison

|CRUD|SQL|SQLAlchemy ORM|
|---|---|---|
|Create|`INSERT`|`session.add()`|
|Read|`SELECT`|`query` / `session.get()`|
|Update|`UPDATE`|Change attributes + `commit()`|
|Delete|`DELETE`|`session.delete()`|

This is an excellent revision table.

```
                  Flask API
                     │
          ┌──────────┼──────────┐
          ↓          ↓          ↓
        POST         GET       DELETE
          │          │          │
          └──────────┼──────────┘
                     ↓
                SQLAlchemy
                     │
```

The key idea is:

> **The model describes the data, while the session performs the database operations.**
