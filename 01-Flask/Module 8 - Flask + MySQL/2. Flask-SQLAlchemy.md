**Flask-SQLAlchemy** is a Flask extension that makes it easier to use **SQLAlchemy** inside a Flask application.

In simple words:

> **Flask-SQLAlchemy connects Flask with SQLAlchemy and provides Flask-friendly tools for working with databases.**

---

## 1. First, What Is SQLAlchemy?

Before understanding Flask-SQLAlchemy, remember the difference:

### MySQL

MySQL is the **database system**.

```
MySQL
 ↓
Stores data
```

### SQLAlchemy

SQLAlchemy is a **Python library** that allows Python applications to communicate with databases.

```
Python
 ↓
SQLAlchemy
 ↓
Database
```

### Flask-SQLAlchemy

Flask-SQLAlchemy integrates SQLAlchemy with Flask.

```
Flask
  ↓
Flask-SQLAlchemy
  ↓
SQLAlchemy
  ↓
MySQL
```

So Flask-SQLAlchemy is not another database.

---

# 2. Why Do We Need Flask-SQLAlchemy?

You could use SQLAlchemy directly in a Flask application.

But Flask-SQLAlchemy provides convenient integration with Flask, including configuration and Flask application context handling.

Without it:

```
Flask
   ↓
SQLAlchemy
   ↓
MySQL
```

With Flask-SQLAlchemy:

```
Flask
   ↓
Flask-SQLAlchemy
   ↓
SQLAlchemy
   ↓
MySQL
```

It makes the setup more natural for Flask applications.

---

# 3. Installing Flask-SQLAlchemy

Install it using:

```
pip install flask-sqlalchemy
```

If you are connecting to MySQL using PyMySQL, install that too:

```
pip install pymysql
```

So you can install both:

```
pip install flask-sqlalchemy pymysql
```

---

# 4. Import Flask-SQLAlchemy

Use:

```
from flask_sqlalchemy import SQLAlchemy
```

Then create a SQLAlchemy object:

```
db = SQLAlchemy()
```

So:

```
from flask import Flask
from flask_sqlalchemy import SQLAlchemy

app = Flask(__name__)

db = SQLAlchemy()
```

At this point, `db` is a SQLAlchemy extension object.

---

# 5. Connecting It to Flask

There are two common ways to initialize it.

### Method 1: Pass the Flask app directly

```
db = SQLAlchemy(app)
```

### Method 2: Initialize separately

```
db = SQLAlchemy()

db.init_app(app)
```

The second approach is especially useful when building larger Flask applications.

For learning, both are important to recognize.

---

# 6. Database Configuration

Before SQLAlchemy can work with MySQL, Flask needs to know the database connection information.

We use:

```
app.config["SQLALCHEMY_DATABASE_URI"]
```

Example:

```
app.config["SQLALCHEMY_DATABASE_URI"] = \
    "mysql+pymysql://root:password@localhost/school"
```

Then:

```
db = SQLAlchemy(app)
```

So the basic setup becomes:

```
from flask import Flask
from flask_sqlalchemy import SQLAlchemy

app = Flask(__name__)

app.config["SQLALCHEMY_DATABASE_URI"] = \
    "mysql+pymysql://root:password@localhost/school"

db = SQLAlchemy(app)
```

---

# 7. Understanding the `db` Object

This line:

```
db = SQLAlchemy(app)
```

creates the object that you'll use throughout your Flask application.

The `db` object provides access to SQLAlchemy functionality.

For example, later you'll use:

```
db.Model
```

to create models.

You'll also use:

```
db.session
```

to add, update, delete, and commit database records.

So you can think of:

```
db
│
├── db.Model
│
├── db.session
│
└── other SQLAlchemy functionality
```

---

# 8. What Is `db.Model`?

This is one of the most important things in Flask-SQLAlchemy.

Suppose you want a database table called `students`.

Instead of manually writing:

```
CREATE TABLE students (...);
```

you can define a Python class:

```
class Student(db.Model):
    ...
```

Here:

```
db.Model
```

is the base class for your database models.

We'll study **Models** in the next topic.

For now, remember:

```
Python Class
     ↓
db.Model
     ↓
Database Table
```

---

# 9. What Is `db.session`?

`db.session` is used to manage database operations within SQLAlchemy.

For example:

```
db.session.add(student)
```

means:

> Add this object to the current database session.

Then:

```
db.session.commit()
```

means:

> Commit the pending changes to the database.

So:

```
db.session
   ↓
Manage database changes
```

---

# 10. Understanding Session

Don't confuse:

```
Database connection
```

with:

```
SQLAlchemy session
```

They're related, but they're not the same thing.

A simplified picture is:

```
Flask
 ↓
SQLAlchemy
 ↓
Session
 ↓
Engine / Connection Pool
 ↓
MySQL
```

The **session** is primarily an ORM-level unit of work.

The **engine** manages communication with the database and connection pooling.

We'll gradually separate these concepts as the module progresses.

# 11. A Simple Example

Let's create a very small Flask-SQLAlchemy application:

```
from flask import Flask
from flask_sqlalchemy import SQLAlchemy

app = Flask(__name__)

app.config["SQLALCHEMY_DATABASE_URI"] = \
    "mysql+pymysql://root:password@localhost/school"

db = SQLAlchemy(app)


@app.route("/")
def home():
    return "Flask-SQLAlchemy is working"


if __name__ == "__main__":
    app.run(debug=True)
```

The architecture is:

```
Browser
   ↓
Flask
   ↓
Flask-SQLAlchemy
   ↓
SQLAlchemy
   ↓
PyMySQL
   ↓
MySQL
```

# 12. What Is SQLAlchemy ORM?

Flask-SQLAlchemy is commonly used with SQLAlchemy's **ORM**.

ORM means:

> **Object-Relational Mapping**

It allows you to work with database records through Python objects and classes.

For example:

```
class Student(db.Model):
    ...
```

can represent:

```
students table
```

And:

```
student = Student(...)
```

can represent:

```
one row in the students table
```

Conceptually:

```
Python                     Database

Student class      →      students table

Student object     →      one row

Class attribute    →      column
```

This is the central idea we'll explore in the next topics.

---

# 13. SQL vs SQLAlchemy

Suppose you want to retrieve students.

With raw SQL:

```
SELECT * FROM students;
```

With SQLAlchemy ORM, you'll eventually write something conceptually like:

```
students = db.session.execute(...)
```

or use SQLAlchemy's ORM querying APIs.

The important point is that **SQLAlchemy still communicates with the database using SQL underneath**.

It doesn't replace SQL itself.

Think:

```
You write Python
      ↓
SQLAlchemy translates/builds database operations
      ↓
SQL
      ↓
MySQL
```

---

# 14. Does SQLAlchemy Mean We Never Write SQL?

No.

That's a common misunderstanding.

SQLAlchemy gives you multiple levels of interaction.

### ORM

Work mainly with Python classes and objects.

```
Student(...)
```

### SQLAlchemy Core

Work with SQLAlchemy's SQL expression system.

### Raw SQL

Write SQL directly when appropriate.

```
SELECT ...
```

We'll specifically learn **Raw SQL** later in Module 8.

So:

```
SQLAlchemy
│
├── ORM
├── SQL Expression Language
└── Raw SQL
```

# 16. `SQLALCHEMY_TRACK_MODIFICATIONS`

You may see this configuration:

```
app.config["SQLALCHEMY_TRACK_MODIFICATIONS"] = False
```

For most applications, you don't need Flask-SQLAlchemy's older modification-tracking feature.

So you'll commonly see:

```
app.config["SQLALCHEMY_TRACK_MODIFICATIONS"] = False
```

This is a configuration setting, not a requirement for basic database functionality.

# 17. A More Complete Setup

A typical learning setup might look like:

```
from flask import Flask
from flask_sqlalchemy import SQLAlchemy

app = Flask(__name__)

app.config["SQLALCHEMY_DATABASE_URI"] = \
    "mysql+pymysql://root:password@localhost/school"

app.config["SQLALCHEMY_TRACK_MODIFICATIONS"] = False

db = SQLAlchemy(app)


@app.route("/")
def home():
    return "Hello Flask + MySQL"


if __name__ == "__main__":
    app.run(debug=True)
```

# 18. Application Factory Style

As Flask applications become larger, you'll often see:

```
db = SQLAlchemy()
```

instead of immediately doing:

```
db = SQLAlchemy(app)
```

Then:

```
def create_app():
    app = Flask(__name__)

    app.config["SQLALCHEMY_DATABASE_URI"] = \
        "mysql+pymysql://root:password@localhost/school"

    db.init_app(app)

    return app
```

The important idea is:

```
Create extension
       ↓
Create Flask application
       ↓
Initialize extension with application
```

This pattern is called the **application factory pattern**.

You don't need to master the entire pattern yet. Just understand why you may see `db.init_app(app)` in larger projects.

---

# 19. Why This Pattern Is Useful

Imagine a large application:

```
Flask App
│
├── Authentication
├── Users
├── Products
├── Orders
├── Payments
└── Reports
```

Using:

```
db = SQLAlchemy()
```

allows the database extension to exist independently of a specific Flask application until initialization.

Then:

```
db.init_app(app)
```

connects it to the application.

This makes larger projects easier to structure and test.

---

# 20. Flask-SQLAlchemy vs SQLAlchemy

This distinction is important.

|SQLAlchemy|Flask-SQLAlchemy|
|---|---|
|General Python library|Flask extension|
|Works independently of Flask|Designed to integrate with Flask|
|Provides ORM and SQL tools|Adds Flask-specific integration|
|Can be used with many frameworks|Specifically designed for Flask applications|

Think:

```
SQLAlchemy
    ↓
Core database library

Flask-SQLAlchemy
    ↓
Flask integration layer
```

# 22. Why We Are Learning This Before Models

Our learning path is intentional.

First:

```
Database Connection
```

You learned how Flask reaches MySQL.

Now:

```
Flask-SQLAlchemy
```

You learned the Flask integration layer.

Next:

```
Models
```

You'll learn how to represent database tables as Python classes.

Then:

```
ORM Basics
```

You'll learn how those classes and objects interact with database records.

Then:

```
CRUD
```

You'll actually start creating, reading, updating, and deleting database records using SQLAlchemy.

So the progression is:

```
Connection
   ↓
Flask-SQLAlchemy
   ↓
Models
   ↓
ORM
   ↓
CRUD
```

That's much easier to understand than jumping directly into complicated queries.
