# What is `jsonify()`?

> **Definition:**
> 
> `jsonify()` converts Python objects (usually dictionaries or lists) into a proper JSON HTTP response.

Simply put:

```
Python Dictionary
        │
        ▼
jsonify()
        │
        ▼
JSON Response
```

---

# Why Do We Need `jsonify()`?

Suppose you write:

```
student = {
    "name": "John",
    "age": 20
}
```

This is a **Python dictionary**.

But browsers, mobile apps, and APIs understand **JSON**, not Python dictionaries.

So Flask needs to convert:

```
{
    "name": "John",
    "age": 20
}
```

into

```
{
    "name": "John",
    "age": 20
}
```

and send it with the correct HTTP headers.

That's the job of `jsonify()`.

---

# Basic Syntax

```
from flask import jsonify

@app.route("/student")
def student():

    return jsonify({
        "name": "John",
        "age": 20
    })
```

Response:

```
{
    "name": "John",
    "age": 20
}
```

# Returning a Status Code

`jsonify()` can be combined with a status code.

```
@app.route("/create")
def create():

    return jsonify({
        "message": "User Created"
    }), 201
```

Response:

```
Status: 201 Created
```

Body:

```
{
    "message": "User Created"
}
```

# Returning JSON with Headers

```
from flask import make_response, jsonify

@app.route("/")
def home():

    response = make_response(
        jsonify({
            "message": "Hello"
        })
    )

    response.headers["Version"] = "1.0"

    return response
```

Now the response contains:

- JSON body
- Custom header

# `jsonify()` vs `str()`

Wrong:

```
@app.route("/")
def home():

    data = {
        "name": "John"
    }

    return str(data)
```

Output:

```
{'name': 'John'}
```

Problems:

- Uses single quotes (`'`)
- Sent as plain text
- Not valid JSON

---

Correct:

```
return jsonify(data)
```

Output:

```
{
    "name": "John"
}
```

Flask also sets:

```
Content-Type:
application/json
```

---

# `jsonify()` vs Returning a Dictionary

In **modern Flask versions**, this works:

```
@app.route("/")
def home():

    return {
        "message": "Hello"
    }
```

Flask automatically converts it to JSON.

However, for learning and readability, many developers still prefer:

```
return jsonify({
    "message": "Hello"
})
```

because:

- It's explicit.
- It works consistently across Flask versions.
- Anyone reading the code immediately knows a JSON response is being returned.

---

# Real API Example

```
from flask import Flask, jsonify

app = Flask(__name__)

@app.route("/product")
def product():

    return jsonify({
        "id": 101,
        "name": "Laptop",
        "price": 65000,
        "available": True
    })

app.run(debug=True)
```

Response:

```
{
    "id": 101,
    "name": "Laptop",
    "price": 65000,
    "available": true
}
```

Notice:

Python:

```
True
```

JSON:

```
true
```

Flask automatically converts Python types into valid JSON.

# Request vs Response

A very common interview question.

|Request|Response|
|---|---|
|`request.get_json()`|`jsonify()`|
|Receives JSON|Sends JSON|
|Client → Server|Server → Client|

Think of them as opposites.

```
Client
   │
   │ JSON
   ▼
request.get_json()

Flask processes data

jsonify()

   ▼
Client receives JSON
```

---

# Common Mistakes

### ❌ Returning `str(dictionary)`

Wrong:

```
return str(data)
```

Correct:

```
return jsonify(data)
```

---

### ❌ Confusing `request.get_json()` and `jsonify()`

Wrong:

```
request.get_json(data)
```

Correct:

```
# Receive JSON
data = request.get_json()

# Send JSON
return jsonify(data)
```

---

# Summary

|Task|Method|
|---|---|
|Receive JSON|`request.get_json()`|
|Send JSON|`jsonify()`|

# Interview Question

**Q: What is `jsonify()` in Flask?**

**Answer:**

> `jsonify()` is a Flask helper function that converts Python objects such as dictionaries and lists into a valid JSON HTTP response while automatically setting the `Content-Type` header to `application/json`.
