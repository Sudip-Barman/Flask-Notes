A **Primary Key** is a column, or combination of columns, that **uniquely identifies each row in a table**.

In simple words:

> **Primary Key = unique identity of each record.**

For example, in a `students` table:

```
students

┌────┬─────────┬─────┐
│ id │ name    │ age │
├────┼─────────┼─────┤
│ 1  │ Alice   │ 20  │
│ 2  │ Bob     │ 21  │
│ 3  │ Charlie │ 19  │
└────┴─────────┴─────┘
```

Here, `id` can be the Primary Key.

```
id
↓
Primary Key
↓
Uniquely identifies each student
```

---

# 1. Why Do We Need a Primary Key?

Imagine two students have the same name:

```
Alice
Alice
```

If we search using only the name, we can't reliably know which Alice we're talking about.

But if each student has a unique ID:

```
id | name
---+-------
1  | Alice
2  | Alice
```

we can distinguish them:

```
Student 1 → Alice
Student 2 → Alice
```

The `id` gives each row its own identity.

---

# 2. Rules of a Primary Key

A primary key has two fundamental properties:

### 1. Must be unique

You cannot have:

```
id
──
1
2
1 ❌
```

Two rows cannot have the same primary key value.

### 2. Cannot be NULL

You cannot have:

```
id
──
1
2
NULL ❌
```

Every row must have a primary key value.

So remember:

```
PRIMARY KEY
     │
     ├── UNIQUE
     │
     └── NOT NULL
```

---

# 3. Creating a Primary Key

You can define it when creating a table:

```
CREATE TABLE students (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    age INT
);
```

Here:

```
id INT PRIMARY KEY
       ↑
   Primary Key
```

---

# 4. Inserting Data

For example:

```
INSERT INTO students (id, name, age)
VALUES (1, 'Alice', 20);
```

Then:

```
INSERT INTO students (id, name, age)
VALUES (2, 'Bob', 21);
```

The table becomes:

```
┌────┬───────┬─────┐
│ id │ name  │ age │
├────┼───────┼─────┤
│ 1  │ Alice │ 20  │
│ 2  │ Bob   │ 21  │
└────┴───────┴─────┘
```

---

# 5. What Happens With Duplicate IDs?

Suppose we already have:

```
id = 1
```

and try:

```
INSERT INTO students (id, name, age)
VALUES (1, 'Charlie', 19);
```

MySQL rejects it because:

```
1 already exists
```

The database protects the uniqueness of the primary key.

---

# 6. Primary Key with AUTO_INCREMENT

In real applications, IDs are often automatically generated.

```
CREATE TABLE students (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100),
    age INT
);
```

Now we don't need to manually provide the ID.

We can write:

```
INSERT INTO students (name, age)
VALUES ('Alice', 20);
```

MySQL generates:

```
id = 1
```

Next:

```
INSERT INTO students (name, age)
VALUES ('Bob', 21);
```

MySQL generates:

```
id = 2
```

So:

```
Alice → 1
Bob   → 2
Charlie → 3
```

This is a very common pattern.

---

# 7. Why AUTO_INCREMENT Is Useful

Without `AUTO_INCREMENT`, you have to manage IDs yourself:

```
INSERT INTO students VALUES (1, 'Alice', 20);
INSERT INTO students VALUES (2, 'Bob', 21);
INSERT INTO students VALUES (3, 'Charlie', 19);
```

With `AUTO_INCREMENT`:

```
INSERT INTO students (name, age)
VALUES ('Alice', 20);

INSERT INTO students (name, age)
VALUES ('Bob', 21);

INSERT INTO students (name, age)
VALUES ('Charlie', 19);
```

MySQL handles the IDs.

# 8. Primary Key and Foreign Key

These two are closely related.

Suppose we have:

```
users
────────────
id ← Primary Key
name
```

and:

```
orders
────────────
id
user_id ← Foreign Key
```

The relationship is:

```
users.id
   ▲
   │
   │
orders.user_id
```

More conceptually:

```
┌─────────┐                 ┌─────────┐
│  USERS  │                 │ ORDERS  │
├─────────┤                 ├─────────┤
│ PK id   │◄───────────────┐│ id      │
│ name    │                └│ FK user_id
└─────────┘                 └─────────┘
```

The primary key identifies the user.

The foreign key references that user.

---

# 9. Primary Key vs Foreign Key

This distinction is extremely important.

### Primary Key

Identifies a record **inside its own table**.

```
users

id ← PRIMARY KEY
```

### Foreign Key

References a record **in another table**.

```
orders

user_id ← FOREIGN KEY
```

Think:

```
PRIMARY KEY
↓
"This is who I am."

FOREIGN KEY
↓
"This is who I'm connected to."
```

---

# 10. Can a Table Have Multiple Primary Keys?

A table can have **only one primary key constraint**.

But that primary key can contain **multiple columns**.

This is called a **composite primary key**.

For example:

```
student_courses

student_id | course_id
-----------+----------
1          | 10
1          | 20
2          | 10
```

We might define:

```
CREATE TABLE student_courses (
    student_id INT,
    course_id INT,
    PRIMARY KEY (student_id, course_id)
);
```

Here the primary key consists of:

```
student_id + course_id
```

The **combination** must be unique.

---

# 11. Understanding Composite Keys

Consider:

```
student_id | course_id
-----------+----------
1          | 10
1          | 20
2          | 10
```

Notice:

```
student_id = 1
```

appears more than once.

And:

```
course_id = 10
```

also appears more than once.

That's okay.

But this combination:

```
1 + 10
```

cannot appear twice.

So this would be invalid:

```
student_id | course_id
-----------+----------
1          | 10
1          | 10  ❌
```

because the combined primary key is duplicated.

---

# 12. Choosing a Good Primary Key

A good primary key should generally be:

### Unique

Every record gets a different value.

### Stable

It shouldn't normally change.

### Simple

An integer ID is often convenient.

For example:

```
1
2
3
4
5
```

is a common choice.

---

# 13. Why Not Use Name as Primary Key?

You might think:

```
name VARCHAR(100) PRIMARY KEY
```

But this is usually a bad idea.

Why?

Because names aren't necessarily unique:

```
Alice
Alice
John
John
```

Also, names can change.

For example:

```
John Smith
```

could become:

```
John Brown
```

An internal ID is generally more stable:

```
id = 42
```

while the person's name can change.

---

# 14. Can Email Be a Primary Key?

Technically, yes, if designed appropriately:

```
email VARCHAR(255) PRIMARY KEY
```

because emails can be unique.

But in many application designs, it's more convenient to use:

```
id → PRIMARY KEY
email → UNIQUE
```

For example:

```
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    email VARCHAR(255) UNIQUE
);
```

This gives us:

```
id
↓
main identity

email
↓
must be unique
```

---

# 15. Defining Primary Key After Creating the Table

You can also add a primary key later.

Suppose:

```
CREATE TABLE students (
    id INT,
    name VARCHAR(100)
);
```

Later:

```
ALTER TABLE students
ADD PRIMARY KEY (id);
```

Now `id` becomes the primary key.

Of course, the existing data must satisfy the primary-key rules.

---

# 16. Checking the Primary Key

You can use:

```
DESCRIBE students;
```

You may see:

```
Field   Type          Key
-------------------------
id      int           PRI
name    varchar(100)
age     int
```

`PRI` indicates that the column is part of the primary key.

# 18. Primary Key in a Real Database Design

Suppose we have:

```
users
```

```
┌──────────────────────────┐
│ USERS                    │
├──────────────────────────┤
│ PK id                    │
│ username                 │
│ email                    │
│ created_at               │
└──────────────────────────┘
```

Then:

```
posts
```

```
┌──────────────────────────┐
│ POSTS                    │
├──────────────────────────┤
│ PK id                    │
│ FK user_id               │
│ title                    │
│ content                  │
└──────────────────────────┘
```

The relationship is:

```
USERS
  │
  │ 1
  │
  │ N
  ▼
POSTS
```

Here:

```
users.id
   ↓
Primary Key

posts.user_id
   ↓
Foreign Key
```

This is one of the most important patterns you'll encounter when working with relational databases.

---

# 19. Primary Key vs UNIQUE

This is another common confusion.

Both can prevent duplicates.

But:

```
PRIMARY KEY
```

is the **main identifier** for the table.

While:

```
UNIQUE
```

simply enforces uniqueness on a column or set of columns.

Example:

```
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50) UNIQUE,
    email VARCHAR(255) UNIQUE
);
```

Here:

```
id
→ Primary Key

username
→ Unique

email
→ Unique
```

The table has one primary key constraint but can have multiple unique constraints.

# Quick Summary

### Primary Key

> A column or combination of columns that uniquely identifies each row.

### Rules

```
PRIMARY KEY
     │
     ├── Must be UNIQUE
     └── Cannot be NULL
```

### Common example

```
CREATE TABLE students (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100),
    age INT
);
```

### Composite Primary Key

```
PRIMARY KEY (student_id, course_id)
```

Uses multiple columns together as the unique identifier.

### Remember

```
Primary Key
     ↓
"Who is this record?"
```
