A **data type** tells MySQL **what kind of data a column can store**.

For example:

```
name → text
age  → whole number
price → decimal number
created_at → date and time
```

When creating a table, each column needs an appropriate data type.

```
CREATE TABLE students (
    id INT,
    name VARCHAR(100),
    age INT
);
```

Here:

```
Column       Data Type
-----------------------
id           INT
name         VARCHAR(100)
age          INT
```

---

# 1. Why Are Data Types Important?

Imagine a column called `age`.

It should store values like:

```
18
20
25
```

So we use a numeric data type:

```
age INT
```

But if we tried to store a name:

```
Alice
Bob
Charlie
```

we need a text data type:

```
name VARCHAR(100)
```

So the basic idea is:

> **Choose the data type according to the kind of data you want to store.**

# 3. Numeric Data Types

Numeric data types store numbers.

Common types include:

```
TINYINT
SMALLINT
INT
BIGINT
DECIMAL
FLOAT
DOUBLE
```

---

## INT

`INT` stores whole numbers.

```
age INT
```

Example:

```
18
20
25
100
```

It does not store normal decimal values like:

```
19.5
```

Example table:

```
CREATE TABLE students (
    id INT,
    name VARCHAR(100),
    age INT
);
```

`INT` is one of the most commonly used data types.

---

## BIGINT

`BIGINT` is used for very large whole numbers.

```
views BIGINT
```

For example:

```
5000000000
```

Applications with extremely large IDs or counters may use `BIGINT`.

---

## TINYINT

`TINYINT` stores a small integer.

It is sometimes used for simple flags such as:

```
0 → False
1 → True
```

Example:

```
is_active TINYINT
```

Data:

```
1
0
1
```

---

# 4. Decimal Numbers

Sometimes we need numbers with decimal values.

For example:

```
99.99
150.50
12.75
```

For values where precision matters, such as money, use `DECIMAL`.

```
price DECIMAL(10, 2)
```

Let's understand:

```
DECIMAL(10, 2)
```

The first number:

```
10
```

means the total number of digits.

The second number:

```
2
```

means digits after the decimal point.

Example:

```
12345678.90
```

So:

```
DECIMAL(10, 2)
```

is commonly used for prices.

Example:

```
price DECIMAL(10, 2)
```

Data:

```
99.99
250.50
1000.00
```

---

# 5. FLOAT and DOUBLE

`FLOAT` and `DOUBLE` store approximate decimal numbers.

Example:

```
temperature FLOAT
```

Possible data:

```
25.5
30.75
18.2
```

However, for money:

```
❌ FLOAT
❌ DOUBLE
```

Prefer:

```
✅ DECIMAL
```

Because money calculations usually require exact precision.

---

# 6. String Data Types

String data types store text.

The most common ones are:

```
CHAR
VARCHAR
TEXT
```

---

# 7. VARCHAR

`VARCHAR` stores variable-length text.

Example:

```
name VARCHAR(100)
```

This means the column can store text up to the specified length.

Examples:

```
Alice
Bob
Charlie
```

Other examples:

```
email VARCHAR(255)
username VARCHAR(50)
```

`VARCHAR` is one of the most commonly used text data types.

---

# 8. CHAR

`CHAR` stores fixed-length text.

For example:

```
country_code CHAR(2)
```

Values:

```
IN
US
JP
```

Another example:

```
status CHAR(1)
```

Possible values:

```
Y
N
```

A simple rule:

```
Fixed-length value
        ↓
       CHAR

Variable-length text
        ↓
      VARCHAR
```

---

# 9. TEXT

`TEXT` is used for larger amounts of text.

For example:

```
description TEXT
```

It could store:

```
A short paragraph...

A long article...

Multiple paragraphs of text...
```

Example:

```
CREATE TABLE posts (
    id INT,
    title VARCHAR(200),
    content TEXT
);
```

Here:

```
title
↓
VARCHAR

content
↓
TEXT
```

Because a post title is usually short, while the content can be much larger.

---

# 10. Date Data Types

MySQL provides special types for dates and times.

Common ones:

```
DATE
TIME
DATETIME
TIMESTAMP
YEAR
```

---

## DATE

Stores only a date.

```
birth_date DATE
```

Example:

```
2004-08-15
```

Format:

```
YYYY-MM-DD
```

---

## TIME

Stores only time.

```
start_time TIME
```

Example:

```
14:30:00
```

Format:

```
HH:MM:SS
```

---

## DATETIME

Stores both date and time.

```
created_at DATETIME
```

Example:

```
2026-09-01 14:30:00
```

Useful for:

```
Account creation
Order creation
Blog publishing
Event scheduling
```

---

## TIMESTAMP

`TIMESTAMP` also stores date and time.

Example:

```
created_at TIMESTAMP
```

A common use is automatically storing when a record was created:

```
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
```

Now when a new row is inserted, MySQL can automatically store the current date and time.

---

# 11. DATETIME vs TIMESTAMP

Both store:

```
Date + Time
```

For basic learning, you can think:

```
DATETIME
→ Date and time value

TIMESTAMP
→ Date and time, often useful for automatically tracking events
```

Example:

```
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
```

We'll encounter these frequently in real applications.

---

# 12. Boolean Values

MySQL does not have a separate native storage type called `BOOLEAN` in the same way some databases do.

In MySQL, `BOOLEAN` is effectively treated as an alias for `TINYINT(1)`.

Common convention:

```
1 → True
0 → False
```

Example:

```
is_active BOOLEAN
```

Values:

```
1
0
```

Conceptually:

```
1 → Active
0 → Inactive
```

---

# 13. NULL and Data Types

A column can sometimes store `NULL`.

Example:

```
phone VARCHAR(20)
```

Data:

```
Alice → 9876543210
Bob   → NULL
```

This means Bob's phone number has not been provided or is unknown.

If you don't want to allow `NULL`:

```
name VARCHAR(100) NOT NULL
```

Then a value is required.

---

# 14. Example: User Table

Let's combine several data types.

```
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50),
    email VARCHAR(255),
    age INT,
    balance DECIMAL(10, 2),
    bio TEXT,
    is_active BOOLEAN,
    birth_date DATE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

Let's understand it:

|Column|Data Type|Purpose|
|---|---|---|
|`id`|`INT`|Unique ID|
|`username`|`VARCHAR(50)`|Username|
|`email`|`VARCHAR(255)`|Email address|
|`age`|`INT`|Age|
|`balance`|`DECIMAL(10,2)`|Exact decimal value|
|`bio`|`TEXT`|Longer text|
|`is_active`|`BOOLEAN`|True/False value|
|`birth_date`|`DATE`|Date of birth|
|`created_at`|`TIMESTAMP`|Record creation time|

---

# 15. Choosing the Correct Data Type

A useful guide:

|Data|Recommended Type|
|---|---|
|ID|`INT` or `BIGINT`|
|Name|`VARCHAR(100)`|
|Username|`VARCHAR(50)`|
|Email|`VARCHAR(255)`|
|Password hash|`VARCHAR(255)`|
|Age|`INT`|
|Price|`DECIMAL(10,2)`|
|Description|`TEXT`|
|True/False|`BOOLEAN` / `TINYINT`|
|Date of birth|`DATE`|
|Date + time|`DATETIME` or `TIMESTAMP`|

# 16. A Common Beginner Mistake

A beginner might use:

```
age VARCHAR(10)
```

This stores the age as text.

Then:

```
"20"
"25"
"30"
```

But age is actually numerical data.

Better:

```
age INT
```

Similarly:

```
Price
```

should usually not be:

```
price VARCHAR(20)
```

because it represents a number.

Instead:

```
price DECIMAL(10, 2)
```

Choosing correct data types makes the database more logical and easier to work with.

# 18. Important Point: Data Type Is Not Just About Storage

A data type also tells the database **how the data should be handled**.

For example:

```
age INT
```

allows numerical operations:

```
20 + 5 = 25
```

A date:

```
birth_date DATE
```

can be used for date operations.

For example, you can compare dates.

A numeric column can also be sorted numerically.

So choosing the correct data type helps MySQL understand the meaning and behavior of your data.
