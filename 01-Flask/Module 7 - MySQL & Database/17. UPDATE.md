`UPDATE` is an SQL command used to **modify existing data in a table**.

In simple words:

> **UPDATE = Change existing data.**

It represents the **Update** part of CRUD:

```
CRUD
│
├── CREATE → INSERT
├── READ   → SELECT
├── UPDATE → UPDATE  ← We are here
└── DELETE → DELETE
```

MySQL's `UPDATE` statement modifies existing rows, and the `SET` clause specifies the new values. [MySQL Developer Zone](https://dev.mysql.com/doc/refman/8.0/en/update.html?utm_source=chatgpt.com)

---

# 1. Basic Syntax

```
UPDATE table_name
SET column_name = new_value
WHERE condition;
```

There are three important parts:

```
UPDATE
  ↓
Which table?

SET
  ↓
What should change?

WHERE
  ↓
Which row(s) should change?
```

For example:

```
UPDATE students
SET age = 21
WHERE id = 1;
```

This means:

> In the `students` table, change the `age` to `21` for the student whose `id` is `1`.

---

# 2. Example Table

Let's use:

```
students

┌────┬─────────┬─────┬────────────┐
│ id │ name    │ age │ city       │
├────┼─────────┼─────┼────────────┤
│ 1  │ Alice   │ 20  │ Kolkata    │
│ 2  │ Bob     │ 21  │ Delhi      │
│ 3  │ Charlie │ 19  │ Mumbai     │
│ 4  │ David   │ 22  │ Kolkata    │
└────┴─────────┴─────┴────────────┘
```

Suppose Alice is now 21.

We write:

```
UPDATE students
SET age = 21
WHERE id = 1;
```

Before:

```
1 | Alice | 20 | Kolkata
```

After:

```
1 | Alice | 21 | Kolkata
```

Only Alice's row changes.

---

# 3. `SET` Means "Change This"

Look at:

```
SET age = 21
```

This doesn't mean:

> "Create an age."

It means:

> **Change the existing `age` value to `21`.**

For example:

```
UPDATE students
SET city = 'Delhi'
WHERE id = 3;
```

Changes:

```
Mumbai
```

to:

```
Delhi
```

---

# 4. Updating Multiple Columns

You can change multiple columns in one `UPDATE`.

```
UPDATE students
SET
    name = 'Robert',
    age = 22,
    city = 'Delhi'
WHERE id = 2;
```

Before:

```
2 | Bob | 21 | Delhi
```

After:

```
2 | Robert | 22 | Delhi
```

Separate assignments with commas:

```
column1 = value1,
column2 = value2,
column3 = value3
```

---

# 5. `WHERE` Is Extremely Important ⚠️

This is the most important thing to understand about `UPDATE`.

Suppose you write:

```
UPDATE students
SET age = 25;
```

There is **no `WHERE`**.

That means:

> Update the age of **every row**.

MySQL documents that if an `UPDATE` has no `WHERE` clause, all rows are updated. [MySQL Developer Zone](https://dev.mysql.com/doc/refman/8.0/en/update.html?utm_source=chatgpt.com)

Before:

```
Alice   | 20
Bob     | 21
Charlie | 19
David   | 22
```

After:

```
Alice   | 25
Bob     | 25
Charlie | 25
David   | 25
```

💥 You just changed everyone's age.

So when you intend to update a specific record, normally use a `WHERE` condition.

---

# 6. Why `id` Is Commonly Used With UPDATE

Remember that `id` is usually a primary key:

```
id
↓
PRIMARY KEY
↓
Unique
```

So:

```
UPDATE students
SET age = 21
WHERE id = 1;
```

is safer because `id = 1` identifies one particular row.

Think of it like an address:

```
WHERE id = 1
      ↓
"Go to this exact row."
```

---

# 7. UPDATE Using Another Condition

You don't have to use `id`.

For example:

```
UPDATE students
SET city = 'Kolkata'
WHERE name = 'Bob';
```

This searches for rows where:

```
name = Bob
```

and changes their city.

However, if multiple students have the name `Bob`, multiple rows could be updated.

That's why a unique identifier such as a primary key is often preferable when you intend to modify exactly one record.

---

# 8. UPDATE With Multiple Conditions

You can use `AND`:

```
UPDATE students
SET city = 'Kolkata'
WHERE age = 21
AND name = 'Bob';
```

Meaning:

```
Find rows where:

age = 21
     AND
name = Bob

        ↓

Change city to Kolkata
```

---

# 9. UPDATE Using OR

You can also use `OR`:

```
UPDATE students
SET city = 'Kolkata'
WHERE name = 'Bob'
OR name = 'Charlie';
```

This can update both Bob and Charlie.

So:

```
AND → Both conditions must match
OR  → At least one condition must match
```

---

# 10. UPDATE Using a Calculation

You don't always have to provide a fixed value.

You can calculate a new value from the existing value.

For example:

```
UPDATE students
SET age = age + 1
WHERE id = 1;
```

If Alice was:

```
age = 20
```

then:

```
20 + 1 = 21
```

Now:

```
age = 21
```

MySQL supports expressions such as `column = column + 1` in `UPDATE`. [MySQL Developer Zone](https://dev.mysql.com/doc/refman/8.0/en/update.html?utm_source=chatgpt.com)

---

# 11. Increase Everyone's Age

You could write:

```
UPDATE students
SET age = age + 1;
```

Because there is no `WHERE`, every student's age increases by 1.

Before:

```
Alice   → 20
Bob     → 21
Charlie → 19
David   → 22
```

After:

```
Alice   → 21
Bob     → 22
Charlie → 20
David   → 23
```

This is a good example of when updating **all rows intentionally** can be valid.

---

# 12. UPDATE With `NULL`

You can set a column to `NULL` if that column permits it.

```
UPDATE students
SET city = NULL
WHERE id = 1;
```

Now:

```
1 | Alice | 20 | NULL
```

But if `city` was declared:

```
city VARCHAR(100) NOT NULL
```

you cannot normally set it to `NULL`.

---

# 13. UPDATE With DEFAULT

If a column has a default value, you can explicitly restore that default using:

```
UPDATE students
SET age = DEFAULT
WHERE id = 1;
```

The `UPDATE` statement supports `DEFAULT` as a value assignment. [MySQL Developer Zone](https://dev.mysql.com/doc/refman/8.0/en/update.html?utm_source=chatgpt.com)

---

# 14. UPDATE and Constraints

Remember the constraints we learned earlier?

They still apply when updating data.

For example:

```
PRIMARY KEY
UNIQUE
NOT NULL
FOREIGN KEY
```

Suppose:

```
email VARCHAR(255) UNIQUE
```

and we already have:

```
alice@example.com
```

If you try:

```
UPDATE users
SET email = 'alice@example.com'
WHERE id = 2;
```

and that email already belongs to another row, MySQL can reject the update because it would violate the `UNIQUE` constraint.

So constraints help protect the database not only during `INSERT`, but also when modifying existing data.

---

# 15. UPDATE and Foreign Keys

Suppose:

```
users

id
──
1
2
3
```

and another table has:

```
orders

user_id
───────
1
2
```

where:

```
orders.user_id
      ↓
users.id
```

If you try to change a referenced user ID in a way that violates the foreign-key relationship, MySQL may reject it depending on the foreign-key rules.

This is why relationships and constraints matter when modifying data.

# 16. UPDATE vs INSERT

This distinction is very important.

### INSERT

Adds a **new row**:

```
INSERT INTO students (name, age)
VALUES ('Alice', 20);
```

Result:

```
New row appears
       ↓
Alice | 20
```

### UPDATE

Changes an **existing row**:

```
UPDATE students
SET age = 21
WHERE id = 1;
```

Result:

```
Existing row changes
       ↓
Alice | 20
       ↓
Alice | 21
```

So:

```
INSERT
→ Add

UPDATE
→ Change
```

---

# 17. UPDATE vs SELECT

Another useful distinction:

```
SELECT
↓
Reads data
↓
Doesn't modify it
```

while:

```
UPDATE
↓
Modifies data
```

For example:

```
SELECT *
FROM students
WHERE id = 1;
```

asks:

> "Show me student 1."

Whereas:

```
UPDATE students
SET age = 21
WHERE id = 1;
```

says:

> "Change student 1's age."

---

# 18. A Safe Habit

Before running an important `UPDATE`, you can first run a `SELECT` with the **same `WHERE` condition**.

For example, suppose you want:

```
UPDATE students
SET city = 'Kolkata'
WHERE age > 20;
```

First check:

```
SELECT *
FROM students
WHERE age > 20;
```

Look at the rows returned.

If those are exactly the rows you intend to change, then run:

```
UPDATE students
SET city = 'Kolkata'
WHERE age > 20;
```

This is a very useful habit.

Think:

```
SELECT first
   ↓
Check the rows
   ↓
UPDATE
```

---

# 19. UPDATE With ORDER BY and LIMIT

MySQL also supports `ORDER BY` and `LIMIT` for single-table `UPDATE` statements. [MySQL Developer Zone](https://dev.mysql.com/doc/refman/8.0/en/update.html?utm_source=chatgpt.com)

For example:

```
UPDATE students
SET city = 'Kolkata'
ORDER BY age DESC
LIMIT 1;
```

Conceptually:

```
Sort students by age
        ↓
Take the first row
        ↓
Update that row
```

This is an advanced use. For normal updates, focus first on:

```
UPDATE
SET
WHERE
```

# 20. Complete CRUD Example

Now we can connect everything we've learned.

### Create

```
INSERT INTO students (name, age, city)
VALUES ('Alice', 20, 'Kolkata');
```

### Read

```
SELECT *
FROM students;
```

### Update

```
UPDATE students
SET age = 21
WHERE id = 1;
```

### Delete

```
DELETE FROM students
WHERE id = 1;
```

So:

```
             CRUD
              │
      ┌───────┼────────┐
      ↓       ↓        ↓
   CREATE    READ     UPDATE    DELETE
      ↓       ↓        ↓          ↓
   INSERT   SELECT   UPDATE     DELETE
```

# 21. The Mental Model

Whenever you see:

```
UPDATE students
SET age = 21
WHERE id = 1;
```

read it like a sentence:

> **UPDATE** the `students` table  
> **SET** the `age` to `21`  
> **WHERE** the `id` is `1`.

That's really all the basic `UPDATE` statement is doing.

```
UPDATE table_name

```

> **`UPDATE` modifies existing rows. It does not create new rows.**
