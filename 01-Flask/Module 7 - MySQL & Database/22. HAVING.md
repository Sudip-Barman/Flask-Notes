`HAVING` is used to **filter groups created by `GROUP BY`**.

The easiest way to remember it is:

> **WHERE filters rows. HAVING filters groups.**

This is the main purpose of `HAVING`.

---

# 1. Why Do We Need HAVING?

Let's start with a table:

```
students

┌────┬─────────┬─────────┐
│ id │ name    │ city    │
├────┼─────────┼─────────┤
│ 1  │ Alice   │ Kolkata │
│ 2  │ Bob     │ Delhi   │
│ 3  │ Charlie │ Kolkata │
│ 4  │ David   │ Mumbai  │
│ 5  │ Emma    │ Delhi   │
│ 6  │ Frank   │ Kolkata │
└────┴─────────┴─────────┘
```

We already know how to count students in each city:

```
SELECT city, COUNT(*) AS total_students
FROM students
GROUP BY city;
```

Result:

```
city       total_students
---------  --------------
Kolkata          3
Delhi            2
Mumbai           1
```

Now suppose we ask:

> "Show only cities that have **at least 2 students**."

We're no longer filtering individual students.

We're filtering the **groups**:

```
Kolkata → 3 ✓
Delhi   → 2 ✓
Mumbai  → 1 ✗
```

That's what `HAVING` is for.

```
SELECT city, COUNT(*) AS total_students
FROM students
GROUP BY city
HAVING COUNT(*) >= 2;
```

Result:

```
Kolkata → 3
Delhi   → 2
```

---

# 2. WHERE vs HAVING

This is the most important part.

### WHERE

Filters **individual rows**:

```
WHERE age >= 20
```

Meaning:

> Keep students whose age is at least 20.

### HAVING

Filters **groups**:

```
HAVING COUNT(*) >= 2
```

Meaning:

> Keep groups containing at least 2 rows.

So remember:

```
WHERE
  ↓
Filters rows

GROUP BY
  ↓
Creates groups

HAVING
  ↓
Filters groups
```

---

# 3. Why Can't We Use WHERE?

Suppose you want:

> Cities having more than 2 students.

You might try:

```
SELECT city, COUNT(*)
FROM students
WHERE COUNT(*) > 2
GROUP BY city;
```

❌ This is not the correct way.

Why?

Because `COUNT(*)` is calculated **after the rows are grouped**.

`WHERE` works on individual rows before the grouping/aggregation.

`HAVING` works with the grouped result.

Conceptually:

```
All rows
   ↓
WHERE
   ↓
Filtered rows
   ↓
GROUP BY
   ↓
Groups
   ↓
COUNT()
   ↓
HAVING
   ↓
Filtered groups
```

---

# 4. Basic Syntax

The basic syntax is:

```
SELECT column, aggregate_function(...)
FROM table
GROUP BY column
HAVING condition;
```

Example:

```
SELECT city, COUNT(*) AS total_students
FROM students
GROUP BY city
HAVING COUNT(*) > 1;
```

---

# 5. HAVING With COUNT()

This is the most common use.

```
SELECT city, COUNT(*) AS total_students
FROM students
GROUP BY city
HAVING COUNT(*) >= 2;
```

Meaning:

> Group students by city, count the students in each city, and keep only cities having at least 2 students.

Result:

```
city       total_students
---------  --------------
Kolkata          3
Delhi            2
```

---

# 6. HAVING With SUM()

Suppose we have:

```
orders

┌────┬─────────┬────────┐
│ id │ city    │ amount │
├────┼─────────┼────────┤
│ 1  │ Kolkata │ 500    │
│ 2  │ Delhi   │ 700    │
│ 3  │ Kolkata │ 300    │
│ 4  │ Delhi   │ 400    │
│ 5  │ Mumbai  │ 900    │
└────┴─────────┴────────┘
```

We want:

> Show cities whose total order amount is greater than 800.

First group:

```
Kolkata → 500 + 300 = 800
Delhi   → 700 + 400 = 1100
Mumbai  → 900
```

Query:

```
SELECT city, SUM(amount) AS total_amount
FROM orders
GROUP BY city
HAVING SUM(amount) > 800;
```

Result:

```
Delhi   → 1100
Mumbai  → 900
```

Kolkata doesn't appear because:

```
800 > 800
```

is false.

---

# 7. HAVING With AVG()

Suppose we want:

> Cities where the average student age is greater than 20.

```
SELECT city, AVG(age) AS average_age
FROM students
GROUP BY city
HAVING AVG(age) > 20;
```

Here:

```
GROUP BY city
       ↓
Calculate AVG(age)
       ↓
HAVING AVG(age) > 20
       ↓
Keep qualifying cities
```

---

# 8. HAVING With MAX()

You can also use:

```
SELECT city, MAX(age) AS oldest
FROM students
GROUP BY city
HAVING MAX(age) > 21;
```

Meaning:

> Find cities where the oldest student is older than 21.

---

# 9. HAVING With MIN()

Similarly:

```
SELECT city, MIN(age) AS youngest
FROM students
GROUP BY city
HAVING MIN(age) >= 20;
```

Meaning:

> Show cities where even the youngest student is at least 20.

---

# 10. HAVING With Multiple Conditions

You can use `AND` and `OR` with `HAVING`.

Example:

```
SELECT city, COUNT(*) AS total_students
FROM students
GROUP BY city
HAVING COUNT(*) >= 2
AND AVG(age) > 20;
```

Meaning:

> Keep cities that have at least 2 students **and** an average age greater than 20.

---

# 11. HAVING With WHERE

This is where things get interesting.

You can use **both**.

Suppose:

> Consider only students aged 20 or older, then show cities having at least 2 such students.

```
SELECT city, COUNT(*) AS total_students
FROM students
WHERE age >= 20
GROUP BY city
HAVING COUNT(*) >= 2;
```

The process is:

```
ALL STUDENTS
     ↓
WHERE age >= 20
     ↓
Remove students younger than 20
     ↓
GROUP BY city
     ↓
Create city groups
     ↓
COUNT(*)
     ↓
HAVING COUNT(*) >= 2
     ↓
Keep qualifying groups
```

This is a very important SQL pattern.

---

# 12. WHERE vs HAVING Example

Suppose:

```
students

Alice    Kolkata    19
Bob      Kolkata    21
Charlie  Kolkata    25
David    Delhi      18
Emma     Delhi      22
Frank    Delhi      23
```

### Query 1

```
SELECT city, COUNT(*)
FROM students
WHERE age >= 20
GROUP BY city;
```

`WHERE` first removes:

```
Alice → 19 ✗
David → 18 ✗
```

Remaining:

```
Bob
Charlie
Emma
Frank
```

Then grouping gives:

```
Kolkata → 2
Delhi   → 2
```

---

### Query 2

```
SELECT city, COUNT(*)
FROM students
GROUP BY city
HAVING COUNT(*) >= 3;
```

Here we count **all students first**:

```
Kolkata → 3
Delhi   → 3
```

Then:

```
COUNT >= 3
```

Both groups remain.

Notice how the two queries answer completely different questions.

---

# 13. WHERE and HAVING Together

Consider:

```
SELECT city, COUNT(*) AS total
FROM students
WHERE age >= 20
GROUP BY city
HAVING COUNT(*) >= 2;
```

Read it as normal English:

> "Take students aged 20 or older, group them by city, count them, and show only cities with at least 2 qualifying students."

That's exactly what the SQL is doing.

---

# 14. HAVING vs WHERE: Simple Example

Think about a classroom.

You have 100 students.

### WHERE

Teacher says:

> "Remove students whose age is below 18."

That's filtering **individual students**.

```
WHERE age >= 18
```

Then the teacher groups them by city.

```
GROUP BY city
```

Then asks:

> "Keep only cities having at least 10 students."

That's:

```
HAVING COUNT(*) >= 10
```

So:

```
WHERE
↓
Filter students

GROUP BY
↓
Group students

HAVING
↓
Filter groups
```

---

# 15. HAVING With ORDER BY

You can also sort the final grouped result.

```
SELECT city, COUNT(*) AS total_students
FROM students
GROUP BY city
HAVING COUNT(*) >= 2
ORDER BY total_students DESC;
```

Process:

```
GROUP BY
   ↓
Create groups

COUNT
   ↓
Calculate group size

HAVING
   ↓
Remove small groups

ORDER BY
   ↓
Sort remaining groups
```

Result:

```
Kolkata → 3
Delhi   → 2
```

with the largest group first.

# 16. The Full SQL Pattern

At this point, you've learned enough SQL clauses to understand this very useful pattern:

```
SELECT ...
FROM ...
WHERE ...
GROUP BY ...
HAVING ...
ORDER BY ...;
```

Each part has a different job:

```
SELECT
↓
What do I want to see?

FROM
↓
Which table?

WHERE
↓
Which rows?

GROUP BY
↓
How should rows be grouped?

HAVING
↓
Which groups?

ORDER BY
↓
What order?
```

---

# 17. Example of Everything Together

Suppose we have an `orders` table.

We want:

> Find cities whose orders from customers with amount ≥ 500 total more than 1000, and show the highest total first.

```
SELECT city, SUM(amount) AS total_amount
FROM orders
WHERE amount >= 500
GROUP BY city
HAVING SUM(amount) > 1000
ORDER BY total_amount DESC;
```

Break it down:

```
FROM orders
     ↓
Take orders

WHERE amount >= 500
     ↓
Keep qualifying orders

GROUP BY city
     ↓
Group them by city

SUM(amount)
     ↓
Calculate total for each city

HAVING SUM(amount) > 1000
     ↓
Keep only large totals

ORDER BY total_amount DESC
     ↓
Highest total first
```

This is the kind of query you'll eventually see in real applications.

---

# 18. A Very Important Difference

Don't confuse:

```
WHERE amount >= 500
```

with:

```
HAVING SUM(amount) >= 500
```

They mean completely different things.

### `WHERE amount >= 500`

> Only consider individual orders worth at least 500.

### `HAVING SUM(amount) >= 500`

> After grouping the orders, keep groups whose total is at least 500.

Think:

```
WHERE → individual data

HAVING → calculated/grouped data
```

---

# 19. Can HAVING Be Used Without GROUP BY?

MySQL allows `HAVING` in some queries even without an explicit `GROUP BY`, particularly when working with aggregate results.

For example:

```
SELECT COUNT(*) AS total_students
FROM students
HAVING COUNT(*) > 5;
```

This asks:

> Return the result only if the total number of students is greater than 5.

However, for learning the fundamentals, remember the main pattern:

```
GROUP BY → HAVING
```

That is where `HAVING` is most commonly understood and used.

---

# 20. Common Mistake

### ❌ Wrong idea

```
SELECT city, COUNT(*)
FROM students
WHERE COUNT(*) > 2
GROUP BY city;
```

`WHERE` cannot normally filter the result of an aggregate such as `COUNT(*)`.

### ✅ Correct

```
SELECT city, COUNT(*) AS total
FROM students
GROUP BY city
HAVING COUNT(*) > 2;
```

# 21. Quick Comparison

|Clause|Works on|Purpose|
|---|---|---|
|`WHERE`|Individual rows|Filter rows|
|`GROUP BY`|Rows|Create groups|
|`HAVING`|Groups|Filter groups|
|`ORDER BY`|Final result|Sort results|

The flow:

```
             ROWS
               │
               ▼
            WHERE
               │
          Filter rows
               │
               ▼
           GROUP BY
               │
          Create groups
               │
               ▼
          AGGREGATE
       COUNT / SUM / AVG
               │
               ▼
            HAVING
               │
          Filter groups
               │
               ▼
          ORDER BY
               │
          Sort result
```

---

# 22. The Golden Rule 🧠

Remember this sentence:

> **WHERE asks "Which rows?" while HAVING asks "Which groups?"**

Example:

```
WHERE age >= 20
```

means:

> Which students?

While:

```
HAVING COUNT(*) >= 2
```

means:

> Which groups have at least 2 students?

That distinction is the entire heart of `HAVING`.
