`INSERT` is an SQL command used to **add new rows (records) to a table**.

In simple words:

> **INSERT = Add new data to the table.**

It represents the **Create** part of CRUD:

```
CRUD
│
├── CREATE → INSERT  ← We are here
├── READ   → SELECT
├── UPDATE → UPDATE
└── DELETE → DELETE
```

---

# 1. Basic Syntax

The basic syntax is:

```
INSERT INTO table_name (column1, column2, column3)
VALUES (value1, value2, value3);
```

For example:

```
INSERT INTO students (name, age, city)
VALUES ('Alice', 20, 'Kolkata');
```

Read it like this:

```
INSERT INTO
     ↓
Which table?

students
     ↓
Which columns?

name, age, city
     ↓
What values?

Alice, 20, Kolkata
```

---

# 2. Example Table

Let's use this table:

```
students

┌────┬─────────┬─────┬────────────┐
│ id │ name    │ age │ city       │
├────┼─────────┼─────┼────────────┤
│ 1  │ Alice   │ 20  │ Kolkata    │
│ 2  │ Bob     │ 21  │ Delhi      │
└────┴─────────┴─────┴────────────┘
```

Suppose we want to add Charlie.

```
INSERT INTO students (name, age, city)
VALUES ('Charlie', 19, 'Mumbai');
```

Now:

```
┌────┬─────────┬─────┬────────────┐
│ id │ name    │ age │ city       │
├────┼─────────┼─────┼────────────┤
│ 1  │ Alice   │ 20  │ Kolkata    │
│ 2  │ Bob     │ 21  │ Delhi      │
│ 3  │ Charlie │ 19  │ Mumbai     │
└────┴─────────┴─────┴────────────┘
```

---

# 3. Why Don't We Insert `id`?

Suppose the table was created like this:

```
CREATE TABLE students (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100),
    age INT,
    city VARCHAR(100)
);
```

Because:

```
AUTO_INCREMENT
```

is being used, MySQL automatically generates the ID.

So we write:

```
INSERT INTO students (name, age, city)
VALUES ('Charlie', 19, 'Mumbai');
```

instead of:

```
INSERT INTO students (id, name, age, city)
VALUES (3, 'Charlie', 19, 'Mumbai');
```

The first approach is generally preferable when using `AUTO_INCREMENT`.

---

# 4. Inserting Into Specific Columns

You don't have to provide every column.

For example:

```
INSERT INTO students (name)
VALUES ('David');
```

If the table allows the other columns to be `NULL` or provides default values, MySQL can insert the row.

Result might look like:

```
┌────┬───────┬──────┬──────┐
│ id │ name  │ age  │ city │
├────┼───────┼──────┼──────┤
│ 4  │ David │ NULL │ NULL │
└────┴───────┴──────┴──────┘
```

However, if a column has:

```
NOT NULL
```

and doesn't have a default value, you must provide a value for it.

---

# 5. Inserting All Columns

You technically can write:

```
INSERT INTO students
VALUES (5, 'Emma', 22, 'Delhi');
```

But this is generally less clear.

Why?

Because you're relying on the exact order of the columns in the table.

It's better to explicitly specify the columns:

```
INSERT INTO students (name, age, city)
VALUES ('Emma', 22, 'Delhi');
```

This makes your query easier to understand and less fragile if the table structure changes.

---

# 6. Inserting Multiple Rows

You can insert multiple rows in a single query.

```
INSERT INTO students (name, age, city)
VALUES
    ('Emma', 22, 'Delhi'),
    ('Frank', 20, 'Kolkata'),
    ('Grace', 21, 'Mumbai');
```

MySQL adds all three records.

Result:

```
┌────┬───────┬─────┬─────────┐
│ id │ name  │ age │ city    │
├────┼───────┼─────┼─────────┤
│ 1  │ Alice │ 20  │ Kolkata │
│ 2  │ Bob   │ 21  │ Delhi   │
│ 3  │ Emma  │ 22  │ Delhi   │
│ 4  │ Frank │ 20  │ Kolkata │
│ 5  │ Grace │ 21  │ Mumbai  │
└────┴───────┴─────┴─────────┘
```

This can be more efficient than sending separate `INSERT` statements for every row.

---

# 7. Strings Need Quotes

For text values, use quotes:

```
INSERT INTO students (name, city)
VALUES ('Alice', 'Kolkata');
```

Notice:

```
'Alice'
'Kolkata'
```

Numbers don't need quotes:

```
20
21
19
```

So:

```
INSERT INTO students (name, age)
VALUES ('Alice', 20);
```

is correct.

---

# 8. Different Data Types

Suppose we have:

```
CREATE TABLE products (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100),
    price DECIMAL(10,2),
    available BOOLEAN
);
```

We can insert:

```
INSERT INTO products (name, price, available)
VALUES ('Keyboard', 799.99, TRUE);
```

Here:

```
'Keyboard' → String
799.99      → Decimal
TRUE        → Boolean
```

---

# 9. INSERT and NULL

`NULL` means:

> **No value / unknown value.**

For example:

```
INSERT INTO students (name, age, city)
VALUES ('John', NULL, 'Delhi');
```

The result could be:

```
id | name | age  | city
---+------+------|-------
6  | John | NULL | Delhi
```

Important:

```
NULL ≠ 0
NULL ≠ ''
```

`NULL` means the value is absent or unknown.

---

# 10. INSERT and DEFAULT

A column can have a default value.

For example:

```
CREATE TABLE students (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100),
    age INT DEFAULT 18
);
```

Now:

```
INSERT INTO students (name)
VALUES ('Alice');
```

Because we didn't provide `age`, MySQL uses:

```
age = 18
```

Result:

```
id | name  | age
---+-------+----
1  | Alice | 18
```

---

# 11. INSERT and NOT NULL

Suppose:

```
CREATE TABLE students (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    age INT
);
```

Because `name` is:

```
NOT NULL
```

this is invalid:

```
INSERT INTO students (age)
VALUES (20);
```

There is no `name`.

MySQL will reject the insertion because the required column wasn't provided.

Correct:

```
INSERT INTO students (name, age)
VALUES ('Alice', 20);
```

---

# 12. INSERT and PRIMARY KEY

Suppose:

```
id
↓
PRIMARY KEY
```

You cannot insert a duplicate ID.

For example, if:

```
id = 1
```

already exists:

```
INSERT INTO students (id, name)
VALUES (1, 'Bob');
```

will fail because `1` is already being used as a primary key.

This is one reason `AUTO_INCREMENT` is convenient.

---

# 13. INSERT and UNIQUE

Suppose:

```
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50) UNIQUE
);
```

Now:

```
INSERT INTO users (username)
VALUES ('alice');
```

works.

But trying:

```
INSERT INTO users (username)
VALUES ('alice');
```

again will fail because `username` must be unique.

So constraints protect your data during insertion.

---

# 14. INSERT and Foreign Keys

Remember foreign keys?

Suppose:

```
users
──────
id
1
2
```

and:

```
orders
───────
id
user_id
```

where:

```
orders.user_id
       ↓
users.id
```

We can insert:

```
INSERT INTO orders (user_id)
VALUES (1);
```

because user `1` exists.

But:

```
INSERT INTO orders (user_id)
VALUES (99);
```

may fail because:

```
users.id = 99
```

doesn't exist.

This is how foreign keys help maintain **referential integrity**.

---

# 15. INSERT vs CREATE TABLE

Don't confuse these:

### `CREATE TABLE`

Creates the **structure**:

```
CREATE TABLE students (
    id INT,
    name VARCHAR(100)
);
```

It creates:

```
Table
├── id
└── name
```

### `INSERT`

Adds **data**:

```
INSERT INTO students (id, name)
VALUES (1, 'Alice');
```

It creates:

```
Row
└── 1 | Alice
```

So:

```
CREATE TABLE
↓
Creates structure

INSERT
↓
Adds records
```

# 16. INSERT and CRUD

Now you can clearly see the relationship:

```
CRUD
│
├── C → INSERT
│
├── R → SELECT
│
├── U → UPDATE
│
└── D → DELETE
```

For example:

```
-- CREATE
INSERT INTO students (name, age)
VALUES ('Alice', 20);

-- READ
SELECT *
FROM students;

-- UPDATE
UPDATE students
SET age = 21
WHERE id = 1;

-- DELETE
DELETE FROM students
WHERE id = 1;
```

---

# 17. A Common Mistake: Column/Value Mismatch

This is wrong:

```
INSERT INTO students (name, age, city)
VALUES ('Alice', 20);
```

You specified **3 columns**:

```
name
age
city
```

but provided only **2 values**:

```
Alice
20
```

The number of columns and values should correspond.

Correct:

```
INSERT INTO students (name, age, city)
VALUES ('Alice', 20, 'Kolkata');
```

---

# 18. Another Common Mistake

This:

```
INSERT INTO students (name, age)
VALUES ('Alice', 'twenty');
```

is problematic because `age` is an integer column.

You should provide:

```
INSERT INTO students (name, age)
VALUES ('Alice', 20);
```

Always pay attention to the column's data type.

---

# 19. INSERT With a SELECT

There is also an advanced form:

```
INSERT INTO new_students (name, age)
SELECT name, age
FROM students;
```

This can copy selected data from one table into another.

You don't need to master this now. Just know that `INSERT` doesn't always have to get its values from manually written values.

# 20. What Happens Internally?

When you execute:

```
INSERT INTO students (name, age)
VALUES ('Alice', 20);
```

conceptually:

```
Your SQL
   ↓
MySQL
   ↓
Checks constraints
   ↓
Creates a new row
   ↓
Stores the data
   ↓
Updates indexes
   ↓
Row is available
```

For example:

```
Before

1 | Bob | 21
2 | Charlie | 19


INSERT Alice


After

1 | Bob | 21
2 | Charlie | 19
3 | Alice | 20
```

# 21. Complete Example

Create the table:

```
CREATE TABLE students (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    age INT,
    city VARCHAR(100)
);
```

Insert one row:

```
INSERT INTO students (name, age, city)
VALUES ('Alice', 20, 'Kolkata');
```

Insert another:

```
INSERT INTO students (name, age, city)
VALUES ('Bob', 21, 'Delhi');
```

Insert multiple rows:

```
INSERT INTO students (name, age, city)
VALUES
    ('Charlie', 19, 'Mumbai'),
    ('David', 22, 'Kolkata');
```

Then read the data:

```
SELECT *
FROM students;
```

You would get:

```
┌────┬─────────┬─────┬────────────┐
│ id │ name    │ age │ city       │
├────┼─────────┼─────┼────────────┤
│ 1  │ Alice   │ 20  │ Kolkata    │
│ 2  │ Bob     │ 21  │ Delhi      │
│ 3  │ Charlie │ 19  │ Mumbai     │
│ 4  │ David   │ 22  │ Kolkata    │
└────┴─────────┴─────┴────────────┘
```

# Quick Summary

### Basic INSERT

```
INSERT INTO students (name, age)

```

### Multiple rows

```
INSERT INTO students (name, age)
VALUES
    ('Alice', 20),
    ('Bob', 21),
    ('Charlie', 19);
```

### With NULL

```
INSERT INTO students (name, age)
VALUES ('Alice', NULL);
```

### With DEFAULT

```
INSERT INTO students (name)

```

if `age` has a default value.

### Remember:

> **`INSERT` adds new rows to an existing table.**

And the CRUD connection:

```
CREATE → INSERT
READ   → SELECT
UPDATE → UPDATE

```
