A **table** is the main structure used to store data in a relational database such as MySQL.

You can think of a table as a structured collection of **rows and columns**.

```
Database
   │
   ├── students
   ├── courses
   └── teachers
```

Each of these is a table.

---

# 1. What Does a Table Look Like?

For example, a `students` table:

```
students

┌────┬─────────┬─────┬───────────────────┐
│ id │ name    │ age │ email             │
├────┼─────────┼─────┼───────────────────┤
│ 1  │ Alice   │ 20  │ alice@example.com │
│ 2  │ Bob     │ 21  │ bob@example.com   │
│ 3  │ Charlie │ 19  │ charlie@example.com│
└────┴─────────┴─────┴───────────────────┘
```

Here:

- `students` = **table**
- `id`, `name`, `age`, `email` = **columns**
- Each horizontal entry = **row/record**
- `Alice`, `20`, etc. = **values**

---

# 2. Creating a Table

We use `CREATE TABLE`.

```
CREATE TABLE students (
    id INT,
    name VARCHAR(100),
    age INT,
    email VARCHAR(255)
);
```

The structure is:

```
CREATE TABLE table_name (
    column1 datatype,
    column2 datatype,
    column3 datatype
);
```

For example:

```
CREATE TABLE
      ↓
students
      ↓
columns
      ↓
id, name, age, email
```

---

# 3. Understanding the Columns

Look at:

```
id INT
```

It has two important parts:

```
id
↓
Column name

INT
↓
Data type
```

Similarly:

```
name VARCHAR(100)
```

means:

```
name
↓
Column name

VARCHAR(100)
↓
Data type
```

We'll study data types in the next topic.

---

# 4. Viewing a Table's Structure

You can use:

```
DESCRIBE students;
```

or:

```
DESC students;
```

You may see something like:

```
Field    Type           Null
--------------------------------
id       int            YES
name     varchar(100)   YES
age      int            YES
email    varchar(255)   YES
```

This shows the structure of the table.

---

# 5. Viewing Data

To see the records:

```
SELECT * FROM students;
```

The `*` means:

> Select all columns.

So:

```
SELECT * FROM students;
```

means:

> Give me all columns and rows from the `students` table.

---

# 6. Adding Data to a Table

Use `INSERT`.

```
INSERT INTO students (id, name, age, email)
VALUES (1, 'Alice', 20, 'alice@example.com');
```

Now:

```
students

┌────┬───────┬─────┬───────────────────┐
│ id │ name  │ age │ email             │
├────┼───────┼─────┼───────────────────┤
│ 1  │ Alice │ 20  │ alice@example.com │
└────┴───────┴─────┴───────────────────┘
```

Add another:

```
INSERT INTO students (id, name, age, email)
VALUES (2, 'Bob', 21, 'bob@example.com');
```

Now there are two rows.

---

# 7. Rows and Columns

This distinction is extremely important.

```
                 Columns
          ↓       ↓       ↓
       ┌────┬─────────┬─────┐
       │ id │ name    │ age │
       ├────┼─────────┼─────┤
Rows → │ 1  │ Alice   │ 20  │
       │ 2  │ Bob     │ 21  │
       └────┴─────────┴─────┘
```

### Column

Describes **what type of information** is stored.

```
name
```

### Row

Represents **one complete record**.

```
1 | Alice | 20
```

---

# 8. Table Names

Table names should be meaningful.

Good:

```
students
products
orders
users
employees
```

Avoid meaningless names such as:

```
table1
data
abc
xyz
```

Good naming makes your database much easier to understand.

---

# 9. Adding a Column Later

Suppose we already created:

```
students
────────────
id
name
age
```

Later we decide we also need:

```
email
```

We can use `ALTER TABLE`.

```
ALTER TABLE students
ADD COLUMN email VARCHAR(255);
```

Now:

```
students
────────────
id
name
age
email
```

---

# 10. Removing a Column

You can remove a column using:

```
ALTER TABLE students
DROP COLUMN email;
```

Now:

```
students
────────────
id
name
age
```

⚠️ Dropping a column can permanently remove the data stored in that column.

---

# 11. Renaming a Table

You can rename a table:

```
RENAME TABLE students TO learners;
```

Now:

```
students
   ↓
learners
```

The data remains in the table, but the table's name changes.

---

# 12. Deleting a Table

To completely remove a table:

```
DROP TABLE students;
```

This removes:

```
Table
+
Data
+
Structure
```

⚠️ `DROP TABLE` is destructive.

Don't use it casually on important databases.

---

# 13. Emptying a Table

There is an important difference between:

```
DROP TABLE students;
```

and:

```
TRUNCATE TABLE students;
```

### DROP

Removes the entire table:

```
students
↓
❌ table gone
```

### TRUNCATE

Removes the rows but keeps the table:

```
students
↓
Table remains
Rows removed
```

Example:

Before:

```
students

1 | Alice
2 | Bob
3 | John
```

After:

```
TRUNCATE TABLE students;
```

The table still exists:

```
students

(empty)
```

---

# 14. Table Constraints

Tables can have rules called **constraints**.

For example:

```
CREATE TABLE students (
    id INT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(255) UNIQUE
);
```

Here:

```
PRIMARY KEY
NOT NULL
UNIQUE
```

are constraints.

They control what data can be stored.

We'll study constraints separately.

---

# 15. Primary Key in a Table

A common table design is:

```
CREATE TABLE students (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    age INT
);
```

Now:

```
id
```

uniquely identifies each row.

```
students

┌────┬─────────┬─────┐
│ id │ name    │ age │
├────┼─────────┼─────┤
│ 1  │ Alice   │ 20  │
│ 2  │ Bob     │ 21  │
│ 3  │ Charlie │ 19  │
└────┴─────────┴─────┘
```

Two rows cannot have the same primary key value.

---

# 16. Auto Increment

For IDs, we often don't want to manually enter:

```
1
2
3
4
5
```

MySQL can generate them automatically.

```
CREATE TABLE students (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100),
    age INT
);
```

Now we can insert:

```
INSERT INTO students (name, age)
VALUES ('Alice', 20);
```

MySQL can generate:

```
id = 1
```

Next:

```
INSERT INTO students (name, age)
VALUES ('Bob', 21);
```

MySQL can generate:

```
id = 2
```

So:

```
Alice → 1
Bob   → 2
John  → 3
```

This is very common in application databases.

---

# 17. A Proper Basic Table

Putting some of these concepts together:

```
CREATE TABLE students (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    age INT,
    email VARCHAR(255) UNIQUE
);
```

This gives us:

```
students
────────────────────────
id       → ID
name     → required
age      → number
email    → unique
```

This is much closer to how real application tables are designed.

---

# 18. Multiple Tables

A database normally contains multiple tables.

For example:

```
college
│
├── students
├── teachers
├── courses
└── departments
```

Each table stores a different type of information.

```
students
→ student information

teachers
→ teacher information

courses
→ course information

departments
→ department information
```

The tables can then be connected using relationships.

---

# 19. Don't Put Everything in One Table

Bad design:

```
college

student_name
student_email
teacher_name
course_name
department_name
marks
...
```

Better:

```
students
teachers
courses
departments
results
```

Then connect them using keys.

This is one of the main ideas behind relational database design.

# 20. Table Lifecycle

You'll frequently work with these SQL commands:

```
CREATE
   ↓
INSERT
   ↓
SELECT
   ↓
UPDATE
   ↓
DELETE
   ↓
ALTER
   ↓
DROP
```

For example:

```
CREATE TABLE students (...);

INSERT INTO students (...);

SELECT * FROM students;

UPDATE students ...;

DELETE FROM students ...;

ALTER TABLE students ...;

DROP TABLE students;
```

These commands form the foundation of working with MySQL tables.
