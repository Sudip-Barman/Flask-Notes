`DELETE` is an SQL command used to **remove existing rows from a table**.

In simple words:

> **DELETE = Remove data from the table.**

It represents the **Delete** part of CRUD:

```
CRUD
│
├── CREATE → INSERT
├── READ   → SELECT
├── UPDATE → UPDATE
└── DELETE → DELETE  ← We are here
```

---

# 1. Basic Syntax

```
DELETE FROM table_name
WHERE condition;
```

There are two important parts:

```
DELETE FROM
     ↓
Which table?

WHERE
     ↓
Which row(s) should be removed?
```

For example:

```
DELETE FROM students
WHERE id = 3;
```

This means:

> Delete the student whose `id` is `3`.

---

# 2. Example Table

Let's use this table:

```
students

┌────┬─────────┬─────┬────────────┐
│ id │ name    │ age │ city       │
├────┼─────────┼─────┼────────────┤
│ 1  │ Alice   │ 20  │ Kolkata    │
│ 2  │ Bob     │ 21  │ Delhi      │
│ 3  │ Charlie │ 19  │ Mumbai     │
│ 4  │ David   │ 22  │ Kolkata    │
└────┴─────────┴─────┴────────────┘
```

Suppose we want to delete Charlie.

```
DELETE FROM students
WHERE id = 3;
```

Before:

```
1 | Alice
2 | Bob
3 | Charlie
4 | David
```

After:

```
1 | Alice
2 | Bob
4 | David
```

Charlie is gone.

---

# 3. Why `WHERE` Is Extremely Important ⚠️

This is the most important thing to understand about `DELETE`.

Consider:

```
DELETE FROM students;
```

There is **no `WHERE`**.

This means:

> Delete **all rows** from `students`.

Before:

```
Alice
Bob
Charlie
David
```

After:

```
(empty)
```

💀 Every row has been deleted.

The table itself still exists, but its rows are gone.

---

# 4. Safe DELETE Habit

Before deleting something, first check what you're going to delete.

Suppose you want:

```
DELETE FROM students
WHERE id = 3;
```

First run:

```
SELECT *
FROM students
WHERE id = 3;
```

Check the result.

If it is the correct student:

```
3 | Charlie | 19 | Mumbai
```

then execute:

```
DELETE FROM students
WHERE id = 3;
```

So a useful habit is:

```
SELECT
   ↓
Check
   ↓
DELETE
```

This is especially useful when working with important data.

---

# 5. DELETE Using Another Condition

You don't have to use `id`.

For example:

```
DELETE FROM students
WHERE age < 20;
```

This removes every student whose age is less than 20.

If the table contains:

```
Alice   | 20
Bob     | 21
Charlie | 19
David   | 22
```

after deletion:

```
Alice   | 20
Bob     | 21
David   | 22
```

Charlie is removed.

---

# 6. DELETE With Multiple Conditions

You can use `AND`.

```
DELETE FROM students
WHERE age < 20
AND city = 'Mumbai';
```

This means:

```
age < 20
    AND
city = Mumbai
```

Both conditions must be true.

---

# 7. DELETE With OR

You can also use `OR`.

```
DELETE FROM students
WHERE city = 'Delhi'
OR city = 'Mumbai';
```

This removes students from either Delhi or Mumbai.

So:

```
AND → Both conditions
OR  → At least one condition
```

---

# 8. DELETE vs DROP

This is a **very important distinction**.

### DELETE

Removes **rows**:

```
DELETE FROM students
WHERE id = 3;
```

The table remains:

```
students
│
├── columns
├── structure
└── remaining rows
```

### DROP

Removes the **entire table**:

```
DROP TABLE students;
```

Now:

```
students
    ↓
GONE
```

So:

```
DELETE
↓
Remove data/rows

DROP
↓
Remove the entire table
```

---

# 9. DELETE vs TRUNCATE

Another common confusion.

### DELETE

```
DELETE FROM students;
```

Removes rows and supports a `WHERE` condition.

For example:

```
DELETE FROM students
WHERE age < 20;
```

Only matching rows are deleted.

### TRUNCATE

```
TRUNCATE TABLE students;
```

Removes **all rows** from the table.

It does not use a normal `WHERE` clause to selectively remove rows.

Think:

```
DELETE
↓
Can remove selected rows

TRUNCATE
↓
Remove all rows quickly
```

`TRUNCATE` is a separate SQL operation, not another form of CRUD's Delete command.

---

# 10. DELETE vs DROP vs TRUNCATE

Remember this table:

|Command|Removes Rows|Removes Table|`WHERE`|
|---|---|---|---|
|`DELETE`|✅|❌|✅|
|`TRUNCATE`|✅ All|❌|❌|
|`DROP`|✅|✅|❌|

A simple mental model:

```
DELETE
🧹 Remove selected/all rows

TRUNCATE
🧹🧹 Empty the table

DROP
💣 Remove the table itself
```

# 11. DELETE and Primary Key

Suppose:

```
id | name
---+------
1  | Alice
2  | Bob
3  | Charlie
```

You can safely target a particular row using its primary key:

```
DELETE FROM students
WHERE id = 2;
```

Result:

```
1 | Alice
3 | Charlie
```

This is a common pattern because the primary key uniquely identifies the record.

---

# 12. DELETE and Foreign Keys

This becomes important when tables are related.

Suppose:

```
users
─────
id
1
2
```

and:

```
orders
──────
id | user_id
1  | 1
2  | 1
```

The relationship is:

```
users.id
   ↑
   │
orders.user_id
```

Now suppose you try:

```
DELETE FROM users
WHERE id = 1;
```

What happens?

It depends on how the foreign key was configured.

MySQL may prevent the deletion because orders still reference that user.

Or, if the foreign key was configured with an appropriate cascading action such as `ON DELETE CASCADE`, related rows can be deleted automatically.

This is why **foreign-key rules are important when deleting data**.

---

# 13. DELETE and Constraints

Remember the constraints we learned:

```
PRIMARY KEY
FOREIGN KEY
UNIQUE
NOT NULL
```

These constraints can affect whether a deletion is allowed.

For example:

```
Parent row
   ↑
   │
Foreign key
   │
Child row
```

Deleting the parent may be blocked if child rows depend on it, unless the relationship has been configured to handle the deletion.

---

# 14. DELETE Multiple Rows

You can intentionally delete multiple rows.

For example:

```
DELETE FROM students
WHERE city = 'Kolkata';
```

If we have:

```
Alice   | Kolkata
Bob     | Delhi
David   | Kolkata
Charlie | Mumbai
```

after deletion:

```
Bob     | Delhi
Charlie | Mumbai
```

Both Kolkata records were deleted.

So `DELETE` doesn't necessarily mean:

> Delete one row.

It means:

> **Delete every row that satisfies the condition.**

---

# 15. DELETE Without WHERE

Let's make this crystal clear:

```
DELETE FROM students;
```

means:

```
Find all rows
     ↓
Delete all rows
```

Whereas:

```
DELETE FROM students
WHERE id = 3;
```

means:

```
Find rows where id = 3
     ↓
Delete those rows
```

So the `WHERE` clause controls **which rows are affected**.

---

# 16. DELETE vs UPDATE

These two are easy to confuse.

### UPDATE

Changes data:

```
UPDATE students
SET age = 21
WHERE id = 1;
```

Before:

```
1 | Alice | 20
```

After:

```
1 | Alice | 21
```

The row remains.

### DELETE

Removes the row:

```
DELETE FROM students
WHERE id = 1;
```

Before:

```
1 | Alice | 21
```

After:

```
No row
```

So:

```
UPDATE
↓
Modify row

DELETE
↓
Remove row
```

---

# 17. DELETE vs SELECT

These are also opposites in terms of effect:

```
SELECT *
FROM students
WHERE id = 1;
```

means:

> "Show me this row."

while:

```
DELETE FROM students
WHERE id = 1;
```

means:

> "Remove this row."

A good habit is to use the same `WHERE` condition in a `SELECT` first:

```
SELECT *
FROM students
WHERE id = 1;
```

then:

```
DELETE FROM students
WHERE id = 1;
```

---

# 18. DELETE and Transactions

There is an important concept called a **transaction**.

For example:

```
START TRANSACTION;

DELETE FROM students
WHERE id = 3;

ROLLBACK;
```

`ROLLBACK` can undo the deletion if the transaction hasn't been committed.

Or:

```
START TRANSACTION;

DELETE FROM students
WHERE id = 3;

COMMIT;
```

`COMMIT` makes the transaction permanent.

We'll study **Transactions** later in this module, so you don't need to master this yet.

Just remember:

```
Transaction
    ↓
DELETE
    ↓
ROLLBACK → Undo
COMMIT   → Save
```

# 19. Complete CRUD Example

Now we've completed all four basic CRUD operations.

### CREATE

```
INSERT INTO students (name, age)
VALUES ('Alice', 20);
```

### READ

```
SELECT *
FROM students;
```

### UPDATE

```
UPDATE students
SET age = 21
WHERE id = 1;
```

### DELETE

```
DELETE FROM students
WHERE id = 1;
```

The entire CRUD cycle:

```
             CRUD
              │
      ┌───────┼────────┐
      ↓       ↓        ↓
   CREATE    READ     UPDATE    DELETE
      ↓       ↓        ↓          ↓
   INSERT   SELECT   UPDATE     DELETE
```

# 20. The Mental Model

Whenever you see:

```
DELETE FROM students
WHERE id = 3;
```

read it like a sentence:

> **DELETE FROM** the `students` table  
> **WHERE** the `id` is `3`.

That's the basic idea.
