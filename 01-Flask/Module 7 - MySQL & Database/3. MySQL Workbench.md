
**MySQL Workbench** is a graphical tool used to **work with MySQL databases**.

Instead of doing everything through the terminal:

```
CREATE DATABASE ...
SELECT ...
INSERT ...
```

you can use a visual interface to manage your MySQL server and execute SQL.

> **Important:** MySQL Workbench is **not MySQL itself**.  
> MySQL Server stores and manages the data. Workbench is a tool that connects to the server.

---

# 1. MySQL Server vs Workbench

This is the most important thing to understand.

```
                MySQL Server
                     │
              Stores/manages
                  databases
                     ▲
                     │
              Connection
                     │
              MySQL Workbench
```

### MySQL Server

Does the actual database work:

```
MySQL Server
│
├── flask_learning
│   ├── users
│   ├── posts
│   └── comments
│
└── shop
    ├── products
    └── orders
```

### MySQL Workbench

Provides a graphical interface to interact with it.

```
Workbench
│
├── Create databases
├── Create tables
├── Write SQL
├── View data
├── Design databases
└── Manage connections
```

---

# 2. Why Use Workbench?

You can manage MySQL completely from the command line, but Workbench makes many tasks easier to visualize.

For example, instead of:

```
SHOW DATABASES;
```

you can see databases in the Workbench interface.

Instead of manually remembering table structures, you can inspect them visually.

It also provides an **SQL Editor** where you can write SQL commands.

---

# 3. Opening MySQL Workbench

After installation, open:

```
MySQL Workbench
```

You'll usually see a section for MySQL connections.

For a local MySQL server, you might have a connection such as:

```
Local instance MySQL
```

or a connection you created yourself.

---

# 4. Creating a Connection

A MySQL connection contains information about **where the MySQL server is and how to access it**.

Typical local settings:

```
Connection Name: Local MySQL
Hostname:        127.0.0.1
Port:            3306
Username:        root
Password:        ********
```

Let's understand them.

### Connection Name

```
Local MySQL
```

Just a name you choose to identify the connection in Workbench.

### Hostname

```
127.0.0.1
```

means your own computer.

You can also commonly use:

```
localhost
```

### Port

```
3306
```

is the default MySQL port.

### Username

For your local installation, this may be:

```
root
```

### Password

The password you configured when installing MySQL.

---

# 5. Connecting

Once the connection is configured, open it.

Workbench will connect:

```
MySQL Workbench
       │
       │ connection
       ▼
MySQL Server
```

If successful, you'll get access to the SQL editor and database information.

# 6. The Workbench Interface

The exact interface can vary by version, but you'll commonly see areas for:

```
┌─────────────────────────────────────────────┐
│ Toolbar                                     │
├──────────────┬──────────────────────────────┤
│              │                              │
│ Navigator    │        SQL Editor            │
│              │                              │
│ Schemas      │     SELECT * FROM users;    │
│              │                              │
│ Tables       │                              │
│              │                              │
└──────────────┴──────────────────────────────┘
```

The important areas are:

### Navigator

Used to browse databases, tables, views, etc.

### SQL Editor

Where you write SQL.

### Output / Result Area

Shows the results of your SQL commands.

---

# 7. Schemas

In MySQL Workbench, you'll often see the word:

> **Schemas**

For practical MySQL usage, you can think of a schema as a **database**.

For example:

```
Schemas
│
├── flask_learning
├── shop
└── school
```

Inside:

```
flask_learning
│
├── Tables
├── Views
├── Stored Procedures
└── Functions
```

For our Flask learning, the important part initially is:

```
Schema
  ↓
Tables
  ↓
Rows
```

---

# 8. Creating a Database Using Workbench

Open the SQL editor and write:

```
CREATE DATABASE flask_learning;
```

Execute the query.

Then refresh the Schemas section.

You should see:

```
flask_learning
```

---

# 9. Selecting a Database

You can execute:

```
USE flask_learning;
```

Now queries operate on that database.

You can also specify the database directly when writing queries.

For example:

```
SELECT *
FROM flask_learning.users;
```

But while learning, this is usually easier:

```
USE flask_learning;
```

Then:

```
SELECT * FROM users;
```

---

# 10. Creating a Table

Let's create a simple table:

```
CREATE TABLE students (
    id INT,
    name VARCHAR(100),
    age INT
);
```

Refresh the schema.

You'll see:

```
flask_learning
│
└── Tables
    │
    └── students
```

---

# 11. Viewing the Table

Expand:

```
Tables
   ↓
students
```

Workbench can show information about the table, including its columns.

You can also use SQL:

```
DESCRIBE students;
```

You'll see something conceptually like:

```
Field   Type           Null
id      int            YES
name    varchar(100)   YES
age     int            YES
```

---

# 12. Insert Data Through SQL Editor

Run:

```
INSERT INTO students (id, name, age)
VALUES (1, 'Alice', 20);
```

Then:

```
SELECT * FROM students;
```

Workbench will show the result in a table-like result grid.

```
┌────┬───────┬─────┐
│ id │ name  │ age │
├────┼───────┼─────┤
│ 1  │ Alice │ 20  │
└────┴───────┴─────┘
```

---

# 13. The SQL Editor

The SQL editor is one of the most useful parts of Workbench.

You can write:

```
SELECT * FROM students;
```

Then execute it.

You can also run multiple statements:

```
INSERT INTO students
VALUES (2, 'Bob', 21);

SELECT *
FROM students;
```

The result appears in the output area.

---

# 14. Why Developers Still Learn SQL

You might wonder:

> "If Workbench can do everything visually, why learn SQL?"

Because your Flask application will eventually need to communicate with the database programmatically.

For example:

```
Flask
  ↓
SQLAlchemy
  ↓
MySQL
```

Your application won't open Workbench.

It sends database operations directly.

Understanding SQL helps you understand what your application is actually doing.

---

# 15. Workbench Is Not Required for Flask

This is another important point.

Your Flask application needs:

```
Flask
+
MySQL Server
```

It does **not** require:

```
MySQL Workbench
```

Workbench is simply a development/administration tool.

You could have:

```
Flask
   │
   ▼
MySQL Server
```

with no Workbench installed.

# 16. Workbench vs phpMyAdmin

You'll also encounter **phpMyAdmin**.

### MySQL Workbench

```
        ↓

```

### phpMyAdmin

```

        ↓

        ↓

```

Conceptually:

```
                 MySQL Server
                ▲           ▲
                │           │
          Workbench     phpMyAdmin
          Desktop          Web
```

We'll cover phpMyAdmin separately.

# 17. Workbench Database Design

Workbench also has tools for visually designing databases.

For example, you might have:

```
users
────────────
id
name
email
```

and:

```
orders
────────────
id
user_id
total
```

You can represent the relationship:

```
users
  │
  │ 1
  │
  │
  │ N
  ▼
orders
```

This is part of **database modeling** and **ER diagrams**, which we'll cover later.

# 18. Important Terms

|Term|Meaning|
|---|---|
|**MySQL Server**|Actually manages the databases|
|**Workbench**|GUI tool for interacting with MySQL|
|**Connection**|Configuration used to connect to a MySQL server|
|**Schema**|Database in common MySQL usage|
|**SQL Editor**|Area where you write SQL|
|**Result Grid**|Displays query results|
|**Table**|Stores data in rows and columns|
