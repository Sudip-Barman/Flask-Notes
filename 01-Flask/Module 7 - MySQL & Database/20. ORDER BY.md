
`ORDER BY` is used in SQL to **sort the rows returned by a query**.

In simple words:

> **ORDER BY = Arrange the result in a particular order.**

For example, you may want to:

- Sort students by age
- Sort products by price
- Sort names alphabetically
- Show newest records first
- Show highest prices first

---

# 1. Basic Syntax

```
SELECT *
FROM table_name
ORDER BY column_name;
```

For example:

```
SELECT *
FROM students
ORDER BY age;
```

This sorts students by `age`.

By default, SQL uses **ascending order (`ASC`)**.

---

# 2. Example Table

Suppose we have:

```
students

┌────┬─────────┬─────┬────────────┐
│ id │ name    │ age │ city       │
├────┼─────────┼─────┼────────────┤
│ 1  │ Alice   │ 22  │ Kolkata    │
│ 2  │ Bob     │ 19  │ Delhi      │
│ 3  │ Charlie │ 25  │ Mumbai     │
│ 4  │ David   │ 21  │ Kolkata    │
└────┴─────────┴─────┴────────────┘
```

If we run:

```
SELECT *
FROM students
ORDER BY age;
```

Result:

```
Bob     → 19
David   → 21
Alice   → 22
Charlie → 25
```

The original table wasn't changed.

Only the **result is sorted**.

---

# 3. ASC: Ascending Order

You can explicitly write:

```
SELECT *
FROM students
ORDER BY age ASC;
```

`ASC` means:

> **Ascending**

For numbers:

```
1 → 2 → 3 → 4 → 5
```

For names:

```
Alice
Bob
Charlie
David
```

For dates:

```
2026-01-01
2026-02-01
2026-03-01
```

So:

```
ASC
↓
Small → Large
A → Z
Old → New
```

---

# 4. DESC: Descending Order

You can reverse the order:

```
SELECT *
FROM students
ORDER BY age DESC;
```

`DESC` means:

> **Descending**

Result:

```
Charlie → 25
Alice   → 22
David   → 21
Bob     → 19
```

Think:

```
DESC
↓
Large → Small
Z → A
New → Old
```

---

# 5. ASC vs DESC

This is the most important part of `ORDER BY`.

```
ASC
↓
1
2
3
4
5
```

```
DESC
↓
5
4
3
2
1
```

Example:

```
ORDER BY age ASC;
```

means:

> Youngest to oldest.

While:

```
ORDER BY age DESC;
```

means:

> Oldest to youngest.

---

# 6. Sorting Text

`ORDER BY` also works with text.

```
SELECT *
FROM students
ORDER BY name ASC;
```

Result:

```
Alice
Bob
Charlie
David
```

You can reverse it:

```
SELECT *
FROM students
ORDER BY name DESC;
```

Result:

```
David
Charlie
Bob
Alice
```

So `ORDER BY` isn't only for numbers.

---

# 7. Sorting by Price

Suppose:

```
products

┌────┬─────────┬───────┐
│ id │ name    │ price │
├────┼─────────┼───────┤
│ 1  │ Mouse   │ 500   │
│ 2  │ Keyboard│ 1200  │
│ 3  │ Monitor │ 8000  │
│ 4  │ Cable   │ 200   │
└────┴─────────┴───────┘
```

Lowest price first:

```
SELECT *
FROM products
ORDER BY price ASC;
```

Result:

```
Cable     → 200
Mouse     → 500
Keyboard  → 1200
Monitor   → 8000
```

Highest price first:

```
SELECT *
FROM products
ORDER BY price DESC;
```

Result:

```
Monitor   → 8000
Keyboard  → 1200
Mouse     → 500
Cable     → 200
```

---

# 8. ORDER BY With WHERE

You can combine `WHERE` and `ORDER BY`.

For example:

> Show students from Kolkata, sorted by age from youngest to oldest.

```
SELECT *
FROM students
WHERE city = 'Kolkata'
ORDER BY age ASC;
```

Think about the process:

```
students
   ↓
WHERE city = Kolkata
   ↓
Filter rows
   ↓
ORDER BY age ASC
   ↓
Sort those rows
```

So:

> **WHERE decides which rows. ORDER BY decides their order.**

This distinction is very important.

---

# 9. ORDER BY With SELECT

You don't have to select every column.

```
SELECT name, age
FROM students
ORDER BY age DESC;
```

Result:

```
name       age
─────────  ───
Charlie    25
Alice      22
David      21
Bob        19
```

---

# 10. Sorting by Multiple Columns

This is where `ORDER BY` becomes more powerful.

Suppose:

```
students

name     city       age
Alice    Kolkata    22
Bob      Delhi      19
Charlie  Kolkata    25
David    Delhi      21
Emma     Kolkata    21
```

You can sort by **city first**, then by age:

```
SELECT *
FROM students
ORDER BY city ASC, age ASC;
```

The database first sorts by:

```
city
```

Then, when multiple rows have the same city, it sorts those rows by:

```
age
```

Result conceptually:

```
Delhi
    Bob    19
    David  21

Kolkata
    Emma   21
    Alice  22
    Charlie 25
```

---

# 11. Different Directions for Different Columns

You can also do:

```
SELECT *
FROM students
ORDER BY city ASC, age DESC;
```

This means:

```
city → A to Z

age → highest to lowest within each city
```

For example:

```
Delhi
    David  21
    Bob    19

Kolkata
    Charlie 25
    Alice   22
    Emma    21
```

Each column can have its own sorting direction.

---

# 12. ORDER BY Happens After WHERE

A useful mental model is:

```
FROM
 ↓
WHERE
 ↓
SELECT
 ↓
ORDER BY
```

For a query like:

```
SELECT name, age
FROM students
WHERE age >= 20
ORDER BY age DESC;
```

Think:

```
1. FROM students
       ↓
2. Find students
       ↓
3. WHERE age >= 20
       ↓
4. Keep matching rows
       ↓
5. ORDER BY age DESC
       ↓
6. Highest age first
```

You don't need to memorize SQL's complete internal execution process yet. This simplified model is enough for now.

---

# 13. ORDER BY With LIMIT

`ORDER BY` is often combined with `LIMIT`.

For example:

> Show the 3 oldest students.

```
SELECT *
FROM students
ORDER BY age DESC
LIMIT 3;
```

The idea is:

```
All students
     ↓
Sort by age DESC
     ↓
25
22
21
19
     ↓
LIMIT 3
     ↓
25
22
21
```

So:

```
ORDER BY → Arrange
LIMIT    → Take only a certain number
```

This combination is extremely useful.

---

# 14. Finding the Highest Value

Suppose you want the most expensive product.

```
SELECT *
FROM products
ORDER BY price DESC
LIMIT 1;
```

Process:

```
Sort highest → lowest
        ↓
Take first row
```

You get the product with the highest price.

---

# 15. Finding the Lowest Value

For the cheapest product:

```
SELECT *
FROM products
ORDER BY price ASC
LIMIT 1;
```

Process:

```
Sort lowest → highest
        ↓
Take first row
```

You get the cheapest product.

Later, you'll learn `MIN()` and `MAX()`, which are often more appropriate when you only need the value itself.

---

# 16. ORDER BY With Dates

Suppose we have:

```
orders

id    order_date
1     2026-08-15
2     2026-09-01
3     2026-07-20
4     2026-08-28
```

Oldest first:

```
SELECT *
FROM orders
ORDER BY order_date ASC;
```

Result:

```
2026-07-20
2026-08-15
2026-08-28
2026-09-01
```

Newest first:

```
SELECT *
FROM orders
ORDER BY order_date DESC;
```

Result:

```
2026-09-01
2026-08-28
2026-08-15
2026-07-20
```

---

# 17. ORDER BY Does NOT Change the Table

This is an important point.

Suppose the table is stored as:

```
Alice
Charlie
Bob
David
```

You run:

```
SELECT *
FROM students
ORDER BY name ASC;
```

You might see:

```
Alice
Bob
Charlie
David
```

But `ORDER BY` did **not permanently rearrange the table's stored rows**.

It only determines the order of the query result.

Think:

```
Database
   ↓
Original data
   ↓
SELECT + ORDER BY
   ↓
Sorted result
```

---

# 18. ORDER BY With UPDATE

MySQL can also use `ORDER BY` in certain `UPDATE` statements.

For example:

```
UPDATE students
SET age = age + 1
ORDER BY age DESC
LIMIT 1;
```

This could target the row with the highest age.

However, for your current learning stage, focus mainly on `ORDER BY` with `SELECT`.

---

# 19. ORDER BY With DELETE

MySQL also supports `ORDER BY` and `LIMIT` in certain single-table `DELETE` statements.

For example:

```
DELETE FROM students
ORDER BY age DESC
LIMIT 1;
```

Conceptually:

```
Sort students by age
        ↓
Highest age first
        ↓
Take 1
        ↓
Delete it
```

Again, this is a more advanced use. The core concept remains:

> `ORDER BY` controls the ordering.

---

# 20. Column Position in ORDER BY

You may sometimes see:

```
SELECT name, age
FROM students
ORDER BY 2;
```

Here `2` refers to the second selected column:

```
1 → name
2 → age
```

So this sorts by `age`.

However, writing:

```
ORDER BY age;
```

is generally clearer and easier to maintain.

For your notes, prefer the column name.

---

# 21. Common Mistake: Forgetting DESC

Suppose you want the highest age first:

❌

```
SELECT *
FROM students
ORDER BY age;
```

This gives ascending order.

✅

```
SELECT *
FROM students
ORDER BY age DESC;
```

Remember:

```
ASC  → Small → Large
DESC → Large → Small
```

---

# 22. Common Mistake: Thinking ORDER BY Filters

Consider:

```
SELECT *
FROM students
ORDER BY age > 20;
```

This is **not the normal way** to say:

> "Show students older than 20."

Use:

```
SELECT *
FROM students
WHERE age > 20;
```

Remember:

```
WHERE
↓
Filter rows

ORDER BY
↓
Sort rows
```

---

# 23. WHERE + ORDER BY

This is a very common combination:

```
SELECT *
FROM students
WHERE city = 'Kolkata'
ORDER BY age DESC;
```

Read it as:

> "Find students from Kolkata, then arrange them from oldest to youngest."

So:

```
WHERE
↓
Which rows?

ORDER BY
↓
What order?
```

That distinction will become very useful as we move into more advanced SQL.

---

# 24. ORDER BY + LIMIT

Another very common combination:

```
SELECT *
FROM products
ORDER BY price DESC
LIMIT 5;
```

Read it as:

> "Sort products from most expensive to cheapest, then show only the first 5."

```
ORDER BY
    ↓
Sort

LIMIT
    ↓
Take some
```

---

# 25. Quick Reference

|Query|Meaning|
|---|---|
|`ORDER BY age`|Sort age ascending|
|`ORDER BY age ASC`|Sort age ascending|
|`ORDER BY age DESC`|Sort age descending|
|`ORDER BY name ASC`|A → Z|
|`ORDER BY name DESC`|Z → A|
|`ORDER BY city, age`|Sort by city, then age|
|`ORDER BY age DESC LIMIT 1`|Highest age row|
|`ORDER BY price ASC LIMIT 1`|Lowest price row|

# 26. The Mental Model

If you remember only one thing:

> **`WHERE` = Which rows?**  
> **`ORDER BY` = What order?**

For example:

```
SELECT *
FROM students
WHERE age >= 20
ORDER BY age DESC;
```

Read it as:

```
FROM students
      ↓
WHERE age >= 20
      ↓
Which students?
      ↓
ORDER BY age DESC
      ↓
Put oldest first
```

And the basic syntax is:

```
SELECT columns
FROM table_name
WHERE condition
ORDER BY column_name ASC;
```

or:

```
SELECT columns
FROM table_name
WHERE condition
ORDER BY column_name DESC;
```
