A **View** in MySQL is a **virtual table based on a SQL query**.

In simple words:

> **View = A saved SQL query that you can use like a table.**

It does not normally store a separate copy of the data. Instead, MySQL stores the **query definition**, and when you use the view, MySQL gets the current data from the underlying tables.

---

# 1. Why Do We Need Views?

Suppose we have two tables:

### `students`

```
┌────┬─────────┬─────────┐
│ id │ name    │ city    │
├────┼─────────┼─────────┤
│ 1  │ Alice   │ Kolkata │
│ 2  │ Bob     │ Delhi   │
│ 3  │ Charlie │ Mumbai  │
└────┴─────────┴─────────┘
```

### `orders`

```
┌────┬────────────┬────────┐
│ id │ student_id │ amount │
├────┼────────────┼────────┤
│ 1  │ 1          │ 500    │
│ 2  │ 2          │ 800    │
│ 3  │ 1          │ 300    │
└────┴────────────┴────────┘
```

We frequently need this information:

```
Student Name | City    | Order Amount
-------------|---------|-------------
Alice        | Kolkata | 500
Bob          | Delhi   | 800
Alice        | Kolkata | 300
```

To get it, we need to write:

```
SELECT s.name, s.city, o.amount
FROM students s
JOIN orders o
ON s.id = o.student_id;
```

Imagine having to write this query again and again.

Instead, we can create a **View**.

---

# 2. Creating a View

Syntax:

```
CREATE VIEW view_name AS
SELECT ...
FROM ...;
```

For example:

```
CREATE VIEW student_orders AS
SELECT s.name, s.city, o.amount
FROM students s
JOIN orders o
ON s.id = o.student_id;
```

Now we have a view called:

```
student_orders
```

Conceptually:

```
students ────┐
             │
             ├── JOIN → student_orders
             │
orders ──────┘
```

---

# 3. Using a View

Once the view exists, you can query it almost like a normal table:

```
SELECT *
FROM student_orders;
```

Result:

```
┌────────┬─────────┬────────┐
│ name   │ city    │ amount │
├────────┼─────────┼────────┤
│ Alice  │ Kolkata │ 500    │
│ Bob    │ Delhi   │ 800    │
│ Alice  │ Kolkata │ 300    │
└────────┴─────────┴────────┘
```

This is the main benefit.

Instead of repeatedly writing:

```
JOIN ...
ON ...
```

you can simply write:

```
SELECT *
FROM student_orders;
```

---

# 4. Is a View a Real Table?

This is an important distinction.

A normal table:

```
TABLE
↓
Stores data
```

A view:

```
VIEW
↓
Stores a SQL query
↓
Acts like a virtual table
```

Think of it like this:

```
Normal Table

┌─────────────────┐
│ Actual Data     │
│ Actual Data     │
│ Actual Data     │
└─────────────────┘
```

Whereas:

```
View

┌─────────────────┐
│ Saved SQL Query │
└─────────────────┘
        ↓
   Gets data from
   underlying tables
```

---

# 5. A Simple Analogy

Imagine you have a large spreadsheet with 50 columns.

You frequently need only:

```
Name
City
Age
```

Instead of manually selecting those columns every time, you create a saved view containing exactly what you need.

So:

```
Database Tables
       ↓
     VIEW
       ↓
Useful subset of data
```

The view is like a **window into the database**. 🪟

---

# 6. View With WHERE

A view doesn't have to contain a JOIN.

For example:

```
CREATE VIEW adult_students AS
SELECT id, name, age
FROM students
WHERE age >= 18;
```

Now:

```
SELECT *
FROM adult_students;
```

returns only students aged 18 or older.

The original `students` table is still there.

---

# 7. View With JOIN

Views are particularly useful for complicated queries.

For example:

```
CREATE VIEW student_orders AS
SELECT
    s.id,
    s.name,
    s.city,
    o.amount
FROM students s
JOIN orders o
ON s.id = o.student_id;
```

Now instead of repeatedly writing:

```
SELECT
    s.id,
    s.name,
    s.city,
    o.amount
FROM students s
JOIN orders o
ON s.id = o.student_id;
```

you can simply:

```
SELECT *
FROM student_orders;
```

Much cleaner.

---

# 8. View With GROUP BY

Views can also contain aggregation.

For example, suppose we want the total orders for every student:

```
CREATE VIEW student_order_totals AS
SELECT
    s.id,
    s.name,
    SUM(o.amount) AS total_amount
FROM students s
JOIN orders o
ON s.id = o.student_id
GROUP BY s.id, s.name;
```

Then:

```
SELECT *
FROM student_order_totals;
```

Result:

```
┌────┬───────┬──────────────┐
│ id │ name  │ total_amount │
├────┼───────┼──────────────┤
│ 1  │ Alice │ 800          │
│ 2  │ Bob   │ 800          │
└────┴───────┴──────────────┘
```

So a view can contain quite complex SQL.

---

# 9. View With ORDER BY

You can also define a view from a query containing `ORDER BY`, although you should not rely on a view having a particular output order when querying it.

For example:

```
CREATE VIEW expensive_orders AS
SELECT *
FROM orders
WHERE amount > 500;
```

Then when you want the results sorted:

```
SELECT *
FROM expensive_orders
ORDER BY amount DESC;
```

This is usually clearer because **the final query controls the ordering**.

---

# 10. Why Are Views Useful?

There are several important reasons.

### 1. Simplicity

A complicated query can be hidden behind a simple view.

Instead of:

```
SELECT ...
JOIN ...
ON ...
WHERE ...
GROUP BY ...
HAVING ...
```

you can use:

```
SELECT *
FROM some_view;
```

---

### 2. Reusability

If you use the same query frequently, create a view once.

Then reuse it:

```
SELECT *
FROM some_view;
```

---

### 3. Security

Views can expose only the columns users are supposed to see.

Suppose the table contains:

```
id
name
email
password_hash
salary
```

You might create:

```
CREATE VIEW public_students AS
SELECT id, name, email
FROM students;
```

Now the view doesn't expose:

```
password_hash
salary
```

This can help with data access control, although proper MySQL privileges are still important for real security.

---

### 4. Abstraction

Users or application code don't always need to know how the underlying tables are connected.

They can simply query:

```
SELECT *
FROM student_orders;
```

The complicated JOIN is hidden inside the view.

---

# 12. Viewing the View

You can query it:

```
SELECT *
FROM adult_students;
```

You can also see the SQL definition using:

```
SHOW CREATE VIEW adult_students;
```

This shows the query used to create the view.

---

# 13. Listing Views

To see information about views in the current database:

```
SHOW FULL TABLES
WHERE TABLE_TYPE = 'VIEW';
```

This can help you identify which objects are views.

---

# 14. Removing a View

If you no longer need a view:

```
DROP VIEW adult_students;
```

This removes the **view**, not the original table.

For safety, you can use:

```
DROP VIEW IF EXISTS adult_students;
```

Meaning:

> Delete the view if it exists.

---

# 15. Changing a View

You can modify a view using:

```
CREATE OR REPLACE VIEW view_name AS
SELECT ...;
```

Example:

```
CREATE OR REPLACE VIEW adult_students AS
SELECT id, name, age, city
FROM students
WHERE age >= 18;
```

Now the view has been updated to include `city`.

---

# 16. View vs Table

This is very important for your notes.

|Feature|Table|View|
|---|---|---|
|Stores actual data|✅|Usually ❌|
|Stores SQL definition|❌|✅|
|Can be queried with `SELECT`|✅|✅|
|Can contain JOIN|Data itself doesn't contain a JOIN|✅|
|Can simplify complex queries|❌|✅|
|Can help restrict exposed columns|Limited by itself|✅|
|Uses underlying table data|N/A|✅|

The key difference:

```
TABLE
→ Actual stored data

VIEW
→ Saved query that presents data
```

# 17. What Happens When Data Changes?

Suppose the view is:

```
CREATE VIEW adult_students AS
SELECT id, name, age
FROM students
WHERE age >= 18;
```

Initially:

```
Alice → 20
Bob   → 17
```

Query:

```
SELECT *
FROM adult_students;
```

Result:

```
Alice → 20
```

Now update Bob:

```
UPDATE students
SET age = 18
WHERE name = 'Bob';
```

Query the view again:

```
SELECT *
FROM adult_students;
```

Now Bob appears too:

```
Alice → 20
Bob   → 18
```

Why?

Because the view normally gets its data from the underlying table when queried.

The view isn't generally a frozen snapshot.

---

# 18. Can We INSERT/UPDATE/DELETE Through a View?

Sometimes, yes.

Some views are **updatable**, depending on how they are defined.

For example, a simple view based on one table may allow certain modifications.

But views containing things such as:

```
GROUP BY
DISTINCT
Aggregate functions
UNION
Certain JOINs
```

may not be updatable in the same way.

For your current level, remember:

> **Views are primarily used to read/present data. Whether a view can be modified depends on how the view was created.**

---

# 19. View Does Not Mean Copy

This is one of the biggest things to remember.

Suppose:

```
CREATE VIEW student_view AS
SELECT name, age
FROM students;
```

It does **not normally mean**:

```
students
    ↓
COPY EVERYTHING
    ↓
student_view
```

Instead, think:

```
student_view
     ↓
Saved SELECT query
     ↓
students
```

So the view acts as a window into the underlying data.

---

# 20. View vs Temporary Table

Don't confuse a view with a temporary table.

### View

```
Saved query
↓
Can be reused
↓
Usually remains until dropped
```

### Temporary table

```
Temporary stored data
↓
Exists for a limited session/lifetime
```

They solve different problems.

Suppose your database has:

```

```

The complexity is tucked behind the view.
