JSON is one of the most important concepts in REST APIs because it is the **common language used to exchange data between a client and a server**.

When your frontend sends data to a Flask API, it will often send JSON. When Flask sends data back, it will usually return JSON.

---

## 1. What is JSON?

**JSON** stands for **JavaScript Object Notation**.

It is a lightweight text-based format used to represent and exchange structured data.

Example:

```
{
    "name": "Rahul",
    "age": 21,
    "email": "rahul@example.com"
}
```

Although JSON originated from JavaScript, it is **language-independent**.

It can be used with:

- Python
- JavaScript
- Java
- C#
- PHP
- Go
- Ruby
- C++
- etc.

### Simple mental model

```
Frontend
   ↓
   JSON
   ↓
Flask API
   ↓
Python
   ↓
Database

Database
   ↓
Python
   ↓
   JSON
   ↓
Frontend
```

JSON acts like a **data envelope** travelling between systems. 📦

---

# 2. Why REST APIs Use JSON

REST APIs commonly use JSON because it is:

- Easy to read
- Easy to generate
- Easy to parse
- Lightweight
- Supported by almost every programming language
- Suitable for nested data
- Well suited for frontend/backend communication

For example, a frontend may request:

```
GET /api/users/10
```

The Flask server could respond:

```
{
    "id": 10,
    "name": "Rahul",
    "email": "rahul@example.com"
}
```

The frontend can easily process this data.

# 3. JSON Object

A JSON object is surrounded by:

```
{ }
```

It contains **key-value pairs**.

Example:

```
{
    "name": "Rahul",
    "age": 21,
    "city": "Kolkata"
}
```

Structure:

```
{
    "key": value
}
```

Multiple properties are separated using commas:

```
{
    "name": "Rahul",
    "age": 21,
    "city": "Kolkata"
}
```

---

# 4. JSON Keys

JSON object keys must use **double quotes**.

Correct:

```
{
    "name": "Rahul"
}
```

Incorrect:

```
{
    'name': 'Rahul'
}
```

Also incorrect:

```
{
    name: "Rahul"
}
```

### Important

JSON requires:

```
"double quotes"
```

not:

```
'single quotes'
```

# 5. JSON Data Types

JSON supports six main data types.

|Type|Example|
|---|---|
|String|`"Rahul"`|
|Number|`25`|
|Boolean|`true`|
|Null|`null`|
|Object|`{ "name": "Rahul" }`|
|Array|`[1, 2, 3]`|

---

## 5.1 String

Strings are written inside double quotes.

```
{
    "name": "Rahul"
}
```

---

## 5.2 Number

Numbers do not require quotes.

```
{
    "age": 21,
    "salary": 25000.50
}
```

If you write:

```
{
    "age": "21"
}
```

then `"21"` is a **string**, not a number.

---

## 5.3 Boolean

JSON uses:

```
true
```

and:

```
false
```

Example:

```
{
    "is_active": true
}
```

### Important

JSON uses lowercase:

```
true
false
null
```

Not Python's:

```
True
False
None
```

JSON uses `null` when a value is empty or unavailable.

```

    "phone": null

```

Python equivalent:

```
{
    "name": "Rahul",
    "phone": None

```

# 10. JSON vs Python Dictionary

JSON and Python dictionaries look very similar, but they are **not the same thing**.

### Python dictionary

```
user = {
    "name": "Rahul",
    "age": 21,
    "active": True
}
```

### JSON

```
{
    "name": "Rahul",
    "age": 21,
    "active": true
}
```

Notice:

```
Python          JSON
--------------------------
True       →    true
False      →    false
None       →    null
```

Also, JSON is a **text/data format**, while a Python dictionary is a Python object in memory.

---

# 11. JSON Serialization

**Serialization** means converting a programming-language object into a format that can be transmitted or stored.

For example:

```
Python dictionary
       ↓
    JSON
       ↓
 Network
```

Python's `json` module can perform this conversion.

```
import json

user = {
    "name": "Rahul",
    "age": 21
}

json_data = json.dumps(user)

print(json_data)
```

Output:

```
{"name": "Rahul", "age": 21}
```

`json.dumps()` converts a Python object into a JSON string.

---

# 12. JSON Deserialization

**Deserialization** is the opposite process.

```
JSON
 ↓
Python object
```

Example:

```
import json

json_data = '{"name": "Rahul", "age": 21}'

user = json.loads(json_data)

print(user)
```

Output:

```
{'name': 'Rahul', 'age': 21}
```

Now `user` is a Python dictionary.

### Remember

```
json.dumps()
```

means:

```
Python → JSON string
```

while:

```
json.loads()
```

means:

```
JSON string → Python object
```

# 13. JSON in Flask

Flask provides convenient tools for working with JSON.

The two most important are:

```
request.get_json()
```

and:

```
jsonify()
```

---

# 14. Receiving JSON in Flask

Suppose the client sends:

```
{
    "name": "Rahul",
    "age": 21
}
```

Flask can read it using:

```
from flask import Flask, request

app = Flask(__name__)

@app.post("/api/users")
def create_user():
    data = request.get_json()

    print(data)

    return {
        "message": "User received"
    }
```

The variable:

```
data
```

will contain approximately:

```
{
    "name": "Rahul",
    "age": 21
}
```

So you can access values:

```
name = data["name"]
age = data["age"]
```

---

# 15. `request.get_json()`

This is one of the most important Flask API functions.

```
data = request.get_json()
```

It reads the JSON body sent by the client.

For example:

```
@app.post("/api/users")
def create_user():
    data = request.get_json()

    name = data["name"]
    age = data["age"]

    return {
        "name": name,
        "age": age
    }
```

Request:

```
{
    "name": "Rahul",
    "age": 21
}
```

Response:

```
{
    "name": "Rahul",
    "age": 21
}
```

---

# 16. Safer JSON Access

Using:

```
data["name"]
```

can raise an error if `"name"` does not exist.

Instead, you can use:

```
data.get("name")
```

Example:

```
@app.post("/api/users")
def create_user():
    data = request.get_json()

    name = data.get("name")
    age = data.get("age")

    return {
        "name": name,
        "age": age
    }
```

This is often useful when validating API input.

---

# 17. Checking Missing JSON

A client might send no JSON body.

You can check:

```
data = request.get_json(silent=True)

if data is None:
    return {
        "error": "JSON body is required"
    }, 400
```

Here:

```
silent=True
```

prevents Flask from raising an exception for invalid JSON and lets you handle the situation yourself.

---

# 18. Sending JSON from Flask

Flask can return a Python dictionary:

```
@app.get("/api/user")
def get_user():
    return {
        "id": 1,
        "name": "Rahul"
    }
```

Modern Flask automatically converts dictionaries into JSON responses.

You can also explicitly use:

```
from flask import jsonify
```

Example:

```
@app.get("/api/user")
def get_user():
    return jsonify({
        "id": 1,
        "name": "Rahul"
    })
```

Both approaches are commonly used.

---

# 19. `jsonify()`

`jsonify()` converts Python data into a Flask JSON response.

Example:

```
from flask import jsonify

@app.get("/api/users")
def get_users():
    users = [
        {
            "id": 1,
            "name": "Rahul"
        },
        {
            "id": 2,
            "name": "Priya"
        }
    ]

    return jsonify(users)
```

Response:

```
[
    {
        "id": 1,
        "name": "Rahul"
    },
    {
        "id": 2,
        "name": "Priya"
    }
]
```

# 21. JSON with Status Codes

You can return JSON together with an HTTP status code.

Example:

```
from flask import jsonify

@app.post("/api/users")
def create_user():
    user = {
        "id": 1,
        "name": "Rahul"
    }

    return jsonify(user), 201
```

The response contains:

```
Status: 201 Created
```

and:

```
{
    "id": 1,
    "name": "Rahul"
}
```

Another example:

```
return jsonify({
    "error": "User not found"
}), 404
```

# 22. Request JSON vs Response JSON

This distinction is important.

### Request JSON

Data sent:

```
Client
   ↓
 JSON
   ↓
Flask
```

Flask reads it using:

```
request.get_json()
```

### Response JSON

Data returned:

```
Flask
   ↓
 JSON
   ↓
Client
```

Flask can create it using:

```
jsonify()
```

### Mental model

```
              HTTP Request
Client ─────────────────────────→ Flask
             JSON Body
                 ↓
        request.get_json()


              HTTP Response
Client ←───────────────────────── Flask
             JSON Body
                 ↑
             jsonify()
```

# 23. Content-Type Header

When sending JSON, the request normally includes:

```
Content-Type: application/json
```

This tells the server:

> "The body contains JSON data."

Example HTTP request:

```
POST /api/users HTTP/1.1
Content-Type: application/json

{
    "name": "Rahul",
    "age": 21
}
```

The important part is:

```
Content-Type: application/json
```

# 24. Sending JSON from JavaScript

A frontend can send JSON using `fetch()`.

```
fetch("/api/users", {
    method: "POST",
    headers: {
        "Content-Type": "application/json"
    },
    body: JSON.stringify({
        name: "Rahul",
        age: 21
    })
});
```

Notice:

```
JSON.stringify()
```

converts the JavaScript object into JSON text.

# 25. Receiving JSON in JavaScript

Suppose Flask returns:

```
{
    "id": 1,
    "name": "Rahul"
}
```

JavaScript can read it:

```
fetch("/api/users/1")
    .then(response => response.json())
    .then(data => {
        console.log(data.name);
```

Here:

```
response.json()
```

parses the JSON response.

# 26. JSON Serialization Flow

The complete process looks like this:

```
JavaScript Object
       ↓
JSON.stringify()
       ↓
JSON Text
       ↓
HTTP Request
       ↓
Flask
       ↓
request.get_json()
       ↓
Python Dictionary
```

Response:

```

       ↓

       ↓
JSON
       ↓
HTTP Response
       ↓
response.json()
       ↓

```

This is the heart of frontend-backend communication. 🔄

# 27. JSON and SQLAlchemy Models

One important issue appears when using SQLAlchemy.

Suppose:

```
user = User.query.first()
```

You generally should **not** do:

```
return jsonify(user)
```

because a SQLAlchemy model instance is not automatically a JSON-serializable dictionary.

Instead, convert the required fields:

```
return jsonify({
    "id": user.id,
    "name": user.name,
    "email": user.email
})
```

This also gives you control over **which data is exposed**.

For example, you should not accidentally expose:

```
password_hash
```

in an API response.

---

# 28. Converting Multiple Database Records

Suppose:

```
users = User.query.all()
```

You can create a list:

```
data = []

for user in users:
    data.append({
        "id": user.id,
        "name": user.name,
        "email": user.email
    })

return jsonify(data)
```

Response:

```
[
    {
        "id": 1,
        "name": "Rahul",
        "email": "rahul@example.com"
    },
    {
        "id": 2,
        "name": "Priya",
        "email": "priya@example.com"
    }
]
```

Later, when building larger applications, serialization libraries or schema tools can make this cleaner.

# 33. Complete Flask JSON Example

```
from flask import Flask, request, jsonify

app = Flask(__name__)


@app.post("/api/users")
def create_user():
    data = request.get_json(silent=True)

    if data is None:
        return jsonify({
            "error": "JSON body is required"
        }), 400

    name = data.get("name")
    age = data.get("age")

    if not name or age is None:
        return jsonify({
            "error": "name and age are required"
        }), 400

    user = {
        "id": 1,
        "name": name,
        "age": age
    }

    return jsonify(user), 201


@app.get("/api/users/1")
def get_user():
    user = {
        "id": 1,
        "name": "Rahul",
        "age": 21
    }

    return jsonify(user), 200


if __name__ == "__main__":
    app.run(debug=True)
```

### POST request

```
{
    "name": "Rahul",
    "age": 21
}
```

### Response

```
{
    "id": 1,
    "name": "Rahul",
    "age": 21
}
```

with:

```
201 Created
```

# 36. JSON in a REST API

A typical REST API might look like:

```
GET /api/users
        ↓
JSON array


GET /api/users/10
        ↓
JSON object


POST /api/users
        ↓
JSON request
        ↓
JSON response


PUT /api/users/10
        ↓
JSON request
        ↓
JSON response


DELETE /api/users/10
        ↓
JSON response
```

JSON is therefore the **data format**, while HTTP methods describe **what operation is being performed**.

This distinction is important:

```
HTTP
 ↓
How we communicate

JSON
 ↓
How we represent the data
```

# 37. JSON Best Practices

### 1. Use meaningful property names

Prefer:

```
{
    "first_name": "Rahul"
}
```

over:

```
{
    "x": "Rahul"
}
```

### 2. Keep response structures consistent

For example:

```
{
    "id": 1,
    "name": "Rahul"
}
```

Keep the same naming style throughout your API.

### 3. Don't expose sensitive information

Avoid returning:

```
{
    "password_hash": "..."
}
```

### 4. Use appropriate data types

If age is a number:

```
{
    "age": 21
}
```

not unnecessarily:

```
{
    "age": "21"
}
```

### 5. Validate incoming JSON

Never assume the client sent correct data.

```
data = request.get_json(silent=True)

if data is None:
    return jsonify({
        "error": "Invalid JSON"
    }), 400
```

### 6. Keep API responses predictable

Clients should know what structure to expect.
