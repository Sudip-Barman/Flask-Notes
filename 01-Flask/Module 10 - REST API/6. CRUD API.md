**CRUD** is one of the most important patterns in REST API development.

CRUD stands for:

```
C → Create
R → Read
U → Update
D → Delete
```

Almost every application that stores data needs these four operations.

For example, a product management system might need to:

```
Create a product
Read products
Update a product
Delete a product
```

A REST API maps these operations to HTTP methods.

---

# 1. CRUD and HTTP Methods

The standard mapping is:

|CRUD|Operation|HTTP Method|
|---|---|---|
|Create|Add new data|POST|
|Read|Get data|GET|
|Update|Modify data|PUT / PATCH|
|Delete|Remove data|DELETE|

So:

```
Create → POST
Read   → GET
Update → PUT / PATCH
Delete → DELETE
```

Example for a `users` resource:

```
POST   /api/users
GET    /api/users
GET    /api/users/10
PUT    /api/users/10
PATCH  /api/users/10
DELETE /api/users/10
```

---

# 2. CRUD API Architecture

A typical CRUD API works like this:

```
Client
  │
  │ HTTP Request
  ▼
Flask Route
  │
  ▼
Request Validation
  │
  ▼
Business Logic
  │
  ▼
SQLAlchemy
  │
  ▼
Database
  │
  ▼
JSON Response
  │
  ▼
Client
```

The API is the bridge between the client and the database.

# 3. Example Database Model

Let's use a simple `Product` model.

```
from flask_sqlalchemy import SQLAlchemy

db = SQLAlchemy()


class Product(db.Model):
    __tablename__ = "products"

    id = db.Column(
        db.Integer,
        primary_key=True
    )

    name = db.Column(
        db.String(100),
        nullable=False
    )

    price = db.Column(
        db.Float,
        nullable=False
    )
```

The database table might look like:

|id|name|price|
|---|---|---|
|1|Keyboard|1200|
|2|Mouse|700|
|3|Monitor|8500|

Now we can build CRUD endpoints around this model.

# 4. Create

**Create** means adding a new record.

REST uses:

```
POST /api/products
```

The client might send:

```
{
    "name": "Keyboard",
    "price": 1200
}
```

Flask receives the JSON:

```
data = request.get_json()
```

Then creates the database object:

```
product = Product(
    name=data.get("name"),
    price=data.get("price")
)
```

Then:

```
db.session.add(product)
db.session.commit()
```

---

# 5. Create Endpoint

Complete example:

```
from flask import request, jsonify

@app.post("/api/products")
def create_product():

    data = request.get_json(silent=True)

    if data is None:
        return jsonify({
            "error": "JSON body is required"
        }), 400

    name = data.get("name")
    price = data.get("price")

    if not name or price is None:
        return jsonify({
            "error": "name and price are required"
        }), 400

    product = Product(
        name=name,
        price=price
    )

    db.session.add(product)
    db.session.commit()

    return jsonify({
        "id": product.id,
        "name": product.name,
        "price": product.price
    }), 201
```

# 8. Read All Products

SQLAlchemy:

```
products = Product.query.all()
```

Then convert them to JSON:

```
data = []

for product in products:
    data.append({
        "id": product.id,
        "name": product.name,
        "price": product.price
    })
```

Complete endpoint:

```
@app.get("/api/products")
def get_products():

    products = Product.query.all()

    data = []

    for product in products:
        data.append({
            "id": product.id,
            "name": product.name,
            "price": product.price
        })

    return jsonify(data), 200
```

Response:

```
[
    {
        "id": 1,
        "name": "Keyboard",
        "price": 1200
    },
    {
        "id": 2,
        "name": "Mouse",
        "price": 700
    }
]
```

# 9. Read One Product

Endpoint:

```
GET /api/products/10
```

Flask:

```
@app.get("/api/products/<int:product_id>")
def get_product(product_id):

    product = db.session.get(
        Product,
        product_id
    )

    if product is None:
        return jsonify({
            "error": "Product not found"
        }), 404

    return jsonify({
        "id": product.id,
        "name": product.name,
        "price": product.price
    }), 200
```

---

# 10. Why Check for `None`?

Suppose the client requests:

```
/api/products/9999
```

but product `9999` doesn't exist.

This:

```
product = db.session.get(Product, product_id)
```

may return:

```
None
```

If you then do:

```
product.name
```

you'll get an error.

So check first:

```
if product is None:
    return jsonify({
        "error": "Product not found"
    }), 404
```

# 11. Update

Update means modifying existing data.

REST commonly uses:

```
PUT
PATCH
```

For example:

```
PATCH /api/products/10
```

Request:

```
{
    "price": 1500
}
```

The API updates product `10`.

---

# 12. PATCH Update

A PATCH request normally updates **only the fields provided**.

Example existing product:

```
{
    "id": 10,
    "name": "Keyboard",
    "price": 1200
}
```

Client sends:

```
{
    "price": 1500
}
```

After update:

```
{
    "id": 10,
    "name": "Keyboard",
    "price": 1500
}
```

The name remains unchanged.

---

# 13. PATCH Endpoint

```
@app.patch("/api/products/<int:product_id>")
def update_product(product_id):

    product = db.session.get(
        Product,
        product_id
    )

    if product is None:
        return jsonify({
            "error": "Product not found"
        }), 404

    data = request.get_json(silent=True)

    if data is None:
        return jsonify({
            "error": "JSON body is required"
        }), 400

    if "name" in data:
        product.name = data["name"]

    if "price" in data:
        product.price = data["price"]

    db.session.commit()

    return jsonify({
        "id": product.id,
        "name": product.name,
        "price": product.price
    }), 200
```

---

# 14. Why Check `"name" in data`?

Suppose the request is:

```
{
    "price": 1500
}
```

If you use:

```
name = data.get("name")
```

you get:

```
None
```

If you then assign:

```
product.name = None
```

you could violate:

```
nullable=False
```

Instead:

```
if "name" in data:
    product.name = data["name"]
```

means:

> Only update `name` if the client actually sent it.

That's the essence of a partial update.

---

# 15. PUT vs PATCH in CRUD

### PUT

Generally represents replacing the resource representation.

Example:

```
PUT /api/products/10
```

```
{
    "name": "Keyboard",
    "price": 1500
}
```

### PATCH

Generally represents partial modification.

```
PATCH /api/products/10
```

```
{
    "price": 1500
}
```

Easy memory:

```
PUT
 ↓
Replace

PATCH
 ↓
Partially modify
```

Exact behavior should be documented by your API.

# 16. Delete

Delete means removing a resource.

Endpoint:

```
DELETE /api/products/10
```

Flask:

```
@app.delete("/api/products/<int:product_id>")
def delete_product(product_id):

    product = db.session.get(
        Product,
        product_id
    )

    if product is None:
        return jsonify({
            "error": "Product not found"
        }), 404

    db.session.delete(product)
    db.session.commit()

    return jsonify({
        "message": "Product deleted"
    }), 200
```

---

# 17. DELETE Response

You could return:

```
{
    "message": "Product deleted"
}
```

with:

```
200 OK
```

Or return:

```
204 No Content
```

Example:

```
db.session.delete(product)
db.session.commit()

return "", 204
```

A `204` response means the operation succeeded and there is no response body.

app.config["SQLALCHEMY_DATABASE_URI"] = (

    id = db.Column(
        db.Integer,

    name = db.Column(
        db.String(100),

        db.Float,
        nullable=False

# CREATE

def create_product():

# 21. CRUD with Database Transactions

Every database-changing operation should be handled carefully.

For example:

```
db.session.add(product)

try:
    db.session.commit()
except Exception:
    db.session.rollback()
    raise
```

Why?

Because something could go wrong during the database operation.

Without rollback, the SQLAlchemy session could remain in a failed transaction state.

A more robust create operation:

```
try:
    db.session.add(product)
    db.session.commit()

except Exception:
    db.session.rollback()

    return jsonify({
        "error": "Could not create product"
    }), 500
```

Later, we'll study better error handling in:

**10.10 Error Handling**

# 22. CRUD and HTTP Status Codes

A good CRUD API uses meaningful status codes.

|Operation|Success|
|---|---|
|Create|`201 Created`|
|Read|`200 OK`|
|Update|`200 OK`|
|Update with no body|`204 No Content`|
|Delete|`200 OK` or `204 No Content`|

Errors:

|Situation|Status|
|---|---|
|Invalid request|`400`|
|Authentication required|`401`|
|Permission denied|`403`|
|Resource not found|`404`|
|Duplicate/conflict|`409`|
|Validation failure|`422`|

# 26. Important Difference: CRUD vs REST

CRUD and REST are related, but they are **not the same thing**.

### CRUD

Describes data operations:

```
Create
Read
Update
Delete
```

### REST

Describes an architectural style for APIs.

REST commonly maps CRUD operations to HTTP methods:

```
CRUD             HTTP
----------------------
Create    →      POST
Read      →      GET
Update    →      PUT/PATCH
Delete    →      DELETE
```

So CRUD is an **operation model**, while REST provides a common way to expose those operations over HTTP.

# 27. Common CRUD API Mistakes

### ❌ 1. Using POST for every operation

Bad:

```
POST /api/createProduct
POST /api/getProducts
POST /api/deleteProduct
```

Better:

```
POST   /api/products
GET    /api/products
DELETE /api/products/10
```

---

### ❌ 2. Returning 200 for everything

Don't use:

```
200 OK
```

for every situation.

For creation:

```
201 Created
```

For missing resource:

```
404 Not Found
```

For invalid input:

```
400 Bad Request
```

---

### ❌ 3. Not checking if the resource exists

Bad:

```
product = db.session.get(Product, product_id)

db.session.delete(product)
```

Better:

```
if product is None:
    return jsonify({
        "error": "Product not found"
    }), 404
```

---

### ❌ 4. Updating fields blindly

Bad:

```
product.name = data.get("name")
product.price = data.get("price")
```

For PATCH, this can unintentionally replace missing values with `None`.

Better:

```
if "name" in data:
    product.name = data["name"]

if "price" in data:
    product.price = data["price"]
```

---

### ❌ 5. Returning database objects directly

Avoid:

```
return jsonify(product)
```

Instead serialize the fields you want to expose:

```
return jsonify({
    "id": product.id,
    "name": product.name,
    "price": product.price
})
```

---

### ❌ 6. Forgetting `commit()`

This:

```
db.session.add(product)
```

does not permanently save the transaction.

Usually you need:

```
db.session.commit()
```

Similarly:

```
product.price = 1500
db.session.commit()
```

and:

```
db.session.delete(product)
db.session.commit()
```
