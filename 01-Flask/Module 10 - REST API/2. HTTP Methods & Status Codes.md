HTTP is the communication protocol used between a client and a server.

When a client communicates with a Flask REST API, it sends an **HTTP request**. Flask processes it and sends an **HTTP response**.

```
Client
   ↓
HTTP Request
   ↓
Flask API
   ↓
HTTP Response
   ↓
Client
```

Two important parts of this communication are:

1. **HTTP Methods**: What action the client wants to perform
2. **HTTP Status Codes**: What happened when the server processed the request

---

# 1. What is an HTTP Method?

An HTTP method tells the server what the client wants to do with a resource.

For REST APIs, the most important methods are:

```
GET
POST
PUT
PATCH
DELETE
```

Think of them as actions:

```
GET     → Give me something
POST    → Create something
PUT     → Replace something
PATCH   → Change part of something
DELETE  → Remove something
```

---

# 2. GET 📖

`GET` is used to **retrieve/read data**.

Example:

```
GET /api/users
```

Meaning:

> Give me the users.

Flask:

```
@app.route("/api/users", methods=["GET"])
def get_users():
    return jsonify(users)
```

---

## Get One Resource

```
GET /api/users/10
```

Meaning:

> Give me user 10.

Flask:

```
@app.route("/api/users/<int:user_id>", methods=["GET"])
def get_user(user_id):

    user = db.session.get(User, user_id)

    if user is None:
        return jsonify({
            "error": "User not found"
        }), 404

    return jsonify({
        "id": user.id,
        "name": user.name
    })
```

---

## GET Should Not Modify Data

A GET request should normally only read data.

Avoid doing something like:

```
@app.route("/api/users")
def users():
    User.query.delete()
```

That's a completely inappropriate use of GET.

The expected idea is:

```
GET
 ↓
Read
 ↓
No database modification
```

---

# 3. POST ➕

`POST` is generally used to **create a new resource**.

Example:

```
POST /api/users
```

Request body:

```
{
    "name": "Rahul",
    "email": "rahul@example.com"
}
```

Flask:

```
@app.route("/api/users", methods=["POST"])
def create_user():

    data = request.get_json()

    user = User(
        name=data.get("name"),
        email=data.get("email")
    )

    db.session.add(user)
    db.session.commit()

    return jsonify({
        "id": user.id,
        "name": user.name,
        "email": user.email
    }), 201
```

The important point is:

```
POST /api/users
        ↓
Create a new user
```

---

# 4. PUT 🔄

`PUT` is generally used to **replace an existing resource**.

Example:

```
PUT /api/users/10
```

Request:

```
{
    "name": "Rahul Kumar",
    "email": "rahulkumar@example.com"
}
```

Conceptually:

```
Old user
   ↓
Completely replaced
   ↓
New representation
```

For example:

```
@app.route("/api/users/<int:user_id>", methods=["PUT"])
def update_user(user_id):

    user = db.session.get(User, user_id)

    if user is None:
        return jsonify({
            "error": "User not found"
        }), 404

    data = request.get_json()

    user.name = data.get("name")
    user.email = data.get("email")

    db.session.commit()

    return jsonify({
        "message": "User updated successfully"
    })
```

---

# 5. PATCH 🩹

`PATCH` is used for a **partial update**.

Suppose the existing user is:

```
{
    "id": 10,
    "name": "Rahul",
    "email": "rahul@example.com",
    "age": 21
}
```

You only want to change the name.

Request:

```
PATCH /api/users/10
```

Body:

```
{
    "name": "Rahul Kumar"
}
```

Only the name changes.

```
name → changed
email → unchanged
age → unchanged
```

Example:

```
@app.route("/api/users/<int:user_id>", methods=["PATCH"])
def patch_user(user_id):

    user = db.session.get(User, user_id)

    if user is None:
        return jsonify({
            "error": "User not found"
        }), 404

    data = request.get_json()

    if "name" in data:
        user.name = data["name"]

    if "email" in data:
        user.email = data["email"]

    db.session.commit()

    return jsonify({
        "message": "User updated successfully"
    })
```

---

# 6. PUT vs PATCH

This is a common interview question.

|Method|Meaning|
|---|---|
|`PUT`|Replace/update the resource representation|
|`PATCH`|Partially update the resource|

Example:

Existing:

```
{
    "name": "Rahul",
    "email": "rahul@example.com",
    "age": 21
}
```

### PUT

Conceptually sends the complete representation:

```
{
    "name": "Rahul Kumar",
    "email": "rahulkumar@example.com",
    "age": 22
}
```

### PATCH

Only changes what is needed:

```
{
    "age": 22
}
```

Mental shortcut:

```
PUT   → Replace
PATCH → Modify part
```

In real-world APIs, the exact PUT semantics should be documented by that API, but this is the standard REST distinction to learn.

---

# 7. DELETE 🗑️

`DELETE` is used to remove a resource.

Example:

```
DELETE /api/users/10
```

Flask:

```
@app.route("/api/users/<int:user_id>", methods=["DELETE"])
def delete_user(user_id):

    user = db.session.get(User, user_id)

    if user is None:
        return jsonify({
            "error": "User not found"
        }), 404

    db.session.delete(user)
    db.session.commit()

    return jsonify({
        "message": "User deleted successfully"
    })
```

Flow:

```
DELETE /api/users/10
        ↓
Find user 10
        ↓
Delete user
        ↓
Commit transaction
        ↓
Return response
```

# 8. HTTP Methods and CRUD

Now connect HTTP methods with CRUD.

|CRUD|HTTP Method|
|---|---|
|Create|POST|
|Read|GET|
|Update|PUT / PATCH|
|Delete|DELETE|

The standard REST pattern becomes:

```
POST   /api/users
       ↓
Create user

GET    /api/users
       ↓
Get users

GET    /api/users/10
       ↓
Get user 10

PUT    /api/users/10
       ↓
Replace user 10

PATCH  /api/users/10
       ↓
Partially update user 10

DELETE /api/users/10
       ↓
Delete user 10
```

This is one of the most important patterns in REST API development.

# 9. What is an HTTP Status Code?

After processing a request, the server sends a **status code**.

Example:

```
HTTP/1.1 200 OK
```

The number tells the client what happened.

Status codes are divided into five major categories:

```
1xx → Informational
2xx → Success
3xx → Redirection
4xx → Client Error
5xx → Server Error
```

For Flask REST API development, **2xx, 4xx, and 5xx** are the most important.

---

# 10. 1xx Informational

These indicate that the request has been received and the process is continuing.

Examples:

```
100 Continue
101 Switching Protocols
```

You won't normally use these directly in everyday Flask API development.

---

# 11. 2xx Success ✅

`2xx` means the request was successfully processed.

Important ones:

```
200 OK
201 Created
202 Accepted
204 No Content
```

---

## 11.1 200 OK

The request succeeded.

Example:

```
GET /api/users
```

Response:

```
200 OK
```

Flask:

```
return jsonify(users), 200
```

You can often omit `200` because Flask will use it by default:

```
return jsonify(users)
```

---

# 12. 201 Created

Used when a new resource has been successfully created.

Example:

```
POST /api/users
```

Response:

```
201 Created
```

Flask:

```
return jsonify({
    "message": "User created"
}), 201
```

Mental shortcut:

```
POST + successfully created
        ↓
       201
```

---

# 13. 202 Accepted

`202 Accepted` means the server accepted the request for processing, but the work may not have completed yet.

This is useful for asynchronous/background operations.

Example:

```
POST /api/reports/generate
        ↓
Large report generation starts
        ↓
202 Accepted
```

The report might still be processing.

For normal CRUD operations, you'll use `200` or `201` much more often.

---

# 14. 204 No Content

`204 No Content` means:

> The operation succeeded, but there is no response body to return.

Example:

```
DELETE /api/users/10
```

Response:

```
204 No Content
```

Flask:

```
return "", 204
```

You could use `204` for a successful delete when you don't need to return a message.

---

# 15. 3xx Redirection 🔀

`3xx` status codes indicate that the client needs to follow a redirection or use cached information.

Examples:

```
301 Moved Permanently
302 Found
304 Not Modified
```

These are more common with traditional web navigation and caching than with basic REST CRUD APIs.

---

# 16. 4xx Client Errors ⚠️

`4xx` means there is a problem with the request or the client's authorization.

Important ones:

```
400 Bad Request
401 Unauthorized
403 Forbidden
404 Not Found
409 Conflict
422 Unprocessable Content
```

These are extremely important for API development.

---

# 17. 400 Bad Request

Used when the request is invalid or malformed.

Example:

```
{
    "name": ""
}
```

If the API requires a name:

```
if not data.get("name"):
    return jsonify({
        "error": "Name is required"
    }), 400
```

Response:

```
{
    "error": "Name is required"
}
```

Think:

```
Request is invalid
        ↓
       400
```

---

# 18. 401 Unauthorized 🔐

`401` means the request requires valid authentication credentials, or the supplied credentials are invalid.

Example:

```
GET /api/profile
```

without a valid token.

Response:

```
{
    "error": "Authentication required"
}
```

Status:

```
401 Unauthorized
```

This connects directly with your authentication and JWT topics.

```
No valid authentication
        ↓
       401
```

---

# 19. 403 Forbidden 🚫

`403` means:

> The server understands who you are, but you are not allowed to perform this action.

Example:

```
User = Staff
Permission = users.delete ❌
```

Response:

```
{
    "error": "Permission denied"
}
```

Status:

```
403 Forbidden
```

Remember:

```
401 → Authentication problem
403 → Authorization/permission problem
```

---

# 20. 404 Not Found 🔎

Used when the requested resource doesn't exist.

Example:

```
GET /api/users/9999
```

If user `9999` doesn't exist:

```
return jsonify({
    "error": "User not found"
}), 404
```

Mental shortcut:

```
Resource doesn't exist
        ↓
       404
```

---

# 21. 409 Conflict

`409` is used when a request conflicts with the current state of the resource.

A common example is duplicate email registration.

Suppose:

```
rahul@example.com
```

already exists.

A new request attempts:

```
{
    "email": "rahul@example.com"
}
```

Response:

```
{
    "error": "Email already exists"
}
```

Status:

```
409 Conflict
```

---

# 22. 422 Unprocessable Content

`422` is commonly used when the request has a valid structure but the submitted data fails validation.

Example:

```
{
    "age": -5
}
```

The JSON itself is valid, but the value doesn't satisfy the application's rules.

Response:

```
{
    "error": "Age must be greater than 0"
}
```

Status:

```
422
```

You'll encounter `422` frequently with API frameworks and validation libraries.

For simple Flask applications, `400` is also commonly used for validation failures. The important thing is to choose a convention and use it consistently.

---

# 23. 5xx Server Errors 💥

`5xx` means the server failed to successfully process an otherwise valid request.

Important:

```
500 Internal Server Error
502 Bad Gateway
503 Service Unavailable
504 Gateway Timeout
```

For your Flask applications, the most important is:

```
500 Internal Server Error
```

Example:

```
return jsonify({
    "error": "Internal server error"
}), 500
```

But you generally shouldn't manually return `500` for every exception. Unexpected exceptions should be handled properly and logged.

# 27. Flask Route Syntax

Flask allows you to specify methods:

```
@app.route(
    "/api/users",
    methods=["GET"]
)
def get_users():
    ...
```

Multiple methods:

```
@app.route(
    "/api/users",
    methods=["GET", "POST"]
)
def users():
    ...
```

Or you can use separate routes, which is often cleaner:

```
@app.get("/api/users")
def get_users():
    ...


@app.post("/api/users")
def create_user():
    ...
```

Similarly:

```
@app.put("/api/users/<int:user_id>")
def replace_user(user_id):
    ...


@app.patch("/api/users/<int:user_id>")
def update_user(user_id):
    ...


@app.delete("/api/users/<int:user_id>")
def delete_user(user_id):
    ...
```

These decorators are Flask's convenient HTTP-method-specific route syntax.

# 28. Safe and Idempotent Methods

These are useful concepts to know.

### Safe

A safe method should not intentionally modify server state.

`GET` is considered safe.

```
GET → Read
```

### Idempotent

An operation is idempotent when making the same request multiple times has the same intended final effect as making it once.

Commonly:

```
GET     → Idempotent
PUT     → Idempotent
DELETE  → Idempotent
```

`POST` is generally **not** idempotent.

For example:

```
POST /api/orders
```

called twice could create two orders.

Whereas:

```
DELETE /api/users/10
```

called multiple times should leave user 10 deleted, although subsequent calls may return `404`.

Don't worry about memorizing the terminology immediately. Understand the behavior.

# 29. A Complete Request Example

Imagine a client wants to create a product.

### Request

```
POST /api/products
Content-Type: application/json
```

Body:

```
{
    "name": "Laptop",
    "price": 55000
}
```

Flask:

```
@app.post("/api/products")
def create_product():

    data = request.get_json()

    if not data.get("name"):
        return jsonify({
            "error": "Name is required"
        }), 400

    product = Product(
        name=data["name"],
        price=data["price"]
    )

    db.session.add(product)
    db.session.commit()

    return jsonify({
        "id": product.id,
        "name": product.name,
        "price": product.price
    }), 201
```

Response:

```
HTTP/1.1 201 Created
Content-Type: application/json
```

```
{
    "id": 10,
    "name": "Laptop",
    "price": 55000
}
```

Notice the complete chain:

```
HTTP Method
     ↓
POST
     ↓
Endpoint
     ↓
/api/products
     ↓
JSON Request
     ↓
Validation
     ↓
Database
     ↓
JSON Response
     ↓
Status Code 201
```

# 30. Common Beginner Mistakes

### ❌ Using GET to delete data

```
GET /api/deleteUser/10
```

Prefer:

```
DELETE /api/users/10
```

---

### ❌ Using POST for everything

You technically can create APIs that use POST everywhere, but it makes the API less predictable and doesn't follow normal REST conventions.

Prefer the appropriate method.

---

### ❌ Returning 200 for every error

Don't do:

```
return jsonify({
    "error": "User not found"
}), 200
```

Use:

```
return jsonify({
    "error": "User not found"
}), 404
```

The status code communicates important information to the client.

---

### ❌ Confusing 401 and 403

Remember:

```
401 → You aren't properly authenticated
403 → You are authenticated, but aren't allowed
```

---

### ❌ Returning 500 for user mistakes

If the user sends invalid data:

```
400 / 422
```

not:

```
500
```

`500` generally indicates an unexpected server-side failure.

# 31. Mental Model 🧠

Think of an API request as:

```
METHOD + URL + DATA
```

For example:

```
POST + /api/users + JSON
```

The server then returns:

```
STATUS CODE + RESPONSE DATA
```

For example:

```
201 + JSON
```

So:

```
┌─────────────────────────────┐
│        HTTP REQUEST         │
│                             │
│ Method: POST                │
│ URL: /api/users             │
│ Body: JSON                  │
└──────────────┬──────────────┘
               ↓
          Flask API
               ↓
          Process Request
               ↓
┌──────────────┴──────────────┐
│        HTTP RESPONSE        │
│                             │
│ Status: 201 Created         │
│ Body: JSON                  │
└─────────────────────────────┘
```
