When a client sends a request to a Flask REST API, the server often needs to **read data from that request**.

For example, a frontend might send:

- A user ID
- Search text
- Form fields
- JSON data
- HTTP headers
- Authentication tokens
- Files

Flask provides different ways to access each type of request data.

The most important tools are:

```
request.args
request.form
request.get_json()
request.files
request.headers
request.cookies
request.view_args
```

Understanding **where each type of data comes from** is essential when building APIs.

---

# 1. What is Request Data?

**Request data** is information sent by the client to the server as part of an HTTP request.

For example:

```
Client
   │
   │  GET /api/products?category=books
   │
   ▼
Flask
```

Here:

```
category=books
```

is request data.

Another request:

```
POST /api/users
Content-Type: application/json

{
    "name": "Rahul",
    "age": 21
}
```

The JSON body is also request data.

---

# 2. Where Can Request Data Come From?

A request can carry data in several places:

```
HTTP Request
│
├── URL Path
│     └── /users/10
│
├── Query String
│     └── ?page=2
│
├── Form Data
│     └── name=Rahul
│
├── JSON Body
│     └── {"name": "Rahul"}
│
├── Headers
│     └── Authorization: Bearer ...
│
├── Cookies
│     └── session=...
│
└── Files
      └── profile.jpg
```

Flask has a different way to access each one.

# 3. The Flask `request` Object

First import:

```
from flask import request
```

The `request` object contains information about the **current HTTP request**.

For example:

```
@app.get("/api/users")
def get_users():
    print(request.method)
    print(request.path)

    return {
        "message": "Request received"
    }
```

Common properties include:

```
request.method
request.path
request.args
request.form
request.headers
request.cookies
request.files
request.get_json()
```

---

# 4. Path Parameters

Path parameters are values embedded directly into the URL.

Example:

```
/api/users/10
```

Here:

```
10
```

is the user ID.

Flask route:

```
@app.get("/api/users/<int:user_id>")
def get_user(user_id):
    return {
        "user_id": user_id
    }
```

Request:

```
GET /api/users/10
```

Flask receives:

```
user_id = 10
```

### Important

Path parameters are accessed directly through the function arguments.

```
def get_user(user_id):
```

You don't use:

```
request.args
```

for path parameters.

---

# 5. Query Parameters

Query parameters appear after `?` in a URL.

Example:

```
/api/products?category=books
```

Here:

```
category=books
```

is a query parameter.

Flask accesses query parameters using:

```
request.args
```

Example:

```
from flask import Flask, request

@app.get("/api/products")
def get_products():
    category = request.args.get("category")

    return {
        "category": category
    }
```

Request:

```
/api/products?category=books
```

Response:

```
{
    "category": "books"
}
```

---

# 6. Multiple Query Parameters

Example:

```
/api/products?category=books&page=2&limit=20
```

Flask:

```
@app.get("/api/products")
def get_products():
    category = request.args.get("category")
    page = request.args.get("page")
    limit = request.args.get("limit")

    return {
        "category": category,
        "page": page,
        "limit": limit
    }
```

Result:

```
{
    "category": "books",
    "page": "2",
    "limit": "20"
}
```

Notice something important:

> Query parameters are received as strings by default.

---

# 7. Converting Query Parameters

Suppose:

```
/api/products?page=2
```

Then:

```
page = request.args.get("page")
```

usually gives:

```
"2"
```

not:

```
2
```

You can convert it:

```
page = request.args.get("page", type=int)
```

Now:

```
page = 2
```

This is very useful for pagination.

---

# 8. Default Query Values

You can provide a default value.

```
page = request.args.get("page", default=1, type=int)
```

If the client sends:

```
/api/products
```

then:

```
page = 1
```

If the client sends:

```
/api/products?page=3
```

then:

```
page = 3
```

This makes API endpoints more robust.

---

# 9. Form Data

Form data is commonly used when submitting HTML forms.

Example request:

```
POST /register
Content-Type: application/x-www-form-urlencoded

name=Rahul&email=rahul@example.com
```

Flask accesses it using:

```
request.form
```

Example:

```
@app.post("/register")
def register():
    name = request.form.get("name")
    email = request.form.get("email")

    return {
        "name": name,
        "email": email
    }
```

---

# 10. `request.form.get()`

Prefer:

```
request.form.get("name")
```

over:

```
request.form["name"]
```

when the field might be missing.

For example:

```
name = request.form.get("name")
```

If the field doesn't exist, it returns:

```
None
```

rather than immediately raising a `BadRequestKeyError`.

---

# 11. JSON Request Data

REST APIs commonly receive JSON.

Request:

```
POST /api/users
Content-Type: application/json

{
    "name": "Rahul",
    "age": 21
}
```

Flask:

```
data = request.get_json()
```

Then:

```
name = data.get("name")
age = data.get("age")
```

Complete example:

```
@app.post("/api/users")
def create_user():
    data = request.get_json()

    name = data.get("name")
    age = data.get("age")

    return {
        "name": name,
        "age": age
    }
```

---

# 12. Safer JSON Reading

A client might send:

- No JSON
- Invalid JSON
- The wrong content type

You can use:

```
data = request.get_json(silent=True)
```

Then:

```
if data is None:
    return {
        "error": "Valid JSON is required"
    }, 400
```

This lets your API handle bad input gracefully.

---

# 13. JSON vs Form Data

These are different.

### Form data

```
name=Rahul&age=21
```

Flask:

```
request.form.get("name")
```

### JSON

```
{
    "name": "Rahul",
    "age": 21
}
```

Flask:

```
request.get_json()
```

Remember:

```
Form
 ↓
request.form

JSON
 ↓
request.get_json()
```

# 14. Request Headers

HTTP headers contain additional information about the request.

Example:

```
Authorization: Bearer abc123
Content-Type: application/json
Accept: application/json
```

Flask:

```
request.headers
```

To get a specific header:

```
authorization = request.headers.get("Authorization")
```

Example:

```
@app.get("/api/profile")
def profile():
    authorization = request.headers.get("Authorization")

    return {
        "authorization": authorization
    }
```

---

# 15. Why Headers Matter

Headers can provide information such as:

- Authentication tokens
- Content type
- Accepted response formats
- User agent
- Caching information
- Client-specific metadata

For example, JWT authentication commonly uses:

```
Authorization: Bearer <token>
```

Later, when we study JWT, you'll see how Flask extracts and verifies this header.

# 16. Checking Content Type

You can inspect the request's content type:

```
request.content_type
```

For JSON:

```
application/json
```

For a normal HTML form:

```
application/x-www-form-urlencoded
```

For file uploads:

```
multipart/form-data
```

Example:

```
@app.post("/api/users")
def create_user():
    print(request.content_type)

    return {
        "message": "Received"
    }
```

# 17. Request Body

The **request body** contains data sent with the request.

For example:

```
POST /api/users

{
    "name": "Rahul",
    "age": 21
}
```

The JSON object is the request body.

For raw body data, Flask provides:

```
request.data
```

However, for JSON APIs, you generally want:

```
request.get_json()
```

rather than manually processing `request.data`.

---

# 18. Raw Request Data

Example:

```
@app.post("/api/raw")
def raw_data():
    data = request.data

    print(data)

    return {
        "message": "Received"
    }
```

`request.data` gives the raw request body as bytes.

For normal REST JSON APIs, prefer:

```
request.get_json()
```

because Flask can parse the JSON for you.

---

# 19. Request Files

Flask can receive uploaded files through:

```
request.files
```

Example:

```
@app.post("/api/upload")
def upload_file():
    file = request.files.get("file")

    if file is None:
        return {
            "error": "File is required"
        }, 400

    return {
        "filename": file.filename
    }
```

A client might send:

```
POST /api/upload
Content-Type: multipart/form-data
```

with a file field named:

```
file
```

---

# 20. Form Data + File Upload

A multipart request can contain both regular fields and files.

For example:

```
name = Rahul
email = rahul@example.com
profile_picture = image.jpg
```

Flask:

```
name = request.form.get("name")
email = request.form.get("email")
file = request.files.get("profile_picture")
```

So:

```
Text fields
   ↓
request.form

Files
   ↓
request.files
```

# 21. Cookies

Cookies are small pieces of data sent with HTTP requests.

Flask accesses them through:

```
request.cookies
```

Specific cookie:

```
theme = request.cookies.get("theme")
```

Example:

```
@app.get("/api/settings")
def settings():
    theme = request.cookies.get("theme")

    return {
        "theme": theme
    }
```

Cookies are commonly used for:

- Session information
- Preferences
- Tracking
- Authentication-related mechanisms

# 22. Request Method

You can determine which HTTP method was used:

```
request.method
```

Example:

```
@app.route("/api/test", methods=["GET", "POST"])
def test():
    if request.method == "GET":
        return {
            "message": "GET request"
        }

    return {
        "message": "POST request"
    }
```

However, when possible, Flask's method-specific decorators are cleaner:

```
@app.get("/api/test")
def get_test():
    ...


@app.post("/api/test")
def post_test():
    ...
```

# 25. Example: Combining Different Request Data

Consider:

```
/api/users/10?include_orders=true
```

Request body:

```
{
    "name": "Rahul"
}
```

Header:

```
Authorization: Bearer abc123
```

Flask:

```
@app.patch("/api/users/<int:user_id>")
def update_user(user_id):

    # Path parameter
    user_id = user_id

    # Query parameter
    include_orders = request.args.get(
        "include_orders",
        default=False,
        type=lambda value: value.lower() == "true"
    )

    # JSON body
    data = request.get_json(silent=True)

    # Header
    authorization = request.headers.get("Authorization")

    return {
        "user_id": user_id,
        "include_orders": include_orders,
        "data": data,
        "authorization": authorization
    }
```

A single HTTP request can therefore contain **multiple kinds of request data**.

# 26. Request Validation

Reading request data is only half the job.

You also need to validate it.

Suppose the API expects:

```
{
    "name": "Rahul",
    "age": 21
}
```

Don't blindly trust the client.

```
@app.post("/api/users")
def create_user():

    data = request.get_json(silent=True)

    if data is None:
        return {
            "error": "JSON body is required"
        }, 400

    name = data.get("name")
    age = data.get("age")

    if not name:
        return {
            "error": "Name is required"
        }, 400

    if age is None:
        return {
            "error": "Age is required"
        }, 400

    if not isinstance(age, int):
        return {
            "error": "Age must be an integer"
        }, 400

    return {
        "message": "Valid request"
    }, 200
```

Validation becomes a major topic later in:

**10.11 Input Validation**

---

# 27. Query Parameter Validation

Suppose your API accepts:

```
/api/products?page=2&limit=20
```

You should validate the values.

```
@app.get("/api/products")
def get_products():

    page = request.args.get(
        "page",
        default=1,
        type=int
    )

    limit = request.args.get(
        "limit",
        default=20,
        type=int
    )

    if page < 1:
        return {
            "error": "Page must be at least 1"
        }, 400

    if limit < 1 or limit > 100:
        return {
            "error": "Limit must be between 1 and 100"
        }, 400

    return {
        "page": page,
        "limit": limit
    }
```

This prevents invalid input from reaching your business logic.

# 28. Optional vs Required Data

Not every request field has to be required.

For example:

```
{
    "name": "Rahul",
    "phone": "9876543210"
}
```

Maybe:

```
name  → required
phone → optional
```

Your API should clearly define this.

Example:

```
name = data.get("name")
phone = data.get("phone")

if not name:
    return {
        "error": "Name is required"
    }, 400
```

You don't necessarily need to reject a missing `phone`.

# 29. `request.args` vs `request.form` vs `request.get_json()`

This is one of the most important comparisons in Flask.

### `request.args`

Used for query parameters:

```
/api/users?role=admin
```

```
role = request.args.get("role")
```

---

### `request.form`

Used for form fields:

```
name=Rahul
```

```
name = request.form.get("name")
```

---

### `request.get_json()`

Used for JSON body:

```
{
    "name": "Rahul"
}
```

```
data = request.get_json()
```

### Memory trick

```
URL ?something
      ↓
request.args

HTML Form
      ↓
request.form

JSON Body
      ↓
request.get_json()
```

---

# 30. Don't Mix Them Up

Suppose the request is:

```
POST /api/users?source=mobile
Content-Type: application/json

{
    "name": "Rahul"
}
```

There are two different pieces of data:

### Query parameter

```
source = request.args.get("source")
```

### JSON body

```
data = request.get_json()
```

Then:

```
name = data.get("name")
```

So the API can receive data from different locations simultaneously.

---

# 31. Security: Never Trust Request Data

Everything coming from the client should be treated as **untrusted input**.

That includes:

```
request.args
request.form
request.get_json()
request.headers
request.files
request.cookies
```

A malicious client can manually send requests without using your frontend.

Therefore:

```
Client Input
     ↓
Validate
     ↓
Authorize
     ↓
Process
     ↓
Database
```

Never:

```
Client Input
     ↓
Database
```

---

# 32. Example of Unsafe Thinking

Suppose your API expects:

```
{
    "age": 21
}
```

Don't assume:

```
age = data["age"]
```

is always safe.

The client could send:

```
{
    "age": "hello"
}
```

or:

```
{
    "age": -500
}
```

or:

```
{
    "unexpected_field": "something"
}
```

Your API should validate what it accepts.

# 34. Practical Flask Example

Here's a small API that demonstrates several request-data types:

```
from flask import Flask, request, jsonify

app = Flask(__name__)


@app.patch("/api/users/<int:user_id>")
def update_user(user_id):

    # Path parameter
    print("User ID:", user_id)

    # Query parameter
    notify = request.args.get(
        "notify",
        default=False,
        type=lambda value: value.lower() == "true"
    )

    # JSON body
    data = request.get_json(silent=True)

    if data is None:
        return jsonify({
            "error": "Valid JSON body is required"
        }), 400

    # Header
    authorization = request.headers.get("Authorization")

    name = data.get("name")

    return jsonify({
        "user_id": user_id,
        "name": name,
        "notify": notify,
        "authorization": authorization
    })
```

Request:

```
PATCH /api/users/10?notify=true
Content-Type: application/json
Authorization: Bearer abc123
```

Body:

```
{
    "name": "Rahul"
}
```

Flask receives:

```
user_id
   ↓
10

notify
   ↓
true

JSON
   ↓
{"name": "Rahul"}

Authorization
   ↓
Bearer abc123
```
