If **GET** is mainly used to retrieve/search/filter data, **POST** is commonly used when a form needs to **send data to the server for processing**.

The most important difference is:

```
GET
Data → URL → Flask

POST
Data → Request Body → Flask
```

Let's build this from the ground up.

---

# 1. What Is POST?

`POST` is an HTTP request method used to send data to a server.

For example, a registration form might contain:

```
Username: John
Email: john@example.com
Password: 12345
```

When submitted using POST, the browser sends the data in the **request body**, rather than putting it in the URL.

Conceptually:

```
POST /register

username=John&email=john@example.com&password=12345
```

The important point is that the data is **not placed in the URL as query parameters**.

---

# 2. Basic POST Form

HTML:

```
<form method="POST" action="/submit">

    <input
        type="text"
        name="username"
    >

    <button type="submit">
        Submit
    </button>

</form>
```

Flask:

```
from flask import Flask, request

app = Flask(__name__)


@app.route("/submit", methods=["POST"])
def submit():

    username = request.form.get("username")

    return f"Username: {username}"
```

If the user enters:

```
John
```

Flask receives:

```
username = John
```

---

# 3. Why Do We Need `methods=["POST"]`?

By default:

```
@app.route("/submit")
```

accepts:

```
GET
```

It does **not** automatically accept POST.

Therefore:

```
@app.route("/submit", methods=["POST"])
```

means:

> This route is allowed to receive POST requests.

You can also allow multiple methods:

```
@app.route("/submit", methods=["GET", "POST"])
```

Now the same route can handle both.

---

# 4. `request.form`

This is the most important Flask concept for traditional POST forms.

Suppose your HTML contains:

```
<input type="text" name="username">
```

and the form uses:

```
<form method="POST">
```

Flask can retrieve the value using:

```
request.form.get("username")
```

So the relationship is:

```
HTML
│
├── method="POST"
│
└── name="username"
          │
          ▼
       Flask
          │
          ▼
request.form.get("username")
```

---

# 5. Complete Example

### `app.py`

```
from flask import Flask, request, render_template

app = Flask(__name__)


@app.route("/")
def home():
    return render_template("form.html")


@app.route("/submit", methods=["POST"])
def submit():

    username = request.form.get("username")

    return f"Hello, {username}!"


if __name__ == "__main__":
    app.run(debug=True)
```

### `form.html`

```
<!DOCTYPE html>

<html>

<head>
    <title>POST Form</title>
</head>

<body>

    <h1>POST Form</h1>

    <form method="POST" action="/submit">

        <input
            type="text"
            name="username"
            placeholder="Enter username"
        >

        <button type="submit">
            Submit
        </button>

    </form>

</body>

</html>
```

If the user enters:

```
Sudip
```

the browser sends a POST request to:

```
/submit
```

Flask executes:

```
username = request.form.get("username")
```

and gets:

```
Sudip
```

# 6. GET vs POST

This is the part worth putting in your notes carefully.

### GET

```
<form method="GET" action="/search">
```

Browser:

```
/search?q=Flask
```

Flask:

```
request.args.get("q")
```

### POST

```
<form method="POST" action="/submit">
```

Browser:

```
/submit
```

Data is sent in the request body.

Flask:

```
request.form.get("username")
```

So:

||GET|POST|
|---|---|---|
|HTTP method|GET|POST|
|Data location|URL/query string|Request body|
|Flask access|`request.args`|`request.form`|
|URL contains submitted values|Usually yes|Usually no|
|Common use|Search/filter|Submit/create/update|
|Suitable for passwords|❌|✅ Preferable|
|Bookmarkable request|Usually yes|Usually no|

**Important:** POST hiding data from the URL does **not** mean it encrypts the data. For security, use HTTPS.

# 7. Multiple Form Fields

A POST form can send many values.

```
<form method="POST" action="/register">

    <input
        type="text"
        name="username"
    >

    <input
        type="email"
        name="email"
    >

    <input
        type="password"
        name="password"
    >

    <button type="submit">
        Register
    </button>

</form>
```

Flask:

```
@app.route("/register", methods=["POST"])
def register():

    username = request.form.get("username")
    email = request.form.get("email")
    password = request.form.get("password")

    return f"""
        Username: {username}<br>
        Email: {email}
    """
```

Notice that the password isn't displayed here. In a real application, you would **hash the password** before storing it, which we'll cover in Module 9.

# 8. Why Does `name` Matter?

Consider:

```
<input type="text" name="username">
```

The:

```
name="username"
```

becomes the key Flask uses:

```
request.form.get("username")
```

If you instead write:

```
<input type="text" name="email">
```

you retrieve it with:

```
request.form.get("email")
```

So:

```
name="username"
       ↓
request.form.get("username")
```

The names must match.

---

# 9. `request.form["username"]` vs `.get()`

You can write:

```
username = request.form["username"]
```

or:

```
username = request.form.get("username")
```

The difference matters.

### Using `[]`

```
username = request.form["username"]
```

If `username` isn't present, Flask raises a `BadRequestKeyError`.

### Using `.get()`

```
username = request.form.get("username")
```

If it isn't present, you generally get:

```
None
```

You can also provide a default:

```
username = request.form.get("username", "")
```

For beginner Flask applications, `.get()` is often convenient because you can explicitly handle missing values.

# 10. POST With GET and POST on the Same Route

A very common Flask pattern is:

```
@app.route("/login", methods=["GET", "POST"])
def login():

    if request.method == "POST":

        username = request.form.get("username")
        password = request.form.get("password")

        return "Form submitted"

    return render_template("login.html")
```

Now one URL performs two jobs.

### First visit

Browser sends:

```
GET /login
```

Flask displays the form:

```
return render_template("login.html")
```

### Form submission

Browser sends:

```
POST /login
```

Flask processes:

```
if request.method == "POST":
```

So:

```
GET /login
      ↓
Display form

POST /login
      ↓
Process form
```

This pattern is extremely common.

---

# 11. A Better Example

### `app.py`

```
from flask import Flask, request, render_template

app = Flask(__name__)


@app.route("/login", methods=["GET", "POST"])
def login():

    if request.method == "POST":

        username = request.form.get("username")
        password = request.form.get("password")

        return f"Received login for {username}"

    return render_template("login.html")


if __name__ == "__main__":
    app.run(debug=True)
```

### `login.html`

```
<!DOCTYPE html>

<html>

<head>
    <title>Login</title>
</head>

<body>

    <h1>Login</h1>

    <form method="POST" action="/login">

        <input
            type="text"
            name="username"
            placeholder="Username"
        >

        <input
            type="password"
            name="password"
            placeholder="Password"
        >

        <button type="submit">
            Login
        </button>

    </form>

</body>

</html>
```

The flow:

```
                    /login
                       │
             ┌─────────┴─────────┐
             │                   │
           GET                  POST
             │                   │
             ▼                   ▼
       Show login form     Read form data
                                 │
                                 ▼
                        request.form
```

# 12. What Actually Happens Internally?

Let's make the HTTP part visible.

The browser first requests:

```
GET /login HTTP/1.1
```

Flask returns the HTML form.

The user fills it out.

When they click **Login**, the browser creates something conceptually like:

```
POST /login HTTP/1.1
Content-Type: application/x-www-form-urlencoded

username=John&password=12345
```

Flask receives the request.

Then:

```
request.form
```

contains the submitted form fields.

You can think of it approximately as:

```
{
    "username": "John",
    "password": "12345"
}
```

Then:

```
request.form.get("username")
```

returns:

```
John
```

# 13. POST Does Not Mean "Form"

This is an important distinction.

`POST` is an **HTTP method**.

A POST request can contain different types of data.

For example:

```
POST + form data
POST + JSON
POST + file upload
```

So don't think:

```
POST = form
```

Instead:

```
POST = HTTP method commonly used to submit/send data
```

The data format determines how Flask reads it.

For example:

### Form data

```
request.form
```

### JSON

```
request.get_json()
```

### Uploaded files

```
request.files
```

This connects directly with the topics you've already learned.

# 14. POST Form vs JSON Request

These can both use POST, but they're different.

### HTML form

```
<form method="POST">
```

Flask:

```
request.form
```

### JSON request

```
POST /api/users
Content-Type: application/json
```

Body:

```
{
    "username": "John",
    "age": 25
}
```

Flask:

```
data = request.get_json()
```

So:

```
                 POST
                  │
        ┌─────────┼──────────┐
        │         │          │
      Form       JSON       File
        │         │          │
request.form  get_json()  request.files
```

# 15. Redirect After POST

There is a very important pattern you'll encounter in real Flask applications:

```
GET → POST → Redirect → GET
```

For example:

```
from flask import Flask, request, redirect, url_for

app = Flask(__name__)


@app.route("/submit", methods=["POST"])
def submit():

    username = request.form.get("username")

    # Process data here

    return redirect(url_for("success"))


@app.route("/success")
def success():

    return "Successfully submitted!"
```

Why redirect?

Imagine:

```
POST /submit
      ↓
Process data
      ↓
redirect
      ↓
GET /success
```

This prevents the browser from simply resubmitting the POST when the user refreshes the resulting page.

This pattern is called **Post/Redirect/Get (PRG)**.

You don't need to memorize the implementation yet, but you should recognize the pattern.

---

# 16. POST and Browser Refresh

Suppose you directly return a response after POST:

```
@app.route("/submit", methods=["POST"])
def submit():

    # Save data

    return "Saved!"
```

The browser may show a warning when the user refreshes:

```
Confirm Form Resubmission
```

because refreshing can repeat the POST request.

With PRG:

```
POST
 ↓
Process
 ↓
302 Redirect
 ↓
GET
 ↓
Display result
```

refreshing the final page performs the GET again instead of resubmitting the form.

# 18. Common Mistakes

### Mistake 1: Forgetting `methods`

```
@app.route("/submit")
```

while the form sends:

```
<form method="POST">
```

Result:

```
405 Method Not Allowed
```

Correct:

```
@app.route("/submit", methods=["POST"])
```

---

### Mistake 2: Using `request.args`

For a POST form:

```
request.args.get("username")
```

is normally wrong because `request.args` is for query parameters.

Use:

```
request.form.get("username")
```

---

### Mistake 3: Missing `name`

This:

```
<input type="text">
```

doesn't give Flask a useful form key.

Use:

```
<input type="text" name="username">
```

Then:

```
request.form.get("username")
```

---

### Mistake 4: Mixing up `action`

```
<form method="POST" action="/register">
```

means the request goes to:

```
/register
```

So Flask needs a matching route:

```
@app.route("/register", methods=["POST"])
```

# 19. GET and POST Together

This is the mental model I recommend remembering:

```
                 HTML FORM
                     │
            ┌────────┴────────┐
            │                 │
           GET               POST
            │                 │
            ▼                 ▼
      URL / Query         Request Body
            │                 │
            ▼                 ▼
      request.args       request.form
```

Example:

```
GET /search?q=Flask
```

```
request.args.get("q")
```

versus:

```
POST /login

username=John
password=12345
```

```
request.form.get("username")
request.form.get("password")
```
