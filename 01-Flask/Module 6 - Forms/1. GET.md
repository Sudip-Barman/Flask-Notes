Before learning `POST`, validation, and WTForms, we need to understand how a **GET form** works in Flask.

The main idea:

> **A GET form sends user input to the server through the URL as query parameters.**

This connects directly to the **Query Parameters** topic we studied earlier.

---

# 1. What Is a GET Form?

A form is an HTML element used to collect information from a user.

Example:

```
<form method="GET">
    <input type="text" name="username">

    <button type="submit">
        Search
    </button>
</form>
```

When the user enters:

```
John
```

and clicks **Search**, the browser sends a request like:

```
GET /?username=John
```

The important part is:

```
?username=John
```

That's a **query parameter**.

---

# 2. Basic GET Form in Flask

### `app.py`

```
from flask import Flask, request, render_template

app = Flask(__name__)


@app.route("/")
def home():
    return render_template("home.html")


@app.route("/search")
def search():

    username = request.args.get("username")

    return f"Searching for: {username}"


if __name__ == "__main__":
    app.run(debug=True)
```

### `home.html`

```
<!DOCTYPE html>

<html>

<head>
    <title>GET Form</title>
</head>

<body>

    <form method="GET" action="/search">

        <input
            type="text"
            name="username"
            placeholder="Enter username"
        >

        <button type="submit">
            Search
        </button>

    </form>

</body>

</html>
```

---

# 3. What Happens When the User Submits?

Suppose the user enters:

```
Sudip
```

The form is:

```
<form method="GET" action="/search">
```

The browser creates:

```
GET /search?username=Sudip
```

Flask receives the request.

Then:

```
request.args.get("username")
```

gets:

```
Sudip
```

So the complete flow is:

```
User enters:
"Sudip"
     ↓
Clicks Search
     ↓
HTML GET form
     ↓
GET /search?username=Sudip
     ↓
Flask
     ↓
request.args.get("username")
     ↓
"Sudip"
```

---

# 4. Why Does `name` Matter?

Consider:

```
<input type="text" name="username">
```

The `name` becomes the query parameter's key.

For example:

```
name="username"
```

produces:

```
?username=Sudip
```

If you write:

```
<input type="text" name="user">
```

you get:

```
?user=Sudip
```

Therefore:

```
HTML name
     ↓
Query parameter key
     ↓
request.args.get()
```

Example:

```
<input name="username">
```

matches:

```
request.args.get("username")
```

---

# 5. `action` Attribute

The `action` tells the browser **where to send the form**.

```
<form method="GET" action="/search">
```

means:

```
Submit form
     ↓
GET request
     ↓
/search
```

You can also use Flask's `url_for()`:

```
<form
    method="GET"
    action="{{ url_for('search') }}"
>
```

This is generally preferable to hardcoding the URL.

Your route:

```
@app.route("/search")
def search():
    ...
```

has the endpoint:

```
search
```

So:

```
{{ url_for('search') }}
```

generates:

```
/search
```

---

# 6. Multiple Form Fields

A GET form can contain multiple inputs.

```
<form method="GET" action="/search">

    <input
        type="text"
        name="username"
        placeholder="Username"
    >

    <input
        type="text"
        name="city"
        placeholder="City"
    >

    <button type="submit">
        Search
    </button>

</form>
```

Suppose the user enters:

```
Username: John
City: Kolkata
```

The browser sends:

```
GET /search?username=John&city=Kolkata
```

Flask:

```
@app.route("/search")
def search():

    username = request.args.get("username")
    city = request.args.get("city")

    return f"User: {username}, City: {city}"
```

Result:

```
User: John, City: Kolkata
```

# 7. GET Form and Query Parameters

This should now connect with what you learned earlier.

A GET form:

```
<form method="GET">
```

creates query parameters.

For example:

```
/search?username=John&city=Kolkata
```

Flask reads them with:

```
request.args
```

So:

```
GET Form
   ↓
Query Parameters
   ↓
request.args
```

That's why GET forms are closely related to query parameters.

---

# 8. `request.args`

`request.args` contains the query parameters.

Suppose the browser sends:

```
/search?name=John&age=25
```

Then:

```
request.args
```

contains approximately:

```
{
    "name": "John",
    "age": "25"
}
```

You can retrieve individual values:

```
name = request.args.get("name")
age = request.args.get("age")
```

---

# 9. `.get()` Is Safer

You can technically write:

```
name = request.args["name"]
```

But if `name` isn't provided, Flask can raise an error.

Using:

```
name = request.args.get("name")
```

returns:

```
None
```

if the parameter doesn't exist.

For example:

```
@app.route("/search")
def search():

    name = request.args.get("name")

    if name is None:
        return "Name was not provided"

    return f"Hello {name}"
```

---

# 10. Default Values

You can provide a default value:

```
name = request.args.get("name", "Guest")
```

If the request is:

```
/search
```

then:

```
name
```

will be:

```
Guest
```

If the request is:

```
/search?name=John
```

then:

```
name
```

will be:

```
John
```

# 15. GET Forms Are Visible in the URL

This is one of the biggest characteristics of GET.

Suppose:

```
<form method="GET">
```

and the user enters:

```
John
```

The URL might become:

```
/search?username=John
```

The submitted information is therefore visible in:

- URL
- Browser history
- Bookmarks
- Potentially server/proxy logs

Therefore, **GET should not normally be used for sensitive information such as passwords**.

---

# 16. GET Is Usually Used for Retrieval

GET is commonly appropriate when the user wants to:

```
Search
Filter
Sort
Navigate
Retrieve information
```

Examples:

```
/search?q=flask
/products?category=books
/users?sort=name
/articles?page=2
```

The request is primarily asking:

> "Give me this information."

---

# 17. GET Should Not Normally Change Server Data

Suppose you have:

```
/delete-user?id=10
```

Using GET for deletion is a bad design.

Why?

Because GET requests can be triggered by things such as:

- Links
- Browser refreshes
- Crawlers
- Prefetching
- Bookmarks

A GET request should generally be **safe and read-oriented**.

For operations that modify server-side data, you'll normally use methods such as:

```
POST
PUT
PATCH
DELETE
```

We'll focus on `POST` next.

---

# 18. GET Form vs POST Form

This distinction is extremely important.

|GET|POST|
|---|---|
|Data goes into URL|Data goes into request body|
|Uses query parameters|Uses form/request body|
|Data visible in URL|Data not normally visible in URL|
|Good for search/filter|Good for submitting/changing data|
|Can be bookmarked|Usually not meaningful to bookmark|
|Suitable for non-sensitive data|Better for sensitive/submission data|
|`request.args`|`request.form`|

Example GET:

```
GET /search?name=John
```

Flask:

```
request.args.get("name")
```

Example POST:

```
POST /register
```

with form data in the body.

Flask:

```
request.form.get("name")
```

You'll see the POST side in the next topic.

```

│

### `app.py`

```
from flask import Flask, request, render_template

app = Flask(__name__)


@app.route("/")
