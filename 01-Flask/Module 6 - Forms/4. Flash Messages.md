> **Note:** In Flask, this is called **Flash Messages**, not Flash Memory.

A **flash message** is a temporary message that Flask stores so it can be displayed to the user on the **next request**.

Typical examples:

```
Registration successful!
Login successful!
Invalid username or password.
Profile updated successfully.
Please fill in all required fields.
```

The important idea is:

```
Request 1
   ↓
Set flash message
   ↓
Redirect
   ↓
Request 2
   ↓
Display flash message
   ↓
Message disappears
```

This makes flash messages especially useful after form submissions.

---

# 1. Why Do We Need Flash Messages?

Suppose we have a registration form:

```
User
 ↓
POST /register
 ↓
Registration successful
```

We could simply do:

```
return "Registration successful!"
```

But that's not ideal because the user remains on the POST response.

A better approach is:

```
POST /register
       ↓
Process registration
       ↓
flash("Registration successful!")
       ↓
redirect("/login")
       ↓
GET /login
       ↓
Show message
```

The user sees:

```
Registration successful!
```

on the login page.

This is commonly used with the **Post/Redirect/Get (PRG)** pattern we discussed earlier.

---

# 2. Import `flash`

Flask provides `flash()`:

```
from flask import flash
```

You also need:

```
app.secret_key = "your-secret-key"
```

We'll discuss why the secret key is required shortly.

---

# 3. Basic Flash Message

```
from flask import Flask, flash

app = Flask(__name__)

app.secret_key = "your-secret-key"


@app.route("/")
def home():

    flash("Hello! This is a flash message.")

    return "Message created"
```

However, this only creates the message.

We need another request to **display** it.

---

# 4. Displaying Flash Messages

Flask provides:

```
get_flashed_messages()
```

Import it:

```
from flask import get_flashed_messages
```

But normally you'll use it inside your Jinja template.

### `app.py`

```
from flask import Flask, flash, redirect, url_for, render_template

app = Flask(__name__)

app.secret_key = "your-secret-key"


@app.route("/")
def home():

    flash("Welcome to the website!")

    return redirect(url_for("message"))


@app.route("/message")
def message():

    return render_template("message.html")
```

### `message.html`

```
<!DOCTYPE html>

<html>

<head>
    <title>Message</title>
</head>

<body>

    {% with messages = get_flashed_messages() %}

        {% for message in messages %}

            <p>{{ message }}</p>

        {% endfor %}

    {% endwith %}

</body>

</html>
```

Flow:

```
GET /
 ↓
flash("Welcome...")
 ↓
redirect
 ↓
GET /message
 ↓
get_flashed_messages()
 ↓
Display message
```

---

# 5. Why Is It Called "Flash"?

Because the message is designed to exist temporarily.

For example:

```
Request 1
    ↓
flash("Saved successfully!")
    ↓
Request 2
    ↓
Display message
    ↓
Message consumed
```

It isn't intended to be permanent application data.

Think:

```
Database
→ permanent data

Flash message
→ temporary notification
```

---

# 6. Flash Messages and Redirects

This is where flash messages become particularly useful.

Suppose we have:

```
@app.route("/register", methods=["POST"])
def register():

    # Process registration

    flash("Registration successful!")

    return redirect(url_for("login"))
```

Then:

```
@app.route("/login")
def login():

    return render_template("login.html")
```

The message created during `/register` can be displayed during `/login`.

---

# 7. Complete Example

### `app.py`

```
from flask import (
    Flask,
    flash,
    redirect,
    url_for,
    render_template,
    request
)

app = Flask(__name__)

app.secret_key = "your-secret-key"


@app.route("/register", methods=["GET", "POST"])
def register():

    if request.method == "POST":

        username = request.form.get("username", "").strip()

        if not username:

            flash("Username is required.")

            return redirect(url_for("register"))

        flash("Registration successful!")

        return redirect(url_for("login"))

    return render_template("register.html")


@app.route("/login")
def login():

    return render_template("login.html")


if __name__ == "__main__":
    app.run(debug=True)
```

# 10. Flash Messages Are Stored Temporarily

Internally, Flask associates the flashed message with the user's session.

That's why Flask needs:

```
app.secret_key
```

Flash messages rely on Flask's session mechanism.

So:

```
flash()
   ↓
Session
   ↓
Next request
   ↓
get_flashed_messages()
```

This is also why you should configure a proper secret key instead of using an obvious hardcoded value in production.

---

# 11. `SECRET_KEY`

You may see:

```
app.secret_key = "your-secret-key"
```

or:

```
app.config["SECRET_KEY"] = "your-secret-key"
```

Both configure Flask's secret key.

For development, you might temporarily use:

```
app.config["SECRET_KEY"] = "dev-secret-key"
```

For production, don't put a real secret directly into your source code.

Instead, use an environment variable:

```
import os

app.config["SECRET_KEY"] = os.environ.get("SECRET_KEY")
```

We'll cover **configuration and environment variables** properly in Module 11.

For now, just remember:

> **Flash messages require Flask's session system, and the session system requires a secret key.**

# 12. `get_flashed_messages()`

The basic form is:

```
{% with messages = get_flashed_messages() %}

    {% for message in messages %}

        <p>{{ message }}</p>

    {% endfor %}

{% endwith %}
```

Let's break it down.

### Get messages

```
get_flashed_messages()
```

returns the available flash messages.

For example:

```
[
    "Registration successful!",
    "Welcome back!"
]
```

### Loop through them

```
{% for message in messages %}
```

Then display:

```
{{ message }}
```

# 13. Flash Categories

Flash messages can have categories.

For example:

```
flash("Registration successful!", "success")
```

or:

```
flash("Invalid username or password.", "error")
```

The second argument is the **category**.

Common categories are:

```
success
error
warning
info
```

These names aren't special Flask keywords. They're labels you choose.

---

# 14. Getting Categories in the Template

By default:

```
get_flashed_messages()
```

returns just the messages.

To receive categories too:

```
get_flashed_messages(with_categories=true)
```

Example:

```
{% with messages = get_flashed_messages(with_categories=true) %}

    {% for category, message in messages %}

        <p class="{{ category }}">
            {{ message }}
        </p>

    {% endfor %}

{% endwith %}
```

Suppose Flask sends:

```
flash("Registration successful!", "success")
```

The template receives something conceptually like:

```
[
    ("success", "Registration successful!")
]
```

So:

```
category
```

is:

```
success
```

and:

```
message
```

is:

```
Registration successful!
```

---

# 15. Using CSS With Categories

Now the category becomes useful.

```
{% with messages = get_flashed_messages(with_categories=true) %}

    {% for category, message in messages %}

        <div class="alert {{ category }}">
            {{ message }}
        </div>

    {% endfor %}

{% endwith %}
```

CSS:

```
.alert {
    padding: 10px;
    margin-bottom: 10px;
}

.success {
    background: lightgreen;
}

.error {
    background: lightcoral;
}

.warning {
    background: lightyellow;
}

.info {
    background: lightblue;
}
```

Now Flask controls the message type:

```
flash("Profile updated!", "success")
```

and the template/CSS controls how it looks.

# 16. Multiple Flash Messages

You can create multiple messages:

```
flash("Profile updated.", "success")

```

Then:

```
{% with messages = get_flashed_messages(with_categories=true) %}

    {% for category, message in messages %}

        <div class="{{ category }}">
            {{ message }}
        </div>

    {% endfor %}

{% endwith %}
```

Both messages can be displayed.

# 17. Filtering by Category

You can ask Flask for messages belonging to specific categories.

Example:

```
get_flashed_messages(
    category_filter=["error"]
)
```

This retrieves only messages categorized as:

```
error
```

For example:

```
flash("Username is incorrect.", "error")
flash("Profile saved.", "success")
```

Then:

```
{% with messages = get_flashed_messages(category_filter=["error"]) %}

    {% for message in messages %}
        <p>{{ message }}</p>
    {% endfor %}

{% endwith %}
```

Only the error message is displayed.

# 18. Flash Messages With Validation

Now let's connect this with the previous topic.

Suppose:

```
@app.route("/register", methods=["POST"])
def register():

    username = request.form.get("username", "").strip()

    if not username:

        flash(
            "Username is required.",
            "error"
        )

        return redirect(url_for("register"))

    flash(
        "Registration successful!",
        "success"
    )

    return redirect(url_for("login"))
```

Flow:

```
POST
 ↓
Get form data
 ↓
Validate
 ↓
 ┌──────────────┐
 │              │
Invalid        Valid
 │              │
 ▼              ▼
flash(error)  flash(success)
 │              │
 └──────┬───────┘
        ▼
     redirect
```

This is a very common Flask pattern.

---

# 19. Flash Messages vs Returning a String

Without flash:

```
return "Registration successful!"
```

With flash:

```
flash("Registration successful!", "success")

return redirect(url_for("login"))
```

The difference is:

```
return
  ↓
Current response

flash
  ↓
Temporary message
  ↓
Available on a subsequent request
```

---

# 20. Flash Messages vs Sessions

They are related, but they're not the same thing.

### Session

Used for information that should persist across requests.

Example:

```
logged_in = True
user_id = 123
```

### Flash

Used for temporary notifications.

Example:

```
"Profile updated successfully!"
```

Conceptually:

```
Session
├── user_id
├── logged_in
└── preferences

Flash
└── "Profile updated successfully!"
```

Flash messages use the session mechanism internally, but you don't manually manage their lifecycle.

# 21. Flash Messages and MySQL

Once you connect Flask with MySQL, flash messages become very useful.

For example:

```
POST /users
      ↓
Validate
      ↓
INSERT into MySQL
      ↓
Success
      ↓
flash("User created!", "success")
      ↓
redirect
      ↓
Display message
```

If the database operation fails:

```
MySQL error
    ↓
flash("Unable to create user.", "error")
    ↓
redirect
```

We'll use this pattern extensively when we reach **Flask + MySQL**.

# 22. Important Security Note

Never put sensitive information into flash messages.

Avoid:

```
flash(password)
```

or:

```
flash(database_password)
```

Flash messages are designed for user-visible notifications.

Good:

```
flash("Password changed successfully.", "success")
```

Bad:

```
flash(f"Your password is {password}")
```

# 23. Common Mistakes

### Mistake 1: Forgetting the secret key

```
flash("Hello")
```

without configuring the secret key can cause session-related problems.

Use:

```
app.config["SECRET_KEY"] = "..."
```

---

### Mistake 2: Creating a message but never displaying it

This:

```
flash("Hello!")
```

doesn't automatically put it into your HTML.

Your template needs:

```
get_flashed_messages()
```

---

### Mistake 3: Forgetting categories

If you write:

```
flash("Saved!")
```

you won't have a category.

If you want one:

```
flash("Saved!", "success")
```

---

### Mistake 4: Displaying messages incorrectly

Remember:

```
{% with messages = get_flashed_messages() %}
```

then:

```
{% for message in messages %}
```

For categories:

```
{% with messages = get_flashed_messages(with_categories=true) %}

    {% for category, message in messages %}

    {% endfor %}

{% endwith %}
```

# 24. Recommended Reusable Pattern

In a real Flask application, you often put the flash-message display in your base template.

For example:

```
templates/
│
├── base.html
├── login.html
└── register.html
```

`base.html`:

```
{% with messages = get_flashed_messages(with_categories=true) %}

    {% for category, message in messages %}

        <div class="alert {{ category }}">
            {{ message }}
        </div>

    {% endfor %}

{% endwith %}

{% block content %}
{% endblock %}
```

Because other templates inherit from `base.html`, all pages can display flash messages.

This connects directly to the **Template Inheritance** topic you already learned.
