**WTForms** is a Python library for creating, processing, and validating HTML forms.

Instead of manually doing this:

```
username = request.form.get("username")
email = request.form.get("email")

if not username:
    ...

if not email:
    ...
```

WTForms lets you define the form in Python:

```
class RegistrationForm(FlaskForm):
    username = StringField(...)
    email = EmailField(...)
    password = PasswordField(...)
```

and define validation rules alongside the fields.

---

# 1. Why WTForms?

Without WTForms, a form can become repetitive:

```
username = request.form.get("username")
email = request.form.get("email")
password = request.form.get("password")

if not username:
    ...

if not email:
    ...

if len(password) < 8:
    ...
```

You also have to manually handle:

- Getting form data
- Validation
- Error messages
- Repopulating fields
- CSRF protection
- Rendering fields

WTForms organizes these things.

Think of it as:

```
HTML Form
   ↓
WTForms
   ├── Fields
   ├── Validation
   ├── Errors
   └── Form processing
```

---

# 2. WTForms vs Flask-WTF

There are two names you should distinguish.

### WTForms

The core form library.

```
WTForms
↓
Form classes
Fields
Validators
```

### Flask-WTF

An extension that integrates WTForms with Flask.

```
Flask
  ↓
Flask-WTF
  ↓
WTForms
```

For Flask applications, you'll commonly use **Flask-WTF**.

Install it:

```
pip install flask-wtf
```

It will install the necessary WTForms dependency as well.

# 4. Creating Your First Form

`app.py`:

```
from flask import Flask, render_template
from flask_wtf import FlaskForm
from wtforms import StringField, PasswordField, SubmitField

app = Flask(__name__)

app.config["SECRET_KEY"] = "dev-secret-key"


class RegistrationForm(FlaskForm):

    username = StringField("Username")

    password = PasswordField("Password")

    submit = SubmitField("Register")


@app.route("/register")
def register():

    form = RegistrationForm()

    return render_template(
        "register.html",
        form=form
    )


if __name__ == "__main__":
    app.run(debug=True)
```

```

RegistrationForm
```

```
<!DOCTYPE html>

<html>

        {{ form.username() }}

```

WTForms generates the appropriate HTML.

For example:

```
{{ form.username() }}
```

generates an HTML input similar to:

```
<input id="username" name="username" type="text">
```

And:

```
{{ form.password() }}
```

generates:

```
<input id="password" name="password" type="password">
```

So instead of manually writing every `<input>`, WTForms can generate them.

# 8. Adding Validation

This is where WTForms becomes much more useful.

Import validators:

```
from wtforms.validators import DataRequired, Length
```

Then:

```
class RegistrationForm(FlaskForm):

    username = StringField(
        "Username",
        validators=[
            DataRequired(),
            Length(min=3, max=20)
        ]
    )
```

Now WTForms checks:

```
Username
   │
   ├── Required?
   │
   └── 3-20 characters?
```

---

# 9. `DataRequired`

```
DataRequired()
```

means:

> The user must provide a value.

Example:

```
username = StringField(
    "Username",
    validators=[
        DataRequired()
    ]
)
```

If the user submits:

```
username = ""
```

validation fails.

---

# 10. `Length`

```
Length(min=3, max=20)
```

means:

```
Minimum: 3 characters
Maximum: 20 characters
```

For example:

```
ab
```

❌ Invalid

```
sudip
```

✅ Valid

A very long value exceeding the maximum is also invalid.

---

# 11. Multiple Validators

You can use multiple validators:

```
username = StringField(
    "Username",
    validators=[
        DataRequired(),
        Length(min=3, max=20)
    ]
)
```

Validation happens as a chain:

```
Input
 ↓
DataRequired
 ↓
Length
 ↓
Valid / Invalid
```

# 12. Handling POST Requests

Now let's make the form actually submit.

```
@app.route("/register", methods=["GET", "POST"])
def register():

    form = RegistrationForm()

    if form.validate_on_submit():

        return "Registration successful!"

    return render_template(
        "register.html",
        form=form
    )
```

This is one of the most important WTForms patterns.

---

# 13. What Is `validate_on_submit()`?

This:

```
form.validate_on_submit()
```

essentially combines two checks:

```
Is this a POST request?
        +
Does the form pass validation?
```

Conceptually:

```
request.method == "POST"
```

and:

```
form.validate()
```

So:

```
if form.validate_on_submit():
```

means:

> "If the form was submitted and all validation rules passed..."

# 14. Complete Example

### `app.py`

```
from flask import Flask, render_template
from flask_wtf import FlaskForm
from wtforms import (
    StringField,
    PasswordField,
    SubmitField
)
from wtforms.validators import (
    DataRequired,
    Length
)

app = Flask(__name__)

app.config["SECRET_KEY"] = "dev-secret-key"


class RegistrationForm(FlaskForm):

    username = StringField(
        "Username",
        validators=[
            DataRequired(),
            Length(min=3, max=20)
        ]
    )

    password = PasswordField(
        "Password",
        validators=[
            DataRequired(),
            Length(min=8)
        ]
    )

    submit = SubmitField("Register")


@app.route("/register", methods=["GET", "POST"])
def register():

    form = RegistrationForm()

    if form.validate_on_submit():

        return "Registration successful!"

    return render_template(
        "register.html",
        form=form
    )


if __name__ == "__main__":
    app.run(debug=True)
```

# 17. `form.hidden_tag()`

You may have noticed:

```
{{ form.hidden_tag() }}
```

This is extremely important when using Flask-WTF.

It generates hidden fields required by Flask-WTF, most importantly the **CSRF token**.

So don't simply remove it.

A common form structure is:

```
<form method="POST">

    {{ form.hidden_tag() }}

    ...

</form>
```

# 18. What Is CSRF?

CSRF means:

> **Cross-Site Request Forgery**

It is a security attack where another website attempts to make a user's browser perform an unwanted action on a website where the user is authenticated.

For example, imagine you're logged into:

```
example.com
```

A malicious website could attempt to trick your browser into submitting:

```
POST /change-email
```

without your intention.

CSRF protection adds a secret token to forms.

The server checks:

```
Browser submits form
       ↓
CSRF token included
       ↓
Flask-WTF verifies token
       ↓
Valid?
  ├── Yes → process
  └── No  → reject
```

This is one of the major advantages of Flask-WTF.

---

# 19. Why `SECRET_KEY` Matters Again

Flask-WTF uses Flask's secret key for security-related functionality such as CSRF protection.

Therefore:

```
app.config["SECRET_KEY"] = "..."
```

is important.

In production, use a strong secret stored outside your source code.


The validation logic becomes much more organized.

# 23. Common Validators

Some useful validators include:

```
DataRequired()
```

Required value.

```
Length(min=3, max=20)
```

Length restriction.

```
Email()
```

Email validation.

```
NumberRange(min=18, max=100)
```

Numeric range.

```
EqualTo("password")
```

Compare one field to another.

For example, password confirmation:

```
confirm_password = PasswordField(
    "Confirm Password",
    validators=[

            message="Passwords must match."
```

# 28. Custom Validation

WTForms also allows you to write your own validation logic.

For example:

```
from wtforms.validators import ValidationError
```

Then:

```
def validate_username(form, field):

    if field.data == "admin":
        raise ValidationError(
            "This username is not allowed."
        )
```

Use it:

```
username = StringField(
    "Username",
    validators=[
        DataRequired(),
        validate_username
    ]
)
```

Now your custom rule becomes part of the validation system.

# 31. WTForms Does Not Replace HTML

This is an important misconception.

WTForms does **not** mean:

```
Python → no HTML required
```

Instead:

```
Python
 ↓
Define form + validation
 ↓
WTForms
 ↓
Generate/manage HTML form fields
```

You still use Jinja templates to decide where and how fields appear.

You can also manually customize the generated HTML.

# 34. GET vs POST With WTForms

A typical route:

```
@app.route(
    "/register",
    methods=["GET", "POST"]
)
def register():

    form = RegistrationForm()

    if form.validate_on_submit():

        # process form

        return redirect(...)

    return render_template(
        "register.html",
        form=form
    )
```

Flow:

```
GET /register
     ↓
Create form
     ↓
Display form


POST /register
     ↓
Create/process form
     ↓
Validate
     ↓
Success?
 ┌──────┴──────┐
No             Yes
│               │
Errors          Process
│               │
└──────┬────────┘
       ▼
   Render/Redirect
```

```
        ▼            ▼            ▼
      Fields      Validators    Submit
        │            │
        ▼            ▼
   username       Required
   email          Email
   password       Length
                  EqualTo
                     │
                     ▼
               validate_on_submit()
                     │
              ┌──────┴──────┐
              ▼             ▼
           Invalid         Valid
              │             │
              ▼             ▼
```
