**Validation** means checking whether the data submitted by the user is acceptable before your application uses or stores it.

For example, suppose a registration form asks for:

```
Username: 
Email:
Age:
Password:
```

A user could submit:

```
Username: [empty]
Email: hello
Age: -50
Password: 123
```

Your application should not blindly accept that data.

Instead:

```
User submits data
       ↓
Flask receives data
       ↓
Validate
       ↓
 ┌─────┴─────┐
 │           │
Valid      Invalid
 │           │
 ↓           ↓
Process    Show errors
```

---

# 1. Why Do We Need Validation?

Without validation:

```
username = request.form.get("username")

# directly use it
```

you are trusting whatever the user sends.

Users can submit:

- Empty values
- Incorrect formats
- Extremely long values
- Invalid numbers
- Invalid email addresses
- Unexpected values
- Duplicate information
- Data that violates business rules

Validation creates a boundary between:

```
Untrusted user input
        ↓
     Validation
        ↓
Trusted application data
```

**Important:** Validation improves correctness, but it is not a replacement for security controls such as authentication, authorization, CSRF protection, parameterized SQL, and output escaping.

---

# 2. HTML Validation vs Flask Validation

There are two major places where validation can happen.

### Browser-side validation

HTML:

```
<input
    type="email"
    name="email"
    required
>
```

The browser can catch some errors before sending the request.

### Server-side validation

Flask:

```
email = request.form.get("email")

if not email:
    return "Email is required"
```

The server checks the data after receiving it.

The important rule is:

> **Never rely only on browser-side validation.**

A user can send a request directly without using your HTML form.

Therefore:

```
HTML validation
      ↓
Good user experience

Flask validation
      ↓
Actual server-side validation
```

You generally want both.

# 3. Basic Required Field Validation

Suppose:

```
<form method="POST" action="/register">

    <input
        type="text"
        name="username"
    >

    <button type="submit">
        Register
    </button>

</form>
```

Flask:

```
@app.route("/register", methods=["POST"])
def register():

    username = request.form.get("username")

    if not username:
        return "Username is required"

    return f"Welcome, {username}"
```

If the user submits nothing:

```
Username is required
```

If they submit:

```
John
```

then:

```
Welcome, John
```

---

# 4. What Does `not username` Mean?

Consider:

```
if not username:
```

This catches values such as:

```
None
""
```

For form validation, that's often useful.

But there's another common problem.

The user might enter:

```
"     "
```

That's technically a non-empty string.

So:

```
if not username:
```

would not catch it.

You can use:

```
username = request.form.get("username", "").strip()

if not username:
    return "Username is required"
```

Now:

```
"     "
```

becomes:

```
""
```

and is rejected.

# 5. Validating Multiple Fields

Suppose you have:

```
<form method="POST" action="/register">

    <input type="text" name="username">

    <input type="email" name="email">

    <input type="password" name="password">

    <button type="submit">
        Register
    </button>

</form>
```

Flask:

```
@app.route("/register", methods=["POST"])
def register():

    username = request.form.get("username", "").strip()
    email = request.form.get("email", "").strip()
    password = request.form.get("password", "")

    if not username:
        return "Username is required"

    if not email:
        return "Email is required"

    if not password:
        return "Password is required"

    return "Registration successful"
```

The validation happens **before** the application processes the data.

# 6. Length Validation

Suppose usernames must contain at least 3 characters.

```
username = request.form.get("username", "").strip()

if len(username) < 3:
    return "Username must contain at least 3 characters"
```

Maximum length:

```
if len(username) > 30:
    return "Username must not exceed 30 characters"
```

Together:

```
if len(username) < 3 or len(username) > 30:
    return "Username must be between 3 and 30 characters"
```

---

# 7. Password Validation

Suppose your application requires a password with at least 8 characters:

```
password = request.form.get("password", "")

if len(password) < 8:
    return "Password must contain at least 8 characters"
```

You can create more rules:

```
if len(password) < 8:
    return "Password must contain at least 8 characters"

if not any(char.isupper() for char in password):
    return "Password must contain an uppercase letter"

if not any(char.isdigit() for char in password):
    return "Password must contain a number"
```

This is validation.

Later, when building authentication, the password should be **hashed**, not stored as plain text.

---

# 8. Number Validation

HTML:

```
<input type="number" name="age">
```

You might receive:

```
age = request.form.get("age")
```

But there's an important detail:

> Form values are received as strings.

So:

```
age
```

might contain:

```
"25"
```

not:

```
25
```

You can convert it:

```
try:
    age = int(age)
except (TypeError, ValueError):
    return "Age must be a valid number"
```

Then validate:

```
if age < 18:
    return "Age must be at least 18"
```

---

# 9. Why Use `try/except`?

Suppose someone sends:

```
abc
```

Then:

```
int("abc")
```

causes a `ValueError`.

So this:

```
age = int(request.form.get("age"))
```

can crash the request if the input isn't numeric.

Instead:

```
try:
    age = int(request.form.get("age", ""))
except ValueError:
    return "Invalid age"
```

Now invalid input is handled gracefully.

# 10. Email Validation

HTML provides a basic browser-side check:

```
<input
    type="email"
    name="email"
>
```

But server-side validation is still necessary.

A simple approach is to check whether it has a reasonable structure:

```
email = request.form.get("email", "").strip()

if "@" not in email:
    return "Invalid email address"
```

However, real email validation can be more complicated than simply checking for `@`.

In production applications, use a well-tested validation library or framework validator rather than building an enormous regular expression yourself.

This becomes much easier when we reach **WTForms**.

# 11. Comparing Two Fields

A common example is password confirmation.

HTML:

```
<input
    type="password"
    name="password"
>

<input
    type="password"
    name="confirm_password"
>
```

Flask:

```
password = request.form.get("password", "")
confirm_password = request.form.get("confirm_password", "")

if password != confirm_password:
    return "Passwords do not match"
```

Flow:

```
Password
    │
    ├──────────────┐
    │              │
    ▼              ▼
password    confirm_password
    │              │
    └───────┬──────┘
            ▼
        Compare
            │
       ┌────┴────┐
       │         │
      Same    Different
       │         │
       ▼         ▼
    Continue    Error
```

# 12. Choice Validation

Suppose a form contains:

```
<select name="gender">
    <option value="male">Male</option>
    <option value="female">Female</option>
    <option value="other">Other</option>
</select>
```

Don't blindly trust the submitted value.

Someone could manually send:

```
gender=anything
```

Instead:

```
gender = request.form.get("gender")

allowed = {"male", "female", "other"}

if gender not in allowed:
    return "Invalid selection"
```

This is an important concept:

> **Validate against the values your application actually accepts.**

# 13. Multiple Validation Errors

Our earlier examples stop at the first error:

```
if not username:
    return "Username is required"

if not email:
    return "Email is required"
```

That's not always ideal.

Suppose both are empty.

The user sees:

```
Username is required
```

They fix it.

Then they see:

```
Email is required
```

It would be better to collect all errors first.

---

# 14. Using an Error Dictionary

```
errors = {}

username = request.form.get("username", "").strip()
email = request.form.get("email", "").strip()
password = request.form.get("password", "")

if not username:
    errors["username"] = "Username is required"

if not email:
    errors["email"] = "Email is required"

if len(password) < 8:
    errors["password"] = "Password must contain at least 8 characters"
```

Then:

```
if errors:
    return errors
```

For example, the result might be:

```
{
    "username": "Username is required",
    "email": "Email is required",
    "password": "Password must contain at least 8 characters"
}
```

Later, instead of returning this directly, you'll send the errors back to the template.

# 15. Showing Validation Errors in the Template

A better approach is:

```
@app.route("/register", methods=["GET", "POST"])
def register():

    errors = {}

    if request.method == "POST":

        username = request.form.get("username", "").strip()
        email = request.form.get("email", "").strip()

        if not username:
            errors["username"] = "Username is required"

        if not email:
            errors["email"] = "Email is required"

        if not errors:
            return "Registration successful"

    return render_template(
        "register.html",
        errors=errors
    )
```

Template:

```
<form method="POST">

    <input
        type="text"
        name="username"
    >

    {% if errors.get("username") %}
        <p>{{ errors["username"] }}</p>
    {% endif %}


    <input
        type="email"
        name="email"
    >

    {% if errors.get("email") %}
        <p>{{ errors["email"] }}</p>
    {% endif %}


    <button type="submit">
        Register
    </button>

</form>
```

Now the server can send validation errors back to the page.

# 16. Preserving User Input

There's another usability problem.

Suppose the user enters:

```
Username: John
Email: invalid
```

and the email fails validation.

You don't want the user to type everything again.

You can pass the submitted values back to the template.

Flask:

```
return render_template(
    "register.html",
    errors=errors,
    username=username,
    email=email
)
```

Template:

```
<input
    type="text"
    name="username"
    value="{{ username }}"
>

<input
    type="email"
    name="email"
    value="{{ email }}"
>
```

Now the valid information remains in the form.

# 19. Validation and Database

Validation becomes especially important before inserting data into MySQL.

A simplified workflow:

```
HTML Form
    ↓
POST
    ↓
Flask
    ↓
Get form data
    ↓
Validate
    │
    ├── Invalid → Show errors
    │
    └── Valid
          ↓
      Process data
          ↓
       MySQL
```

For example:

```
username = request.form.get("username", "").strip()

if not username:
    return "Username is required"

# Only after validation:
# INSERT INTO users ...
```

Later, we'll add database-specific concerns such as:

- Unique constraints
- Foreign keys
- Transactions
- Parameterized queries
- SQLAlchemy validation patterns

# 20. Validation Is Different From Sanitization

These concepts are often mixed together.

### Validation

Asks:

> "Is this input acceptable?"

Example:

```
if age < 18:
    return "Invalid age"
```

### Sanitization / normalization

Asks:

> "Can this input be normalized into the form we want?"

Example:

```
email = email.strip().lower()
```

Input:

```
"  USER@EXAMPLE.COM  "
```

becomes:

```
"user@example.com"
```

They are related but not identical.

---

# 21. Validation Is Also Different From Escaping

You learned **escaping** in Jinja2.

Don't confuse:

```
Validation
Escaping
Sanitization
```

They solve different problems.

|Concept|Purpose|
|---|---|
|Validation|Determine whether input is acceptable|
|Normalization|Convert input into a consistent representation|
|Escaping|Safely represent data in an output context|
|Hashing|Protect passwords when storing them|
|Parameterized SQL|Safely send values to SQL|

For example, if a user submits:

```
<script>alert(1)</script>
```

validation might decide whether that value is acceptable.

Escaping protects HTML output:

```
{{ username }}
```

Jinja's autoescaping helps prevent the browser from interpreting ordinary user-provided text as HTML.

# 22. A Practical Validation Example

Let's combine several concepts.

### `app.py`

```
from flask import Flask, request, render_template

app = Flask(__name__)


@app.route("/register", methods=["GET", "POST"])
def register():

    errors = {}

    username = ""
    email = ""

    if request.method == "POST":

        username = request.form.get("username", "").strip()
        email = request.form.get("email", "").strip()
        password = request.form.get("password", "")

        # Username
        if not username:
            errors["username"] = "Username is required"

        elif len(username) < 3:
            errors["username"] = "Username must contain at least 3 characters"

        elif len(username) > 30:
            errors["username"] = "Username must not exceed 30 characters"


        # Email
        if not email:
            errors["email"] = "Email is required"

        elif "@" not in email:
            errors["email"] = "Invalid email address"


        # Password
        if len(password) < 8:
            errors["password"] = "Password must contain at least 8 characters"


        # If everything is valid
        if not errors:
            return "Registration successful"


    return render_template(
        "register.html",
        errors=errors,
        username=username,
        email=email
    )


if __name__ == "__main__":
    app.run(debug=True)
```

# 24. Why WTForms Exists

At this point you might notice something:

Our validation code is becoming repetitive.

We're manually doing:

```
if not username:
    ...

if len(username) < 3:
    ...

if not email:
    ...

if "@" not in email:
    ...
```

Imagine a form with **20 fields**.

The Flask route could become enormous.

That's one of the reasons **WTForms** exists.

Instead of manually handling everything, you can define a form class with fields and validators.

Conceptually:

```
class RegistrationForm(FlaskForm):

    username = StringField(
        validators=[DataRequired(), Length(min=3, max=30)]
    )

    email = StringField(
        validators=[DataRequired(), Email()]
    )
```

Then WTForms handles much of the repetitive validation work.

We'll learn this properly under:

```
Module 6
└── WTForms
```

So don't worry about memorizing WTForms yet.

# Quick Reference

### Required field

```
value = request.form.get("value", "").strip()

if not value:
    return "Value is required"
```

### Minimum length

```
if len(value) < 3:
    return "Too short"
```

### Maximum length

```
if len(value) > 30:
    return "Too long"
```

### Number

```
try:
    number = int(request.form.get("number", ""))
except ValueError:
    return "Invalid number"
```

### Compare fields

```
if password != confirm_password:
    return "Passwords do not match"
```

### Allowed values

```
allowed = {"red", "green", "blue"}

if color not in allowed:
    return "Invalid color"
```

### Multiple errors

```
errors = {}

if not username:
    errors["username"] = "Username is required"

if not email:
    errors["email"] = "Email is required"

if errors:
    return render_template("form.html", errors=errors)
```
