
**Blueprints** are one of the most important features for organizing a larger Flask application.

When a Flask project becomes large, putting every route inside one `app.py` file becomes difficult to maintain.

Blueprints allow you to **split an application into smaller, logical modules**.

---

# 1. What is a Blueprint?

A **Blueprint** is a collection of Flask routes, view functions, error handlers, and related configuration that can be registered with a Flask application.

In simple words:

> A Blueprint is a **modular group of routes** that you can attach to a Flask application.

For example, imagine an application with:

```
Users
Products
Orders
Authentication
Admin
```

Instead of:

```
app.py
 ├── user routes
 ├── product routes
 ├── order routes
 ├── auth routes
 └── admin routes
```

you can organize them:

```
app/
├── users/
│   └── routes.py
├── products/
│   └── routes.py
├── orders/
│   └── routes.py
├── auth/
│   └── routes.py
└── admin/
    └── routes.py
```

Each area can have its own Blueprint.

---

# 2. Why Do We Need Blueprints?

Consider a small application:

```
from flask import Flask

app = Flask(__name__)


@app.get("/")
def home():
    return "Home"


@app.get("/users")
def users():
    return "Users"


@app.get("/products")
def products():
    return "Products"
```

This works perfectly.

But imagine you eventually have:

```
100+ routes
50+ models
Authentication
Admin
Payments
Products
Orders
Reports
API endpoints
Error handlers
```

Putting everything in one file becomes difficult.

Blueprints let you divide the application into manageable pieces.

---

# 3. Blueprint vs Flask Application

This distinction is very important.

### Flask Application

The Flask application is the **main application**.

```
app = Flask(__name__)
```

### Blueprint

A Blueprint is a **module that gets registered with the application**.

```
users_bp = Blueprint("users", __name__)
```

A Blueprint **is not an independent Flask application**.

Think of it like this:

```
                    Flask App
                       │
        ┌──────────────┼──────────────┐
        ↓              ↓              ↓
    Users BP       Products BP     Orders BP
        │              │              │
     Routes          Routes         Routes
```

The Flask application is the house.

Blueprints are organized rooms inside it. 🏠

---

# 4. Creating Your First Blueprint

Import `Blueprint`:

```
from flask import Blueprint
```

Create a Blueprint:

```
users_bp = Blueprint("users", __name__)
```

The first argument:

```
"users"
```

is the **Blueprint name**.

The second:

```
__name__
```

helps Flask determine the Blueprint's location.

---

# 5. Adding Routes to a Blueprint

```
from flask import Blueprint

users_bp = Blueprint("users", __name__)


@users_bp.get("/users")
def users():
    return {
        "message": "Users"
    }
```

Notice something important.

Instead of:

```
@app.get("/users")
```

we use:

```
@users_bp.get("/users")
```

The route belongs to the Blueprint.

---

# 6. Registering the Blueprint

Creating a Blueprint does **not** automatically add it to the Flask application.

You must register it.

```
app.register_blueprint(users_bp)
```

Complete example:

```
from flask import Flask, Blueprint

app = Flask(__name__)

users_bp = Blueprint("users", __name__)


@users_bp.get("/users")
def users():
    return {
        "message": "Users"
    }


app.register_blueprint(users_bp)
```

Now:

```
GET /users
```

will execute:

```
users()
```

---

# 7. Blueprint with `url_prefix`

One of the most useful Blueprint features is `url_prefix`.

Instead of writing:

```
users_bp = Blueprint("users", __name__)

@users_bp.get("/users")
def users():
    ...
```

you can define:

```
users_bp = Blueprint(
    "users",
    __name__,
    url_prefix="/users"
)
```

Then routes can be shorter:

```
@users_bp.get("/")
def users():
    return {"message": "Users"}
```

The final URL becomes:

```
/users/
```

---

# 8. Multiple Routes with `url_prefix`

Suppose:

```
users_bp = Blueprint(
    "users",
    __name__,
    url_prefix="/users"
)
```

Then:

```
@users_bp.get("/")
def get_users():
    ...


@users_bp.get("/<int:user_id>")
def get_user(user_id):
    ...


@users_bp.post("/")
def create_user():
    ...


@users_bp.patch("/<int:user_id>")
def update_user(user_id):
    ...


@users_bp.delete("/<int:user_id>")
def delete_user(user_id):
    ...
```

The resulting API becomes:

```
GET    /users/
GET    /users/10
POST   /users/
PATCH  /users/10
DELETE /users/10
```

This is much cleaner.

---

# 9. API Blueprint Example

For REST APIs, you might use:

```
products_bp = Blueprint(
    "products",
    __name__,
    url_prefix="/api/products"
)
```

Then:

```
@products_bp.get("/")
def get_products():
    return {"data": []}


@products_bp.get("/<int:product_id>")
def get_product(product_id):
    return {
        "id": product_id
    }
```

The resulting endpoints:

```
GET /api/products/
GET /api/products/10
```

# 10. Multiple Blueprints

A real application can have multiple Blueprints.

```
Flask Application
│
├── Auth Blueprint
├── Users Blueprint
├── Products Blueprint
├── Orders Blueprint
└── Admin Blueprint
```

For example:

### `auth.py`

```
from flask import Blueprint

auth_bp = Blueprint(
    "auth",
    __name__,
    url_prefix="/api/auth"
)


@auth_bp.post("/login")
def login():
    return {"message": "Login"}
```

### `users.py`

```
from flask import Blueprint

users_bp = Blueprint(
    "users",
    __name__,
    url_prefix="/api/users"
)


@users_bp.get("/")
def get_users():
    return {"data": []}
```

### `products.py`

```
from flask import Blueprint

products_bp = Blueprint(
    "products",
    __name__,
    url_prefix="/api/products"
)


@products_bp.get("/")
def get_products():
    return {"data": []}
```

Then register all of them:

```
app.register_blueprint(auth_bp)
app.register_blueprint(users_bp)
app.register_blueprint(products_bp)
```

# 12. Blueprint File

For example:

```
# app/routes/users.py

from flask import Blueprint

users_bp = Blueprint(
    "users",
    __name__,
    url_prefix="/api/users"
)


@users_bp.get("/")
def get_users():
    return {
        "success": True,
        "data": []
    }


@users_bp.get("/<int:user_id>")
def get_user(user_id):
    return {
        "success": True,
        "data": {
            "id": user_id
        }
    }
```

The Blueprint only defines the routes.

It does not create the main Flask application.

# 13. Registering Blueprints in the Factory

Remember the Application Factory from **11.1**?

This is where the two concepts connect.

### `app/__init__.py`

```
from flask import Flask

from .routes.users import users_bp


def create_app():
    app = Flask(__name__)

    app.register_blueprint(users_bp)

    return app
```

Now:

```
create_app()
      ↓
Create Flask App
      ↓
Register users_bp
      ↓
Return App
```

This is one of the most common Flask architectures.

---

# 14. Multiple Blueprints in the Factory

```
from flask import Flask

from .routes.auth import auth_bp
from .routes.users import users_bp
from .routes.products import products_bp


def create_app():
    app = Flask(__name__)

    app.register_blueprint(auth_bp)
    app.register_blueprint(users_bp)
    app.register_blueprint(products_bp)

    return app
```

Now your factory acts as the **central assembly point**.

```
                 create_app()
                      │
          ┌───────────┼───────────┐
          ↓           ↓           ↓
       Auth BP     Users BP    Products BP
          │           │           │
          ↓           ↓           ↓
       Routes       Routes       Routes
```

# 15. Blueprint Endpoint Names

Blueprints also affect endpoint names.

Suppose:

```
users_bp = Blueprint("users", __name__)


@users_bp.get("/")
def list_users():
    ...
```

The endpoint name becomes:

```
users.list_users
```

This matters when using:

```
url_for()
```

For example:

```
url_for("users.list_users")
```

Instead of:

```
url_for("list_users")
```

The Blueprint name acts like a namespace.

---

# 16. Why Endpoint Namespaces Are Useful

Imagine two Blueprints:

```
users.list
admin.list
```

Both could have a function named:

```
list()
```

The Blueprint separates them.

```
url_for("users.list")
```

and:

```
url_for("admin.list")
```

This prevents endpoint-name conflicts.

# 17. Blueprint with Templates

Blueprints can also work with templates.

Example:

```
app/
│
├── users/
│   ├── routes.py
│   └── templates/
│       └── users/
│           └── profile.html
```

Blueprint:

```
from flask import Blueprint, render_template

users_bp = Blueprint(
    "users",
    __name__,
    template_folder="templates"
)


@users_bp.get("/profile")
def profile():
    return render_template("users/profile.html")
```

This allows a feature to keep its routes and templates together.

---

# 18. Blueprint with Static Files

Blueprints can also have their own static files.

For example:

```
users/
│
├── routes.py
├── templates/
│   └── users/
│       └── profile.html
│
└── static/
    └── users.css
```

Blueprint:

```
users_bp = Blueprint(
    "users",
    __name__,
    template_folder="templates",
    static_folder="static"
)
```

Now the Blueprint can have its own static resources.

This becomes useful when different application modules have their own UI resources.

# 19. Blueprint vs Application Factory

These two concepts are related, but they solve different problems.

|Application Factory|Blueprint|
|---|---|
|Creates the Flask application|Organizes application modules|
|`create_app()`|`Blueprint()`|
|Handles application setup|Handles routes/features|
|Initializes extensions|Groups routes|
|Registers Blueprints|Gets registered by app|
|Useful for testing/configuration|Useful for modular architecture|

Together:

```
Application Factory
        ↓
Creates App
        ↓
Registers Blueprints
        ↓
Blueprints provide Routes
```

---

# 20. Blueprint vs Route

A route is one endpoint.

```
@app.get("/users")
def users():
    ...
```

A Blueprint can contain many routes:

```
users_bp = Blueprint("users", __name__)


@users_bp.get("/")
def get_users():
    ...


@users_bp.get("/<int:user_id>")
def get_user(user_id):
    ...


@users_bp.post("/")
def create_user():
    ...


@users_bp.delete("/<int:user_id>")
def delete_user(user_id):
    ...
```

So:

```
Route
  ↓
One endpoint

Blueprint
  ↓
Collection of related endpoints

Flask Application
  ↓
Collection of Blueprints
```

# 22. Common Mistakes

### ❌ Mistake 1: Creating a Blueprint but not registering it

```
users_bp = Blueprint("users", __name__)
```

is not enough.

You also need:

```
app.register_blueprint(users_bp)
```

Otherwise Flask doesn't know about those routes.

---

### ❌ Mistake 2: Using the wrong decorator

Inside a Blueprint:

```
@users_bp.get("/users")
```

not:

```
@app.get("/users")
```

Otherwise the route belongs directly to the application.

---

### ❌ Mistake 3: Duplicate Blueprint names

Avoid:

```
users_bp = Blueprint("users", __name__)
other_bp = Blueprint("users", __name__)
```

Blueprint names should be unique within the application.

---

### ❌ Mistake 4: Making one giant Blueprint

Don't create:

```
everything.py
```

containing hundreds of unrelated routes.

Instead:

```
auth.py
users.py
products.py
orders.py
admin.py
```

Group routes according to application responsibilities.

---

### ❌ Mistake 5: Confusing Blueprint with Application

Remember:

```
Blueprint ≠ Flask Application
```

A Blueprint needs to be registered with a Flask application.
