Images in Flask are handled as **static files**.

The key idea is simple:

> **Put images inside the `static` directory, then use `url_for('static', ...)` to generate their URL in your templates.**

Flask doesn't process the image itself. It simply makes the image available to the browser.

---

# 1. Where Do Images Go?

A recommended structure is:

```
project/
│
├── app.py
│
├── templates/
│   └── home.html
│
└── static/
    ├── css/
    │   └── style.css
    │
    ├── js/
    │   └── script.js
    │
    └── images/
        ├── logo.png
        ├── banner.jpg
        └── profile.png
```

The important part is:

```
static/images/
```

---

# 2. Displaying an Image

Suppose you have:

```
static/images/logo.png
```

In your HTML template:

```
<img src="{{ url_for('static', filename='images/logo.png') }}"
     alt="Logo">
```

That's the standard Flask approach.

---

# 3. Understanding the Path

Look at:

```
{{ url_for('static', filename='images/logo.png') }}
```

Break it down:

```
url_for()
   │
   ├── 'static'
   │
   └── filename='images/logo.png'
```

Flask already knows:

```
static/
```

So:

```
static/
+
images/logo.png
```

produces the location:

```
static/images/logo.png
```

The generated URL will normally look like:

```
/static/images/logo.png
```

# 4. Complete Example

### Project

```
project/
│
├── app.py
│
├── templates/
│   └── home.html
│
└── static/
    └── images/
        └── logo.png
```

### `app.py`

```
from flask import Flask, render_template

app = Flask(__name__)


@app.route("/")
def home():
    return render_template("home.html")


if __name__ == "__main__":
    app.run(debug=True)
```

### `home.html`

```
<!DOCTYPE html>

<html>

<head>

    <title>Images</title>

</head>

<body>

    <h1>My Website</h1>

    <img
        src="{{ url_for('static', filename='images/logo.png') }}"
        alt="Website Logo"
    >

</body>

</html>
```

When the browser loads the page, it requests the image from Flask.

---

# 5. What Happens Behind the Scenes?

Suppose the HTML contains:

```
<img src="/static/images/logo.png">
```

The browser first requests:

```
GET /
```

Flask returns the HTML.

The browser sees:

```
<img src="/static/images/logo.png">
```

Then it makes another request:

```
GET /static/images/logo.png
```

Flask finds:

```
static/images/logo.png
```

and sends the image.

The flow:

```
Browser
   │
   │ GET /
   ▼
Flask
   │
   │ home.html
   ▼
Browser
   │
   │ GET /static/images/logo.png
   ▼
Flask
   │
   │ logo.png
   ▼
Browser
   │
   ▼
Displays image
```

So the image is **not embedded into the HTML automatically**.

The HTML contains a URL pointing to the image.

---

# 6. `src` and `alt`

The basic HTML syntax is:

```
<img src="IMAGE_URL" alt="DESCRIPTION">
```

In Flask:

```
<img
    src="{{ url_for('static', filename='images/logo.png') }}"
    alt="Website Logo"
>
```

### `src`

Tells the browser where the image is.

### `alt`

Provides alternative text describing the image.

For example:

```
alt="Company logo"
```

is useful for accessibility and when the image cannot be loaded.

# 7. Different Image Formats

You can store common image formats in `static/images/`:

```
static/images/
├── logo.png
├── banner.jpg
├── icon.svg
├── photo.webp
└── animation.gif
```

Then:

```
<img src="{{ url_for('static', filename='images/banner.jpg') }}">
```

or:

```
<img src="{{ url_for('static', filename='images/icon.svg') }}">
```

The Flask process is essentially the same.

# 9. Using Images With CSS

Images aren't only used through `<img>`.

CSS can also use static images.

Suppose:

```
static/
├── css/
│   └── style.css
│
└── images/
    └── background.jpg
```

Inside `style.css`:

```
body {
    background-image: url("../images/background.jpg");
}
```

Why?

Because the CSS file is here:

```
static/css/style.css
```

and the image is here:

```
static/images/background.jpg
```

From `css/`, we go up one directory:

```
../
```

Then enter:

```
images/
```

So:

```
../images/background.jpg
```

points to the correct file.

---

# 10. Using a Flask URL in CSS

A normal external CSS file is a static file.

Therefore, don't normally do this:

```
background-image: url("{{ url_for('static', filename='images/bg.jpg') }}");
```

inside:

```
static/css/style.css
```

Instead:

```
background-image: url("../images/bg.jpg");
```

This is an important distinction.

# 11. Images With Jinja2 Variables

Suppose Flask passes an image filename to the template.

Python:

```
@app.route("/")
def home():

    image = "logo.png"

    return render_template(
        "home.html",
        image=image
    )
```

Template:

```
<img
    src="{{ url_for('static', filename='images/' + image) }}"
    alt="Logo"
>
```

If:

```
image = "logo.png"
```

Flask/Jinja2 generates the appropriate URL.

This becomes useful when the image depends on application data.

# 12. Dynamic Images From a Database

This is where Flask applications become more interesting.

Suppose a database contains:

```
username | profile_image
---------|--------------
John     | john.png
Sarah    | sarah.jpg
```

Python retrieves the filename:

```
user.profile_image
```

Then the template can use:

```
<img
    src="{{ url_for('static', filename='images/' + user.profile_image) }}"
    alt="Profile picture"
>
```

The important distinction is:

```
Database
   ↓
stores image filename/path
   ↓
Jinja2
   ↓
generates image URL
   ↓
Browser
   ↓
requests image
```

We'll deal with the database side later in **Module 7 and Module 8**.

# 13. Uploaded Images Are Different

This is a very important distinction.

There are two situations.

### A. Images that are part of your application

For example:

```
logo.png
banner.jpg
favicon.png
```

These can simply live in:

```
static/images/
```

### B. Images uploaded by users

For example:

```
User uploads profile.jpg
```

These need an **upload process**.

Typically:

```
Browser
   │
   │ multipart/form-data
   ▼
Flask
   │
   │ receives file
   ▼
Validation
   │
   ▼
Save file
   │
   ▼
Database stores filename/path
```

User-uploaded files are a separate topic from simply serving static images.

You already encountered the basics of file uploads in Module 3, and we'll connect the two concepts when needed.

---

# 14. Don't Store User Uploads Blindly

Suppose a user uploads:

```
myphoto.jpg
```

You shouldn't blindly trust:

```
file.filename
```

and save everything without validation.

A proper upload system should consider:

```
Allowed file types
File size
Filename safety
Storage location
Unique filenames
Malicious files
Path traversal
```

This becomes especially important when building production applications.

# 15. Image URL vs Image File

This distinction is useful.

Your database might contain:

```
profile_image = "john.png"
```

That's just **data**.

The actual file might be:

```
static/images/john.png
```

The browser needs a URL:

```
/static/images/john.png
```

So:

```
Database
    │
    │ "john.png"
    ▼
Flask/Jinja2
    │
    │ generates URL
    ▼
/static/images/john.png
    │
    ▼
Browser
    │
    ▼
Actual image
```

# 16. Image URL in a Loop

Suppose Flask passes:

```
products = [
    {"name": "Product 1", "image": "product1.jpg"},
    {"name": "Product 2", "image": "product2.jpg"},
]
```

Template:

```
{% for product in products %}

    <div>

        <h2>{{ product.name }}</h2>

        <img
            src="{{ url_for('static', filename='images/' + product.image) }}"
            alt="{{ product.name }}"
        >

    </div>

{% endfor %}
```

This demonstrates how Jinja2 and static images work together.

# 17. Checking Whether an Image Exists

Suppose your template expects:

```
static/images/profile.png
```

but the file doesn't exist.

The browser may show a broken image.

The Flask server may receive:

```
GET /static/images/profile.png
```

and return:

```
404 Not Found
```

So if an image isn't appearing, check:

```
1. Does the file exist?
2. Is the filename correct?
3. Is the directory correct?
4. Is the generated URL correct?
5. Is the browser receiving 404?
```

# 19. Images and `url_for()`

The general pattern is:

```
{{ url_for('static', filename='PATH_INSIDE_STATIC') }}
```

For an image:

```
{{ url_for('static', filename='images/logo.png') }}
```

For CSS:

```
{{ url_for('static', filename='css/style.css') }}
```

For JavaScript:

```
{{ url_for('static', filename='js/script.js') }}
```

Notice the pattern:

```
static/
   │
   ├── css/
   ├── js/
   └── images/
```

and `filename` specifies the path **inside** `static`.

---

# 20. Responsive Images

Flask doesn't control image responsiveness. That's CSS/HTML.

For example:

```
img {
    max-width: 100%;
    height: auto;
}
```

This allows an image to shrink with its container.

You can also give a specific class:

```
<img
    class="profile-image"
    src="{{ url_for('static', filename='images/profile.png') }}"
    alt="Profile"
>
```

```
.profile-image {
    width: 200px;
    height: 200px;
    object-fit: cover;
}
```

Again:

```
Flask → serves image
CSS → controls appearance
Browser → displays image
```

---

# 21. Image Paths: The Most Important Rule

Suppose your structure is:

```
static/
└── images/
    └── logo.png
```

In a Jinja2 template:

```
<img src="{{ url_for('static', filename='images/logo.png') }}">
```

Not:

```
<img src="{{ url_for('static', filename='static/images/logo.png') }}">
```

And not:

```
<img src="images/logo.png">
```

The Flask-friendly approach is:

```
url_for('static', filename='images/logo.png')
```

# 23. The Big Picture

At this point, your `static` directory looks like:

```
static/
│
├── css/
│   └── style.css
│
├── js/
│   └── script.js
│
└── images/
    ├── logo.png
    └── banner.jpg
```

And the browser receives them independently:

```
                  Flask
                    │
        ┌───────────┼───────────┐
        │           │           │
        ▼           ▼           ▼
      CSS          JS         Images
        │           │           │
        └───────────┼───────────┘
                    ▼
                 Browser
```

Flask is the server. The browser is the consumer.
