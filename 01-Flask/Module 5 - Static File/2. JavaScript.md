JavaScript in Flask works very similarly to CSS.

The important thing to understand is:

> **Flask serves the JavaScript file. The browser executes the JavaScript.**

Flask does not execute your frontend JavaScript.

---

# 1. Where Does JavaScript Go?

JavaScript files normally go inside Flask's `static` directory.

Recommended structure:

```
project/
│
├── app.py
│
├── templates/
│   └── home.html
│
└── static/
    ├── css/
    │   └── style.css
    │
    └── js/
        └── script.js
```

So:

```
static/js/script.js
```

is a static JavaScript file.

---

# 2. Creating a JavaScript File

Create:

```
static/js/script.js
```

Put:

```
console.log("JavaScript loaded!");
```

This is ordinary JavaScript.

Nothing Flask-specific is required inside the file.

---

# 3. Connecting JavaScript to Flask

In your template:

```
<script src="{{ url_for('static', filename='js/script.js') }}"></script>
```

For example:

```
<!DOCTYPE html>

<html>

<head>

    <title>Flask JavaScript</title>

</head>

<body>

    <h1>Hello Flask</h1>

    <script src="{{ url_for('static', filename='js/script.js') }}"></script>

</body>

</html>
```

Flask generates the URL to the JavaScript file.

---

# 4. What Happens Behind the Scenes?

Suppose:

```
static/js/script.js
```

exists.

Your template contains:

```
<script src="{{ url_for('static', filename='js/script.js') }}"></script>
```

Flask generates something like:

```
<script src="/static/js/script.js"></script>
```

The browser then makes:

```
GET /static/js/script.js
```

Flask sends the file.

The browser executes it.

So:

```
Browser
   │
   │ GET /
   ▼
Flask
   │
   │ home.html
   ▼
Browser
   │
   │ GET /static/js/script.js
   ▼
Flask
   │
   │ JavaScript
   ▼
Browser
   │
   ▼
JavaScript executes
```

This is essentially the same process you learned for CSS.

---

# 5. JavaScript Is Executed by the Browser

Suppose your JavaScript contains:

```
alert("Hello!");
```

Flask doesn't execute `alert()`.

Instead:

```
Flask
  ↓
Sends script.js
  ↓
Browser
  ↓
JavaScript engine
  ↓
alert()
```

So the technologies have different responsibilities:

|Technology|Main responsibility|
|---|---|
|Flask/Python|Backend|
|Jinja2|Generate HTML|
|HTML|Page structure|
|CSS|Styling|
|JavaScript|Browser behavior|

---

# 6. External JavaScript vs Inline JavaScript

You can write JavaScript directly in HTML:

```
<script>

    console.log("Hello");

</script>
```

This is **inline JavaScript**.

But Flask applications commonly use external files:

```
<script src="{{ url_for('static', filename='js/script.js') }}"></script>
```

with:

```
static/js/script.js
```

External files are generally easier to organize and maintain.

---

# 7. Multiple JavaScript Files

You can have:

```
static/
└── js/
    ├── main.js
    ├── auth.js
    ├── dashboard.js
    └── forms.js
```

Then:

```
<script src="{{ url_for('static', filename='js/main.js') }}"></script>

<script src="{{ url_for('static', filename='js/auth.js') }}"></script>
```

You don't have to load every JavaScript file on every page.

Only load what the page needs.

---

# 8. JavaScript With Template Inheritance

This is a very useful Flask pattern.

Suppose your `base.html` contains:

```
<body>

    {% block content %}
    {% endblock %}

    <script src="{{ url_for('static', filename='js/main.js') }}"></script>

</body>
```

Every page that extends `base.html` automatically gets:

```
main.js
```

---

# 9. Page-Specific JavaScript

Suppose only the dashboard needs:

```
dashboard.js
```

You can create a block.

### `base.html`

```
<body>

    {% block content %}
    {% endblock %}


    <script src="{{ url_for('static', filename='js/main.js') }}"></script>

    {% block scripts %}
    {% endblock %}

</body>
```

Then in `dashboard.html`:

```
{% extends "base.html" %}


{% block content %}

    <h1>Dashboard</h1>

{% endblock %}


{% block scripts %}

<script src="{{ url_for('static', filename='js/dashboard.js') }}"></script>

{% endblock %}
```

Now:

```
Every page
    ↓
main.js

Dashboard only
    ↓
dashboard.js
```

This is a clean approach.

---

# 10. Where Should the `<script>` Go?

You can put:

```
<script src="..."></script>
```

inside `<head>`.

But a common approach is putting it near the end of `<body>`:

```
<body>

    <h1>Hello</h1>

    <button id="btn">
        Click
    </button>


    <script src="{{ url_for('static', filename='js/script.js') }}"></script>

</body>
```

Why?

Because the browser can load the HTML elements before the JavaScript runs.

---

# 11. The `defer` Attribute

Another good approach is:

```
<script
    src="{{ url_for('static', filename='js/script.js') }}"
    defer>
</script>
```

`defer` tells the browser to download the JavaScript while parsing the HTML, but execute it after the HTML has been parsed.

This lets you safely put scripts in `<head>`:

```
<head>

    <script
        src="{{ url_for('static', filename='js/script.js') }}"
        defer>
    </script>

</head>
```

You will encounter `defer` frequently in modern web development.

---

# 12. JavaScript Can Modify the HTML

Suppose:

```
<h1 id="title">
    Hello
</h1>
```

JavaScript:

```
const title = document.getElementById("title");

title.textContent = "Hello Flask!";
```

The browser changes:

```
Hello
```

to:

```
Hello Flask!
```

Flask doesn't have to render a new page for this change.

That's one of JavaScript's major roles.

---

# 13. JavaScript Can Respond to Events

HTML:

```
<button id="button">
    Click Me
</button>
```

JavaScript:

```
const button = document.getElementById("button");

button.addEventListener("click", function () {

    alert("Button clicked!");

});
```

The browser handles the click.

The flow is:

```
User clicks button
       ↓
Browser detects event
       ↓
JavaScript executes
       ↓
Page changes
```

No Flask request is necessarily required.

---

# 14. Flask and JavaScript Work Together

This is one of the most important concepts.

Imagine:

```
                 Web Application
                       │
          ┌────────────┴────────────┐
          │                         │
       Backend                   Frontend
          │                         │
        Flask                    Browser
          │                         │
       Python                HTML/CSS/JavaScript
          │                         │
          └────────────┬────────────┘
                       │
                    HTTP
```

Flask handles server-side operations.

JavaScript handles browser-side operations.

They communicate through HTTP when necessary.

---

# 15. JavaScript Does NOT Automatically Know Flask Variables

This is a very common confusion.

Suppose Flask does:

```
@app.route("/")
def home():

    username = "John"

    return render_template(
        "home.html",
        username=username
    )
```

Your HTML can directly use:

```
<h1>Hello {{ username }}</h1>
```

because Jinja2 processes the HTML template.

But this external file:

```
static/js/script.js
```

doesn't automatically have access to:

```
username
```

because Flask does not process that `.js` file through Jinja2.

---

# 16. Passing Flask Data to JavaScript

One simple method is using HTML.

Flask:

```
@app.route("/")
def home():

    username = "John"

    return render_template(
        "home.html",
        username=username
    )
```

HTML:

```
<div id="user"
     data-username="{{ username }}">
</div>
```

The generated HTML becomes something like:

```
<div id="user"
     data-username="John">
</div>
```

JavaScript:

```
const user = document.getElementById("user");

const username = user.dataset.username;

console.log(username);
```

So:

```
Python
 ↓
Jinja2
 ↓
HTML data attribute
 ↓
JavaScript
```

---

# 17. Another Method: JSON Data

You can also pass structured data to JavaScript.

Suppose Flask has:

```
user = {
    "name": "John",
    "age": 25
}
```

Jinja2 provides tools for safely embedding data as JavaScript-compatible JSON.

For example:

```
<script>
    const user = {{ user | tojson }};
</script>
```

The resulting JavaScript can contain an object representing the data.

This is useful when passing multiple values.

Later, when we study APIs, you'll see an even more important way for JavaScript and Flask to communicate: **HTTP requests containing JSON**.

---

# 18. JavaScript Can Send Requests to Flask

This is where frontend and backend become much more interesting.

JavaScript can send a request to a Flask route.

For example:

```
fetch("/api/data")
    .then(response => response.json())
    .then(data => {
        console.log(data);
    });
```

Flask:

```
@app.route("/api/data")
def data():

    return {
        "message": "Hello from Flask"
    }
```

The flow:

```
JavaScript
    │
    │ HTTP request
    ▼
Flask
    │
    │ JSON response
    ▼
JavaScript
```

This is the basic idea behind modern web applications and REST APIs.

We'll study this properly in **Module 10: REST API**.

---

# 19. JavaScript Can Submit Forms

A normal form:

```
<form method="POST">

    <input name="username">

    <button type="submit">
        Submit
    </button>

</form>
```

can send a request to Flask.

But JavaScript can also intercept the form and send the data itself.

For example:

```
const form = document.getElementById("form");

form.addEventListener("submit", function(event) {

    event.preventDefault();

    // JavaScript can now handle the data.

});
```

This allows you to create interfaces that don't need a full page reload for every action.

# 20. JavaScript + Flask Architecture

A traditional Flask application might work like:

```
Browser
   │
   │ GET /
   ▼
Flask
   │
   ▼
Jinja2
   │
   ▼
HTML
   │
   ▼

```

Then JavaScript runs in the browser.

A more interactive application might work like:

```
Browser
   │
   ├── HTML/CSS
   │
   └── JavaScript
          │
          │ fetch()
          ▼
       Flask API
          │
          ▼
       Database
          │
          ▼
       JSON
          │
          ▼
      JavaScript
          │
          ▼
       Update UI
```

This architecture becomes especially important when we reach **REST APIs**.

# 21. JavaScript File Paths

Suppose:

```
static/
└── js/
    └── script.js
```

Use:

```
{{ url_for('static', filename='js/script.js') }}
```

Not:

```
{{ url_for('static', filename='static/js/script.js') }}
```

Remember:

```
static/
   +
js/script.js
   =
static/js/script.js
```

The `filename` is the path **inside** `static`.

# 22. JavaScript Loading Error

If the browser reports:

```
GET /static/js/script.js 404
```

check:

```
project/
└── static/
    └── js/
        └── script.js
```

and:

```
<script src="{{ url_for('static', filename='js/script.js') }}"></script>
```

Also check the browser's:

```
Developer Tools
      ↓
Network
      ↓
script.js
```

---

# 23. JavaScript Errors Are Different From Flask Errors

Suppose the browser console shows:

```
Uncaught ReferenceError
```

That is generally a **JavaScript-side error**, not a Flask routing error.

For example:

```
console.log(username);
```

when `username` doesn't exist could produce a JavaScript error.

You should inspect:

```
Browser Developer Tools
        ↓
Console
```

for frontend JavaScript errors.

Meanwhile, Flask errors appear in the Flask/Python server output.

So when debugging:

```
Browser Console
    ↓
JavaScript problems

Flask Terminal
    ↓
Python / Flask problems
```

---

# 24. Static JavaScript Is Not Jinja2

This deserves repetition because it's a common source of confusion.

This:

```
templates/home.html
```

can contain:

```
<script>

    const username = "{{ username }}";

</script>
```

because Jinja2 processes `home.html`.

But:

```
static/js/script.js
```

doesn't normally process:

```
const username = "{{ username }}";
```

as a Jinja2 expression.

For external JavaScript, use a proper data-passing mechanism such as HTML `data-*` attributes, JSON embedded in the page, or an API request.

# 25. A Small Complete Example

### Project

```
project/
│
├── app.py
│
├── templates/
│   └── home.html
│
└── static/
    ├── css/
    │   └── style.css
    │
    └── js/
        └── script.js
```

### `app.py`

```
from flask import Flask, render_template

app = Flask(__name__)


@app.route("/")
def home():

    return render_template("home.html")


if __name__ == "__main__":
    app.run(debug=True)
```

### `home.html`

```
<!DOCTYPE html>

<html>

<head>

    <title>Flask JavaScript</title>

    <link rel="stylesheet"
          href="{{ url_for('static', filename='css/style.css') }}">

</head>

<body>

    <h1 id="title">
        Hello Flask
    </h1>

    <button id="button">
        Change Text
    </button>


    <script
        src="{{ url_for('static', filename='js/script.js') }}">
    </script>

</body>

</html>
```

### `script.js`

```
const button = document.getElementById("button");

const title = document.getElementById("title");


button.addEventListener("click", function() {

    title.textContent = "JavaScript is working!";

});
```

Now:

```
Browser loads home.html
        ↓
Browser requests script.js
        ↓
JavaScript loads
        ↓
User clicks button
        ↓
JavaScript changes <h1>
```

No new Flask request is required for the button click.

# 26. The Three Important Relationships

### Flask → JavaScript

Flask **serves** the JavaScript file.

```
Flask
 ↓
script.js
 ↓
Browser
```

### Jinja2 → JavaScript

Jinja2 can provide data to JavaScript **when JavaScript is embedded in a template or data is passed through the rendered HTML**.

```
Python
 ↓
Jinja2
 ↓
HTML
 ↓
JavaScript
```

### JavaScript → Flask

JavaScript can send HTTP requests to Flask.

```
JavaScript
 ↓
HTTP request
 ↓
Flask
 ↓
Response
 ↓
JavaScript
```

That third relationship becomes the foundation of **REST APIs**.
