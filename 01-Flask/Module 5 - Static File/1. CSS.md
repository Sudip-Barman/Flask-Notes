CSS itself is not a Flask feature. **CSS is used to style the HTML that Flask sends to the browser.**

Flask's job is mainly to **serve the CSS file** to the browser.

The basic relationship is:

```
Flask
  │
  ├── HTML template
  │      ↓
  │   Jinja2
  │      ↓
  │   HTML
  │
  └── CSS file
         ↓
      Browser
         ↓
    Styled webpage
```

---

# 1. Where Does CSS Go?

Flask conventionally keeps CSS inside the `static` directory.

A simple project:

```
myproject/
│
├── app.py
│
├── templates/
│   └── home.html
│
└── static/
    └── style.css
```

You can also organize it:

```
static/
└── css/
    └── style.css
```

For anything beyond a tiny project, I recommend the second structure.

---

# 2. Creating a CSS File

Create:

```
static/css/style.css
```

Put:

```
body {
    font-family: Arial, sans-serif;
}

h1 {
    color: blue;
}
```

This is ordinary CSS. Flask does not require any special syntax inside the `.css` file.

---

# 3. Connecting CSS to a Flask Template

Suppose your template is:

```
templates/home.html
```

You might have:

```
<!DOCTYPE html>

<html>

<head>

    <title>Home</title>

</head>

<body>

    <h1>Hello Flask</h1>

</body>

</html>
```

Now connect the CSS:

```
<link rel="stylesheet"
      href="{{ url_for('static', filename='css/style.css') }}">
```

So:

```
<!DOCTYPE html>

<html>

<head>

    <title>Home</title>

    <link rel="stylesheet"
          href="{{ url_for('static', filename='css/style.css') }}">

</head>

<body>

    <h1>Hello Flask</h1>

</body>

</html>
```

---

# 4. Understanding the `url_for()`

This is the most important Flask-specific part.

```
{{ url_for('static', filename='css/style.css') }}
```

Break it apart:

```
url_for()
   │
   ├── 'static'
   │
   └── filename='css/style.css'
```

### `static`

This tells Flask:

> I want a file from the static-file system.

### `filename`

This tells Flask which file:

```
css/style.css
```

Because the actual structure is:

```
static/
└── css/
    └── style.css
```

So Flask can construct the appropriate URL.

---

# 5. Why Not Just Write `/static/css/style.css`?

You could write:

```
<link rel="stylesheet"
      href="/static/css/style.css">
```

and it can work.

But in Flask templates, prefer:

```
<link rel="stylesheet"
      href="{{ url_for('static', filename='css/style.css') }}">
```

Why?

Because `url_for()` lets Flask generate the URL instead of making your template depend on a hard-coded path.

This becomes particularly useful when application configuration changes.

---

# 6. What Actually Happens?

Suppose you have:

```
static/css/style.css
```

and:

```
{{ url_for('static', filename='css/style.css') }}
```

Flask generates a URL similar to:

```
/static/css/style.css
```

The browser receives HTML containing something like:

```
<link rel="stylesheet"
      href="/static/css/style.css">
```

Then the browser makes another request:

```
GET /static/css/style.css
```

Flask serves the CSS file.

So there are actually **two separate requests** involved:

```
Browser
   │
   │ GET /
   ▼
Flask
   │
   │ HTML
   ▼
Browser
   │
   │ GET /static/css/style.css
   ▼
Flask
   │
   │ CSS
   ▼
Browser
```

This is an important concept.

# 7. Complete Working Example

## Project

```
myproject/
│
├── app.py
│
├── templates/
│   └── home.html
│
└── static/
    └── css/
        └── style.css
```

## `app.py`

```
from flask import Flask, render_template

app = Flask(__name__)


@app.route("/")
def home():
    return render_template("home.html")


if __name__ == "__main__":
    app.run(debug=True)
```

## `home.html`

```
<!DOCTYPE html>

<html>

<head>

    <title>Flask CSS</title>

    <link rel="stylesheet"
          href="{{ url_for('static', filename='css/style.css') }}">

</head>

<body>

    <h1>Hello Flask</h1>

    <p>This page is styled using CSS.</p>

</body>

</html>
```

## `style.css`

```
body {
    font-family: Arial, sans-serif;
    background-color: lightgray;
}

h1 {
    color: blue;
}

p {
    font-size: 20px;
}
```

Now Flask renders the HTML, and the browser loads the CSS.

---

# 8. CSS Can Be Applied in Three Ways

You may already know these from HTML/CSS.

### Inline CSS

```
<h1 style="color: red;">
    Hello
</h1>
```

### Internal CSS

```
<style>

h1 {
    color: red;
}

</style>
```

### External CSS

```
<link rel="stylesheet"
      href="{{ url_for('static', filename='css/style.css') }}">
```

For Flask applications, **external CSS is generally the preferred approach**.

Why?

Because it keeps:

```
HTML
```

and:

```
CSS
```

separate.

---

# 9. Multiple CSS Files

You don't have to put everything into one CSS file.

For example:

```
static/
└── css/
    ├── style.css
    ├── navbar.css
    └── forms.css
```

Then:

```
<link rel="stylesheet"
      href="{{ url_for('static', filename='css/style.css') }}">

<link rel="stylesheet"
      href="{{ url_for('static', filename='css/navbar.css') }}">

<link rel="stylesheet"
      href="{{ url_for('static', filename='css/forms.css') }}">
```

The browser loads all three.

---

# 10. Organizing CSS

For a larger Flask application, you might have:

```
static/
└── css/
    ├── base.css
    ├── navbar.css
    ├── forms.css
    ├── buttons.css
    ├── dashboard.css
    └── responsive.css
```

This can make maintenance easier.

However, don't split CSS into dozens of tiny files without a reason. Every file adds another resource the browser may need to request.

A sensible structure is better than CSS confetti. 🎨

---

# 11. CSS With Template Inheritance

This connects directly to what we learned in Module 4.

Suppose:

```
templates/
├── base.html
├── home.html
└── about.html
```

You don't want to write the main CSS link in every page.

Put it in `base.html`.

```
<head>

    <title>
        {% block title %}
        {% endblock %}
    </title>

    <link rel="stylesheet"
          href="{{ url_for('static', filename='css/style.css') }}">

</head>
```

Then:

```
{% extends "base.html" %}
```

in the child templates.

Now all child pages inherit the stylesheet.

---

# 12. Page-Specific CSS

Sometimes `home.html` needs special CSS that other pages don't need.

You can create a block.

### `base.html`

```
<head>

    <link rel="stylesheet"
          href="{{ url_for('static', filename='css/style.css') }}">

    {% block styles %}
    {% endblock %}

</head>
```

Then in `home.html`:

```
{% extends "base.html" %}

{% block styles %}

<link rel="stylesheet"
      href="{{ url_for('static', filename='css/home.css') }}">

{% endblock %}
```

Now:

```
Every page
   ↓
style.css

Home page
   ↓
style.css
+
home.css
```

This is a very useful pattern.

---

# 13. CSS and Jinja2 Are Different

A common beginner confusion is thinking Jinja2 works inside CSS automatically.

For example:

```
body {
    color: {{ color }};
}
```

inside:

```
static/css/style.css
```

will **not normally be processed by Jinja2**.

Why?

Because:

```
static/css/style.css
```

is a static file.

Jinja2 processes:

```
templates/*.html
```

not your normal external CSS files.

---

# 14. So How Does CSS Get Dynamic Data?

Suppose Python sends:

```
color = "blue"

return render_template(
    "home.html",
    color=color
)
```

You can use Jinja2 inside the HTML:

```
<style>

body {
    color: {{ color }};
}

</style>
```

because the `<style>` block is inside the Jinja2 template.

But this:

```
static/css/style.css
```

doesn't automatically get processed by Jinja2.

---

# 15. Better Approach for Dynamic Styling

Instead of generating an entire CSS file dynamically, you can often use HTML attributes/classes.

For example:

```
<div class="theme-blue">
    Content
</div>
```

and CSS:

```
.theme-blue {
    color: blue;
}
```

Or conditionally select a class using Jinja2:

```
<div class="{{ theme }}">
    Content
</div>
```

Then your static CSS defines:

```
.light {
    background: white;
}

.dark {
    background: black;
}
```

This keeps your CSS static while Jinja2 controls which class is used.

---

# 16. CSS Paths Inside CSS

Here's an important path detail.

Suppose:

```
static/
├── css/
│   └── style.css
│
├── images/
│   └── background.jpg
│
└── fonts/
    └── myfont.woff2
```

Inside `style.css`, you can reference the image using a relative URL:

```
body {
    background-image: url("../images/background.jpg");
}
```

Why `../`?

Because the CSS file is inside:

```
static/css/
```

Going one level up:

```
static/css/
      ↑
     ../
```

takes you to:

```
static/
```

Then:

```
images/background.jpg
```

So:

```
../images/background.jpg
```

points to:

```
static/images/background.jpg
```

---

# 17. CSS and Flask URL Generation

You generally **cannot use Flask's Jinja2 `url_for()` directly inside a normal external CSS file**.

Don't do:

```
background-image: url("{{ url_for('static', filename='images/bg.jpg') }}");
```

inside:

```
static/css/style.css
```

Instead, use the appropriate relative path:

```
background-image: url("../images/bg.jpg");
```

Or handle dynamic URLs through the HTML/template layer when necessary.

---

# 18. CSS File 404

If your browser reports:

```
GET /static/css/style.css 404
```

check:

### 1. Does the file exist?

```
static/
└── css/
    └── style.css
```

### 2. Is the filename correct?

```
style.css
```

not:

```
styles.css
```

### 3. Is your template using the correct path?

```
{{ url_for('static', filename='css/style.css') }}
```

### 4. Did you accidentally write:

```
filename='static/css/style.css'
```

Wrong.

Use:

```
filename='css/style.css'
```

# 19. Browser Developer Tools

When CSS isn't working, the browser's developer tools are extremely useful.

Open:

```
F12
```

or:

```
Ctrl + Shift + I
```

Then check:

```
Network
```

Reload the page.

You should see something like:

```
/
static/css/style.css
```

If `style.css` returns:

```
200
```

the file was successfully loaded.

If it returns:

```
404
```

the path/file is wrong.

If it returns:

```
200
```

but the styling still doesn't work, the problem is probably inside the CSS or caused by another CSS rule.

# 20. Flask Isn't "Running" the CSS

This distinction is worth remembering.

When you write:

```
h1 {
    color: blue;
}
```

Flask doesn't interpret:

```
color: blue;
```

The browser does.

The roles are:

```
Flask
  ↓
Serves CSS

Browser
  ↓
Interprets CSS

CSS
  ↓
Styles HTML
```

So Flask is primarily the **delivery mechanism** for the CSS file.

# 21. Development vs Production

During development:

```
app.run(debug=True)
```

Flask's built-in development server serves your static files.

For production, static files are often handled more efficiently by:

```
Nginx
CDN
Cloud storage
Web server
```

depending on the deployment architecture.

We'll cover production configuration in **Module 12**.

For now, Flask's built-in static-file handling is completely fine for learning and development.

# 25. The Core Concept

If you remember only one thing from this topic, remember:

```
static/
    ↓
Files that the browser needs directly

templates/
    ↓
HTML that Flask/Jinja2 generates
```

And when referencing a static file from a Jinja2 template:

```
{{ url_for('static', filename='PATH_INSIDE_STATIC') }}
```

For CSS:

```
{{ url_for('static', filename='css/style.css') }}
```

That's the Flask-specific part. Everything inside `style.css` is then just normal CSS.
