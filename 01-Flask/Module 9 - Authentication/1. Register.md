## 1. What is Registration?

**Registration** is the process through which a new user creates an account in an application.

For example, a registration form might contain:

```
Name
Email
Password
Confirm Password
        ↓
     Register
```

The application receives this information and creates a new user account.

### Simple flow

```
User
 │
 │ enters name, email, password
 ↓
Registration Form
 │
 ↓
Flask Route
 │
 ├── Validate input
 ├── Check existing user
 ├── Hash password
 ├── Create User object
 └── Save to database
 │
 ↓
Database
```

---

# 2. Why Do We Need Registration?

Without registration, an application cannot easily maintain individual user accounts.

Registration allows an application to associate data with a specific user.

For example:

```
User A
 ├── Profile
 ├── Orders
 └── Settings

User B
 ├── Profile
 ├── Orders
 └── Settings
```

Each user gets their own account.

---

# 3. Registration vs Authentication

These terms are related but different.

|Term|Meaning|
|---|---|
|Registration|Creating an account|
|Authentication|Verifying who the user is|
|Login|Common process used for authentication|
|Authorization|Deciding what the user is allowed to do|

For example:

```
Register
   ↓
Account created

Login
   ↓
Identity verified

Authorization
   ↓
Can this user access this page?
```

# 4. Basic User Model

A registered user usually needs a database table.

For example:

```
class User(db.Model):
    __tablename__ = "users"

    id = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(100), nullable=False)
    email = db.Column(db.String(120), unique=True, nullable=False)
    password = db.Column(db.String(255), nullable=False)
```

This creates a conceptual structure like:

|id|name|email|password|
|---|---|---|---|
|1|Rahul|[rahul@example.com](mailto:rahul@example.com)|hashed password|
|2|Priya|[priya@example.com](mailto:priya@example.com)|hashed password|

Notice something important:

> The database should store a **password hash**, not the user's original password.

We'll cover this properly in **9.3 Password Hashing**.

# 6. Reading Registration Data in Flask

For a normal HTML form:

```
request.form
```

Example:

```
from flask import request

name = request.form.get("name")
email = request.form.get("email")
password = request.form.get("password")
```

### Why `.get()`?

You could write:

```
request.form["name"]
```

But `.get()` is often safer when a field may be missing:

```
request.form.get("name")
```

If the field doesn't exist, `.get()` returns:

```
None
```

instead of immediately raising a `KeyError`.

# 7. Basic Registration Route

A simplified example:

```
from flask import Flask, request

app = Flask(__name__)


@app.route("/register", methods=["GET", "POST"])
def register():

    if request.method == "POST":

        name = request.form.get("name")
        email = request.form.get("email")
        password = request.form.get("password")

        print(name)
        print(email)
        print(password)

        return "Registration successful"

    return "Registration form"
```

The route supports two methods:

```
GET
 ↓
Show registration form

POST
 ↓
Process registration data
```

# 8. Registration with SQLAlchemy

Now let's connect registration to the database.

Suppose we have:

```
class User(db.Model):
    __tablename__ = "users"

    id = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(100), nullable=False)
    email = db.Column(db.String(120), unique=True, nullable=False)
    password = db.Column(db.String(255), nullable=False)
```

Then:

```
@app.route("/register", methods=["GET", "POST"])
def register():

    if request.method == "POST":

        name = request.form.get("name")
        email = request.form.get("email")
        password = request.form.get("password")

        user = User(
            name=name,
            email=email,
            password=password
        )

        db.session.add(user)
        db.session.commit()

        return "Registration successful"

    return "Registration form"
```

However, **this code has a serious security problem**.

It stores the password directly.

```
password=password
```

That means if the database contains:

```
secret123
```

someone with access to the database could see the actual password.

❌ **Never store plain-text passwords.**

We'll fix this using password hashing in Topic 9.3.

---

# 9. Duplicate Email

Since we usually make email unique:

```
email = db.Column(
    db.String(120),
    unique=True,
    nullable=False
)
```

two users cannot normally register with the same email.

For example:

```
rahul@example.com
```

already exists.

Another registration attempt:

```
rahul@example.com
```

should be rejected.

---

# 10. Check Existing User

Before creating a new user, we can check whether the email already exists.

```
existing_user = User.query.filter_by(
    email=email
).first()
```

Then:

```
if existing_user:
    return "Email already registered"
```

Complete basic flow:

```
@app.route("/register", methods=["POST"])
def register():

    name = request.form.get("name")
    email = request.form.get("email")
    password = request.form.get("password")

    existing_user = User.query.filter_by(
        email=email
    ).first()

    if existing_user:
        return "Email already registered"

    user = User(
        name=name,
        email=email,
        password=password
    )

    db.session.add(user)
    db.session.commit()

    return "Registration successful"
```

Again, the password portion is intentionally simplified here. **Do not use this version in a real application until password hashing is added.**

# 11. Input Validation

Registration data should be validated before saving it.

For example:

```
if not name:
    return "Name is required"

if not email:
    return "Email is required"

if not password:
    return "Password is required"
```

You can also validate password length:

```
if len(password) < 8:
    return "Password must contain at least 8 characters"
```

You may validate:

- Required fields
- Email format
- Password length
- Password confirmation
- Duplicate email
- Allowed values
- Input length

# 12. Confirm Password

Many registration forms contain:

```
Password
Confirm Password
```

HTML:

```
<input
    type="password"
    name="password"
>

<input
    type="password"
    name="confirm_password"
>
```

Flask:

```
password = request.form.get("password")
confirm_password = request.form.get("confirm_password")
```

Then:

```
if password != confirm_password:
    return "Passwords do not match"
```

Important:

> `confirm_password` is normally used only for validation. You don't need to store it in the database.

# 13. Better Registration Flow

A more realistic registration process looks like this:

```
User submits form
       ↓
Read form data
       ↓
Validate required fields
       ↓
Validate email
       ↓
Validate password
       ↓
Check password confirmation
       ↓
Check duplicate email
       ↓
Hash password
       ↓
Create User object
       ↓
db.session.add()
       ↓
db.session.commit()
       ↓
Registration successful
```

This is the pattern you should remember.

# 14. Registration and Transactions

Since registration modifies the database, it is part of a database transaction.

Typical operation:

```
db.session.add(user)
db.session.commit()
```

If something goes wrong:

```
try:
    db.session.add(user)
    db.session.commit()

except Exception:
    db.session.rollback()
    raise
```

This connects directly with what you learned in **Module 8: Transactions**.

# 15. Registration API

Registration doesn't have to use HTML forms.

A REST API can accept JSON.

Request:

```
{
    "name": "Rahul",
    "email": "rahul@example.com",
    "password": "secret123"
}
```

Flask:

```
@app.route("/api/register", methods=["POST"])
def register():

    data = request.get_json()

    name = data.get("name")
    email = data.get("email")
    password = data.get("password")

    return {
        "message": "Registration successful"
    }
```

Later, the password will be hashed before storing it.

---

# 16. HTML Form vs JSON API

|HTML Form|JSON API|
|---|---|
|`request.form`|`request.get_json()`|
|Browser form|Frontend/mobile/API client|
|`application/x-www-form-urlencoded` or multipart|`application/json`|
|Often returns HTML/redirect|Usually returns JSON|

Example:

### HTML

```
name = request.form.get("name")
```

### JSON

```
data = request.get_json()
name = data.get("name")
```

# 17. Security Rules for Registration 🔒

These are important.

### ❌ Never store plain-text passwords

Bad:

```
user.password = password
```

when `password` is the original user password.

### ✅ Hash the password

Conceptually:

```
Original password
       ↓
Password hashing algorithm
       ↓
Password hash
       ↓
Database
```

We'll implement this in **9.3**.

---

### ❌ Don't trust user input

Never assume:

```
email is valid
password is strong
name is present
```

Validate everything coming from the client.

---

### ❌ Don't reveal unnecessary information

For authentication systems, be careful about messages that reveal whether an account exists.

For example, in some login/reset-password scenarios, responses such as:

```
This email exists
```

can allow account enumeration.
