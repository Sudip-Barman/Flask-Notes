
Debug Mode is one of the most useful features of Flask during development. It helps you find errors quickly and saves you from restarting the server after every code change.

---

# What is Debug Mode?

## Definition

**Debug Mode** is a development feature in Flask that:

- Automatically reloads the server when your code changes.
- Displays detailed error messages in the browser.
- Helps developers identify and fix problems faster.

> **Simple Definition:**  
> Debug Mode makes developing Flask applications easier by automatically updating changes and showing detailed error information.

---

# Why Do We Need Debug Mode?

Imagine writing code like this:

```
@app.route("/")
def home():
    return "Hello Flask!"
```

Without Debug Mode:

1. Edit the file.
2. Save it.
3. Stop the server.
4. Start the server again.
5. Refresh the browser.

Every small change requires restarting the server.

With Debug Mode:

1. Edit the file.
2. Save it.
3. Refresh the browser.

Flask reloads the application automatically.

---

# Enabling Debug Mode

## Method 1 (Most Common)

```
from flask import Flask

app = Flask(__name__)

@app.route("/")
def home():
    return "Hello Flask!"

if __name__ == "__main__":
    app.run(debug=True)
```

The `debug=True` argument enables Debug Mode.

---

## Method 2 (Recommended for Larger Projects)

Instead of writing `debug=True` in your code, you can use the Flask CLI.

Windows (Command Prompt):

```
set FLASK_DEBUG=1
flask run
```

Linux/macOS:

```
export FLASK_DEBUG=1
flask run
```

This keeps your source code cleaner.

---

# What Happens When Debug Mode is Enabled?

Suppose you change:

```
return "Hello Flask!"
```

to

```
return "Welcome to Flask!"
```

Save the file.

The terminal shows something like:

```
* Detected change in 'app.py'
* Restarting with stat
```

Now refresh your browser.

Output:

```
Welcome to Flask!
```

No manual restart needed.

# Error Reporting

Consider this code:

```
@app.route("/")
def home():
    return message
```

`message` has never been defined.

When you visit the page, Flask raises an error.

Without Debug Mode:

```
Internal Server Error
```

You know something went wrong, but not where.

With Debug Mode:

```
NameError

name 'message' is not defined

File: app.py

Line: 5
```

Flask tells you:

- Error type
- Error message
- File name
- Line number
- Stack trace

This makes debugging much easier.

---

# The Debugger

When Debug Mode is enabled, Flask provides an interactive debugger.

It shows:

- Exception type
- Stack trace
- Local variables
- Call history

This helps you understand exactly what caused the error.

# Development vs Production

|Feature|Development|Production|
|---|---|---|
|Debug Mode|✅ Enabled|❌ Disabled|
|Auto Reload|✅|❌|
|Detailed Errors|✅|❌|
|Performance|Less Important|Important|
|Security|Less Secure|Secure|

---

# Why Shouldn't You Use Debug Mode in Production?

Debug Mode exposes internal details about your application.

If an error occurs, users could see:

- File paths
- Source code information
- Variable values
- Configuration details

This can become a security risk.

Always disable Debug Mode before deploying your application.

---

# Running in Production

Instead of:

```
app.run(debug=True)
```

Use:

```
app.run()
```

Or better yet, use a production server like **Waitress** (Windows) or **Gunicorn** (Linux), which we'll cover later.

---

# Common Mistakes

### ❌ Leaving Debug Mode Enabled

```
app.run(debug=True)
```

Do not deploy production applications with this setting.

---

### ❌ Assuming Debug Mode Fixes Errors

Debug Mode only helps you **find** errors. It does not correct them automatically.

---

### ❌ Ignoring Terminal Output

Even with the browser debugger, the terminal often contains valuable information. Always check both.

---

# Best Practices

- Enable Debug Mode only while developing.
- Read the full error message before changing your code.
- Fix the root cause instead of hiding the error.
- Disable Debug Mode before deployment.
