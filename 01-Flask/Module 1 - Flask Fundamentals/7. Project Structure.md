# Definition

A **project structure** is the way we organize the files and folders of a Flask application.

A good project structure makes your application:

- Easy to understand
- Easy to maintain
- Easy to debug
- Easy to scale
- Easy to collaborate on

> **Simple Definition:**  
> A project structure is the organized layout of all files and folders in your Flask project.

---

# Why is Project Structure Important?

Imagine writing an entire book on one page.

```
Chapter 1
Chapter 2
Chapter 3
Chapter 4
Chapter 5
...
```

Finding anything would be difficult.

Instead, books are divided into chapters.

Similarly, a Flask application is divided into folders.

---

# Beginner Project Structure

For learning Flask, we'll use this structure:

```
FlaskTutorial/
│
├── .venv/
├── app.py
├── requirements.txt
├── .gitignore
├── templates/
├── static/
└── instance/
```

Let's understand each part.

---

# 1. `.venv/`

```
.venv/
```

Contains the virtual environment.

Stores:

- Python interpreter
- Installed packages
- pip
- Flask

### Purpose

Keeps project dependencies isolated.

### GitHub

❌ Never upload this folder.

Add it to `.gitignore`.

---

# 2. `app.py`

```
app.py
```

This is the **main entry point** of your Flask application.

Usually contains:

- Flask application
- Routes
- Configuration
- Server startup

Example:

```
from flask import Flask

app = Flask(__name__)

@app.route("/")
def home():
    return "Hello Flask!"

if __name__ == "__main__":
    app.run(debug=True)
```

---

# 3. `requirements.txt`

```
requirements.txt
```

Stores all Python packages used by the project.

Example:

```
Flask==3.1.2
```

Purpose:

Anyone can install the same dependencies using:

```
pip install -r requirements.txt
```

---

# 4. `.gitignore`

```
.gitignore
```

Tells Git which files or folders should **not** be tracked.

Example:

```
.venv/
__pycache__/
*.pyc
instance/
.env
```

---

# 5. `templates/`

```
templates/
```

Stores HTML files.

Example:

```
templates/

index.html

about.html

contact.html
```

Flask automatically looks for templates inside this folder when using `render_template()`.

Example:

```
return render_template("index.html")
```

---

# 6. `static/`

Stores static resources.

```
static/

css/

js/

images/

fonts/
```

Example:

```
static/

css/
    style.css

js/
    app.js

images/
    logo.png
```

These files are sent directly to the browser.

---

# 7. `instance/`

```
instance/
```

Stores project-specific files.

Examples:

- SQLite database
- Local configuration
- Secret files

Usually not uploaded to GitHub.

---

# How Flask Uses These Folders

Suppose the user visits:

```
http://127.0.0.1:5000/
```

Flow:

```
Browser

↓

Flask (app.py)

↓

templates/index.html

↓

HTML

↓

Browser
```

If the HTML contains:

```
<link rel="stylesheet" href="/static/css/style.css">
```

Flask serves:

```
static/css/style.css
```

to the browser.

# Folder Responsibilities

|Folder/File|Purpose|
|---|---|
|`.venv`|Virtual environment|
|`app.py`|Main Flask application|
|`templates`|HTML templates|
|`static`|CSS, JavaScript, images, fonts|
|`requirements.txt`|Python dependencies|
|`.gitignore`|Files ignored by Git|
|`instance`|Local configuration and project-specific files|

# Common Mistakes

### ❌ Putting HTML beside `app.py`

Wrong:

```
app.py
index.html
about.html
```

Correct:

```
templates/

index.html

about.html
```

---

### ❌ Storing CSS in `templates`

Wrong:

```
templates/

style.css
```

Correct:

```
static/css/style.css
```

---

### ❌ Uploading `.venv`

Never upload:

```
.venv/
```

It can contain thousands of files and is machine-specific.

---

### ❌ Forgetting `requirements.txt`

Without it, other developers won't know which packages your project depends on.

---

# Best Practices

- Keep HTML in `templates/`.
- Keep CSS, JavaScript, images, and fonts in `static/`.
- Keep only Python code in `.py` files.
- Commit `requirements.txt` and `.gitignore` to Git.
- Exclude `.venv` and sensitive files from version control.
- Organize your project from the beginning. It becomes much easier to expand later.

---

# Future Project Structure

As projects grow, a single `app.py` becomes difficult to manage. A common scalable layout looks like this:

```
FlaskProject/

app/

├── __init__.py
├── routes.py
├── models.py
├── forms.py
├── templates/
└── static/

config.py

run.py

requirements.txt
```

Don't worry about this structure yet. We'll learn it later when we cover **Blueprints** and the **Application Factory** pattern.
